# 🍀 260902_TIL

git : 버전 관리 시스템

github : 저장소

git에는 세가지 영역이 있다.

Working Directory : 내가 실제로 파일을 수정하는 공간

Staging Area : 커밋될 파일을 올려놓는 임시 공간 (준비 영역)

Repository : 커밋이 저장되는 로컬 Git 저장소

add 는 파일이 staging area로 이동한다.

commit 은 staging area에 이동된 파일들을 하나의 버전으로 로컬저장소에 저장한다.

push 는 파일들을 repository(원격저장소)에 저장한다.

## 🍀 reset vs revert

reset : 이전 커밋 내역들을 삭제하면서 해당 커밋으로 돌아간다.

revert : 이전 커밋 내역들은 그대로 두고, 되돌리고 싶은 커밋의 코드만 복원시킨다.

reset은 커밋 내역을 깔끔하게 유지할 수 있다. 따라서 개인 프로젝트를 진행할 때는 사용해도 좋다.

협업을 하는 상황에서는 revert를 사용하는 것이 좋다. 왜 되돌아갔는지 중간에 무슨 문제가 있었는지 기록이 가능하기 때문이다. 또한 같은 브랜치에서 작업할 경우 revert를 사용해야 코드 충돌을 최소화 할 수 있다.

## 🍀 checkout vs switch

checkout 명령어는 사실상 졸업한 명령어라고 생각해도 된다.

checkout 명령어는 switch와 restore 로 분리되었다.

따라서 switch 명령어와 restore 명령어에 대해 정리해보자.

switch는 브랜치 전환에만 사용되는 명령어이다.

명령어 사용 예시

git switch branch명 // 해당 브랜치로 이동

git switch -c branch명 // 브랜치를 만들고 해당 브랜치로 이동

restore는 두가지 상황에서 유용하다.

첫번째 상황 : 코드를 이것저것 고쳤는데 동작이 안돼서 그냥 다 취소하고 처음부터 하고 싶을 때.(git add하기 전)

-> 명령어 : git restore app.js

-> 결과 : app.js 에서 수정했던 부분이 전부 날아가고 마지막 커밋 상태로 깨끗하게 원복된다.

app.js에서 수정한 내용들만 날아가고 다른 파일에서 수정한 내용들은 날아가지 않는다.

두번째 상황 : 실수로 git add . 했는데 올라가면 안되는 파일(config.json)이 올라갔을 때.

-> 명령어 : git restore --staged config.json

-> 결과 : config.json 파일이 unstage 된다. 수정 내용은 유지된다.

정리하자면 checkout은 switch + restore로 대체해서 사용하는 것이 권장되고, switch는 브랜치전환할때 사용, restore는 git add 명령어를 사용하기 전후로 원상복구 시킬 때 사용한다.
