## ☘️ Git과 변경 이력

Git은 파일의 변경 이력을 관리하는 도구다. 파일을 수정할 때마다 이전 내용을 별도 파일로 복사해 두지 않아도, 기록한 시점의 내용과 변경 이력을 확인할 수 있다. 수업에서는 텍스트 파일을 만들고 Git 저장소에 기록하는 흐름을 실습했다. 연결한 커밋은 실습 파일을 담고 있으며, 아래 Git 명령의 설명까지 모두 파일에 기록된 것은 아니다.

**저장소와 커밋**

저장소(repository)는 프로젝트의 파일과 변경 이력을 관리하는 공간이다. 내 컴퓨터에 있는 저장소를 로컬 저장소, 네트워크에서 접근하는 공유 저장소를 원격 저장소라고 한다. GitHub는 원격 Git 저장소를 보관하고 공유할 수 있는 서비스다. Git 자체와 GitHub는 같은 것이 아니다.

커밋(commit)은 준비한 변경을 하나의 이력으로 기록한 것이다. 각 커밋에는 당시의 파일 상태와 부모 커밋을 포함한 정보가 저장되므로, 어떤 순서로 작업했는지 살펴볼 수 있다. 커밋은 먼저 로컬에 만들어지며, 다른 사람과 공유하려면 원격 저장소에 올려야 한다.

**작업 폴더 → 준비 영역 → 로컬 저장소 → 원격 저장소**

1. **작업 폴더(working directory)**에서 파일을 만들거나 수정한다. 수정했다고 바로 커밋이 생기지는 않는다.
2. `git add`로 다음 커밋에 담을 변경을 **준비 영역(staging area)**에 올린다. 준비 영역은 변경을 임시로 골라 두는 곳이다.
3. `git commit`으로 준비 영역의 내용을 로컬 저장소에 기록한다. 커밋은 현재 준비된 내용을 기준으로 만들어진다.
4. `git push`로 로컬 커밋을 원격 저장소에 올린다. 로컬에서 커밋만 한 상태라면 그 커밋이 원격에도 자동으로 생기는 것은 아니다.

파일을 준비 영역에 올린 뒤 다시 수정하면, 그 이후의 수정은 다시 준비해야 다음 커밋에 포함된다. `git status`로 현재 수정과 준비 상태를 확인하면서 작업한다.

## ☘️ 브랜치와 복구

**브랜치**

브랜치는 커밋을 가리키는 이름이다. 각 브랜치를 사용하면 작업 흐름을 나누어 진행할 수 있다. 브랜치를 전환하면 Git은 해당 브랜치가 가리키는 상태를 기준으로 작업 폴더를 맞춘다. 미커밋 변경과 전환 대상이 충돌할 수 있으므로 전환 전 상태를 확인한다.

`git switch`는 기존 브랜치로 전환한다. `-c` 옵션을 붙이면 새 브랜치를 만든 뒤 그 브랜치로 전환한다. `checkout`도 브랜치 전환과 파일 복구 등에 쓰였지만, `switch`와 `restore`를 사용하면 의도를 나누어 표현할 수 있다.

**수정한 파일 복구**

`git restore`는 지정한 작업 파일을 준비 영역에 기록된 내용으로 되돌린다. 별도로 준비한 변경이 없다면 보통 마지막 커밋의 내용으로 돌아간다. 이때 작업 폴더에서 되돌린 미커밋 수정은 사라질 수 있으므로 대상 파일을 먼저 확인한다.

`git restore --staged`는 준비 영역에서 지정한 변경을 제외한다. 작업 폴더의 수정 내용은 그대로 남기 때문에, 다음 커밋에서만 빼고 나중에 다시 준비할 수 있다. 즉 작업 파일을 복구하는 것과 커밋 준비를 취소하는 것은 다르다.

**커밋 되돌리기**

`reset`은 브랜치가 가리키는 위치를 다른 커밋으로 옮긴다. 선택한 모드에 따라 준비 영역과 작업 폴더도 함께 바뀐다. 이전 위치 뒤에 있던 커밋은 그 브랜치의 이력에서 빠지므로, 다른 사람과 이미 공유한 이력에 사용할 때는 영향을 확인해야 한다.

`revert`는 기존 커밋을 이력에서 지우는 대신, 그 커밋의 변경을 취소하는 새 커밋을 만든다. 기존 기록과 되돌린 기록이 모두 남기 때문에 공유 이력을 보존하면서 변경을 취소할 때 유용하다.

## ☘️ 원격 저장소와 협업

`clone`은 원격 저장소를 내 컴퓨터에 처음 복제해 로컬 저장소를 만드는 작업이다. 이후 원격에 새 변경이 생겼을 때 `pull`은 그 변경을 가져와 현재 로컬 작업에 통합한다. `push`는 반대로 내 로컬 커밋을 원격에 올린다. 서로 같은 브랜치를 수정했다면 통합 과정에서 충돌을 해결해야 할 수도 있다.

Fork는 다른 사람의 GitHub 저장소를 내 계정으로 복제하는 기능이다. 내 계정의 복사본에서 작업한 뒤 원래 저장소에 변경을 제안할 수 있다. Pull Request는 한 브랜치의 변경을 다른 브랜치에 합쳐 달라고 요청하는 것으로, 변경 내용을 검토하고 의견을 나누는 데 사용한다. 요청 자체와 실제 병합은 별도의 단계다.
