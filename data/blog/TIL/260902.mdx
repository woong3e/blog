Git은 파일을 수정한 결과를 시점별로 기록하는 도구다. 파일 이름에 최종·수정·진짜최종을 붙여 복사하지 않아도 이전 상태를 확인하고 변경을 취소할 수 있다. GitHub는 이 Git 저장소를 온라인에서 보관하고 공유하는 서비스다. Git과 GitHub는 역할이 다르며 인터넷 없이도 로컬 커밋은 만들 수 있다.

## ☘️ 수정한 파일이 커밋이 되는 과정

**작업 폴더, 준비 영역, 저장소**

작업 폴더는 지금 편집하는 파일이 있는 곳이다. 파일을 저장했다고 Git 이력까지 생기지는 않는다. git add는 다음 기록에 넣을 변경을 준비 영역에 올리고, git commit은 준비된 상태를 로컬 저장소에 기록한다. 커밋은 파일명 목록만 기억하는 것이 아니라 그 시점의 파일 내용을 다시 찾을 수 있게 만든다.

준비 영역이 따로 있는 이유는 여러 수정 중 관련된 것만 하나의 커밋으로 묶기 위해서다. 파일을 add한 뒤 다시 편집하면 준비된 내용과 작업 폴더의 내용이 달라진다. 두 번째 수정도 포함하려면 다시 add해야 한다. git status로 준비한 변경과 아직 준비하지 않은 변경을 나누어 확인한다.

커밋 메시지는 어떤 변경을 기록했는지 설명한다. 커밋에는 고유한 식별값이 있어 특정 시점의 소스를 연결할 수 있다. push는 이렇게 만든 로컬 커밋을 원격에 올리는 별도 작업이다. 커밋 성공과 원격 공유 성공을 구분해야 한다.

## ☘️ 브랜치와 되돌리기의 기준

브랜치는 커밋을 가리키는 이름이다. 새 브랜치를 만들면 기존 파일을 별도 폴더로 복사하는 대신 같은 출발점에서 다른 변경 흐름을 만들 수 있다. switch는 작업할 브랜치를 바꾸고, switch -c는 새 브랜치를 만들면서 이동한다. 변경이 겹치는 상태에서 전환하면 작업이 막힐 수 있으므로 전환 전 상태를 확인한다.

restore는 작업 파일을 기준 상태로 복구한다. 기본 동작은 준비 영역의 내용을 작업 폴더에 반영하는 것이며, 준비하지 않은 수정은 사라질 수 있다. restore --staged는 준비만 취소해 수정 파일을 남긴다. 두 명령은 파일 복구와 커밋 대상 선택이라는 다른 목적을 가진다.

이미 기록한 변경을 취소할 때 revert는 반대 변경을 담은 새 커밋을 만든다. 기존 커밋과 취소 커밋이 모두 남는다. reset은 브랜치가 가리키는 위치를 옮기며 옵션에 따라 준비 영역과 파일도 바꾼다. 공유한 이력을 유지해야 할 때는 기존 기록을 남기는 revert가 적합하다.

## ☘️ 원격에 공유하는 흐름

clone은 원격 저장소를 처음 복제하고, pull은 원격의 후속 변경을 가져와 현재 작업에 통합한다. push는 로컬의 기록을 원격에 올린다. 같은 부분을 서로 바꾸었다면 통합 과정에서 충돌한 내용을 직접 선택해야 할 수 있다.

Fork는 GitHub에서 다른 계정의 저장소를 내 계정으로 복제하는 기능이다. Pull Request는 브랜치의 변경을 다른 브랜치에 합치도록 제안하는 절차다. 제안 생성과 실제 병합은 다른 단계다. 맨 위 커밋에는 텍스트 실습 파일이 들어 있으며 아래 명령 순서 전체가 과거에 실행되었다는 기록은 아니다. 다음 예제는 Git의 상태 이동을 독립된 임시 저장소에서 확인하도록 구성했다.

## ☘️ 기록을 만들고 취소하는 전체 흐름

다음은 연결된 학습 코드의 핵심 동작을 한 파일에서 확인하도록 정리한 설명용 예제다. 원본 프로젝트 전체를 그대로 옮긴 것은 아니다. 필요한 선언과 실행 부분을 함께 두었으며, 아래 코드만 저장해 흐름을 따라갈 수 있다.

**git-demo.ps1**

```powershell
$demoDirectory = Join-Path ([IO.Path]::GetTempPath()) ('git-til-' + [Guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $demoDirectory | Out-Null
Push-Location $demoDirectory
try {
    git init -q
    git config user.name 'Example Learner'
    git config user.email 'learner@example.invalid'
    Set-Content -LiteralPath hello.txt -Value '첫 기록' -Encoding UTF8
    git add hello.txt
    git commit -q -m '초기 기록'
    Add-Content -LiteralPath hello.txt -Value '추가 기록' -Encoding UTF8
    git add hello.txt
    git commit -q -m '내용 추가'
    git revert --no-edit HEAD | Out-Null
    git switch -q -c review
    Add-Content -LiteralPath hello.txt -Value '커밋하지 않은 수정' -Encoding UTF8
    git restore hello.txt
    Get-Content -LiteralPath hello.txt -Encoding UTF8
    git log -3 --format='%s'
} finally {
    Pop-Location
}
```

스크립트는 임시 폴더에 독립된 저장소를 만든다. 첫 커밋은 파일 한 줄, 두 번째 커밋은 추가한 한 줄을 기록한다. revert는 두 번째 변경을 취소하는 새 커밋을 남기므로 기록은 세 개가 된다. review 브랜치에서 잠시 수정한 내용은 restore로 버려 마지막 파일에는 첫 줄만 남는다. 여기서 사용한 이름과 이메일은 임시 저장소의 예제용 값이며 전역 Git 설정을 바꾸지 않는다.

코드를 분석한 예상 출력의 마지막 부분:

```text
첫 기록
Revert "내용 추가"
내용 추가
초기 기록
```

**실행 방법**

Git과 PowerShell이 설치된 환경에서 스크립트를 실행한다. 현재 작업 저장소 대신 새 임시 폴더에서 실행되며 네트워크 연결이나 푸시는 하지 않는다.
