## ☘️ Git 작업 흐름

Git은 버전 관리 도구, GitHub는 Git 저장소를 호스팅하는 서비스다.

**작업 폴더 → add → 준비 영역 → commit → 로컬 저장소 → push → 원격 저장소**

- Working Directory: 실제 파일을 수정하는 곳
- Staging Area: 다음 커밋에 포함할 변경을 준비하는 곳
- Repository: 커밋 이력을 보관하는 로컬 저장소

## ☘️ 되돌리기와 협업

- `reset`: 브랜치가 가리키는 커밋을 옮긴다. 모드에 따라 준비 영역·작업 폴더도 바뀌며, 뒤의 커밋은 해당 브랜치 이력에서 빠진다.
- `revert`: 특정 커밋의 변경을 취소하는 **새 커밋**을 만든다. 공유한 이력을 보존하므로 협업 시 유용하다.
- `clone`: 원격 저장소를 처음 복제한다.
- `pull`: 기존 로컬 저장소에 원격 변경을 가져와 통합한다.
- Fork: 다른 사람의 저장소를 내 GitHub 계정으로 복제한다.
- Pull Request: 변경을 검토하고 병합해 달라고 요청한다.

## ☘️ 브랜치와 파일 복구

checkout의 여러 역할을 switch와 restore로 나눠 표현할 수 있다.

```bash
git switch branch-name          # 브랜치 전환
git switch -c new-branch         # 생성 후 전환
git restore app.js              # 준비 영역 기준으로 작업 파일 복구
git restore --staged config.json # 준비 영역에서 제외, 작업 내용 유지
```

`add` 전의 `restore app.js`는 보통 마지막 커밋 상태로 돌아간다. 지정한 파일의 미커밋 수정이 사라지므로 복구 범위를 확인한다.
