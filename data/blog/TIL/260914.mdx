## ☘️ DOM의 관계를 따라 요소 찾기

DOM은 HTML 문서를 부모와 자식으로 연결된 객체 구조로 표현한다. 이 구조의 구성 단위를 **노드**라고 한다. 태그에 해당하는 요소 노드뿐 아니라 글자를 담은 텍스트 노드, 주석 노드도 있다. HTML의 들여쓰기와 줄바꿈도 텍스트 노드가 될 수 있다.

수업에서는 기준 요소를 선택한 뒤 주변으로 이동했다. 모든 노드를 포함하는 childNodes와 달리 children은 요소 자식만 담는다. firstChild·lastChild는 첫 노드와 마지막 노드이고, firstElementChild·lastElementChild는 첫 요소와 마지막 요소다. nextSibling·previousSibling 역시 텍스트까지 포함하지만 Element가 붙은 형제 탐색은 요소만 대상으로 한다.

parentNode는 부모 노드, parentElement는 부모 요소를 찾는다. 부모·형제가 없으면 null일 수 있으므로 존재를 확인하고 사용한다. nodeType은 종류를 알려 주며 수업에서는 요소 1, 텍스트 3, 문서 9를 확인했다. childNodes는 NodeList, children은 HTMLCollection이므로 배열과 같은 것으로 가정하지 않는다.

**텍스트 읽고 바꾸기**

요소 자신의 nodeValue는 null이다. 텍스트 노드의 값을 직접 바꾸려면 그 텍스트 노드를 찾아 nodeValue를 바꾼다. 요소 내부의 글을 한 번에 바꿀 때는 textContent가 더 간단하다. 대입하면 기존 자식들은 제거되고 새 텍스트로 바뀐다. 태그 모양의 문자열도 HTML이 아니라 글자로 표시한다. innerText는 화면 표시와 CSS의 영향을 받지만 textContent는 DOM의 텍스트를 기준으로 한다.

## ☘️ 내용 삽입과 노드 이동

innerHTML은 문자열을 HTML로 해석해 기존 내부를 교체한다. 사용자 입력을 그대로 넣으면 의도하지 않은 HTML이나 코드가 실행되는 XSS 문제가 생길 수 있다. 사용자 글을 단순히 표시할 때는 textContent를 우선한다.

insertAdjacentHTML은 기존 내부를 모두 교체하지 않고 지정한 위치에 HTML을 넣는다. beforebegin은 요소 바깥 앞, afterbegin은 내부 맨 앞, beforeend는 내부 맨 뒤, afterend는 요소 바깥 뒤다.

**생성과 부착은 별개**

```js
const $newLi = document.createElement('li')
$newLi.textContent = '콜라'
$drinkList.appendChild($newLi)
```

createElement는 메모리에 새 요소를 만들 뿐 화면의 목록에 자동으로 넣지 않는다. 내용을 지정한 뒤 부모의 appendChild를 호출해야 마지막 자식으로 붙는다. DocumentFragment는 여러 노드를 임시로 모으는 공간이다. 실제 DOM에 붙이면 담긴 자식들이 이동하고 fragment 자체는 비워진다.

이미 붙어 있는 노드를 appendChild로 다시 붙이면 복사가 아니라 **이동**이다. 같은 부모에 붙이면 뒤로 이동한다. 수업 원본의 피자 이동 주석은 음료 목록으로 옮긴다고 하지만 실제 코드는 foodList에 다시 붙이므로 같은 음식 목록 안에서 위치가 바뀐다.

insertBefore는 기준 자식 앞에 삽입하고, replaceChild는 기존 자식을 새 노드로 교체한다. removeChild는 부모가 자식을 제거하며 remove는 노드 자신을 제거한다. 기준이나 제거 대상이 실제로 해당 부모의 자식인지도 확인해야 한다.

## ☘️ 입력 상태, 데이터와 스타일

HTML에 적은 속성을 **어트리뷰트**, 브라우저의 DOM 객체에 있는 값을 **프로퍼티**라고 한다. getAttribute·setAttribute·hasAttribute·removeAttribute는 HTML 속성을 읽기·설정·존재 확인·삭제하는 메서드다.

input의 value 속성은 기본 입력값과 관련되고, `.value` 프로퍼티는 사용자가 지금 입력한 값이다. 사용자의 최신 입력을 처리하려면 `.value`를 읽는다. 체크박스의 `.checked`는 현재 선택 여부인 boolean이다. checked 어트리뷰트는 존재 자체가 기본 선택을 뜻하므로 문자열 false를 넣는다고 선택이 해제되지 않는다.

`data-*` 속성에는 요소에 필요한 데이터를 담는다. `data-board-id`는 `dataset.boardId`처럼 하이픈을 없애고 다음 단어를 대문자로 바꾸어 접근한다. dataset 값은 문자열이므로 숫자 계산 전 변환이 필요하다.

`style.backgroundColor`처럼 style 프로퍼티로 인라인 스타일을 바꿀 수 있다. CSS의 하이픈 이름은 자바스크립트에서 backgroundColor 같은 카멜 표기법으로 쓴다. className에 문자열을 대입하면 클래스 전체가 교체된다. 일부만 관리하려면 classList의 add·remove·toggle·contains를 사용한다. toggle은 없으면 추가하고 있으면 제거하며, 처리 후 존재 여부를 반환한다.

## ☘️ 종합 과제에서 확인한 구현과 오류

상품 검색은 현재 입력을 trim으로 다듬고 소문자로 바꾼 뒤 상품 텍스트의 includes로 포함 여부를 확인하는 과제다. 일치한 항목에만 matched를 붙이고 개수를 세며, 빈 검색이면 표시를 초기화해야 한다. 이 날짜 커밋에는 검색 함수와 관계 탐색 함수의 구현이 비어 있다.

할 일 과제의 원본은 li를 함수 밖에서 한 번만 만들었다. 매번 같은 노드를 appendChild하므로 항목이 늘지 않고 내용과 위치만 바뀐다. 매 추가마다 새 li를 만들고, 공백뿐인 입력은 막아야 한다. 마지막 삭제도 목록이 비었는지 확인해야 한다. 원본은 이 두 검사가 없어 빈 항목이나 빈 목록 삭제 문제가 남아 있다.

상품 선택 과제는 모든 카드의 selected와 data-selected를 먼저 지우고 선택 카드만 표시하도록 요구하지만 함수는 비어 있다. 프로필 과제는 입력값을 콘솔에만 보여 주고 카드 이름·소개에는 반영하지 않았다. setAttribute로 기본값을 바꾸는 것과 현재 입력을 카드에 표시하는 일은 다르다.

다크 모드 원본은 버튼에 `.dark`라는 문자열을 토글한다. classList에는 선택자 점을 붙이지 않는 클래스 이름을 전달해야 하고, 실제로 꾸밀 대상도 버튼이 아니라 카드다. 크기와 다크 모드는 카드의 클래스로 관리하고 버튼 글자는 그 상태를 읽어 정해야 한다. 이 오류들은 원본 설명이며, 새 완성 코드를 수업 코드처럼 제시하지 않는다.
