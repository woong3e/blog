## ☘️ 이벤트 등록과 실행 대상

이벤트는 클릭·입력·제출처럼 브라우저에서 발생하는 동작이다. 그때 실행할 함수를 이벤트 핸들러라고 한다. HTML 속성으로 연결하거나 DOM의 onclick에 대입하거나 addEventListener로 등록할 수 있다.

onclick은 함수 하나를 담는 프로퍼티이므로 새 함수를 대입하면 이전 함수를 대체한다. addEventListener는 같은 요소에 서로 다른 핸들러를 여러 개 등록할 수 있다. 나중에 제거하려면 등록한 함수 자체를 변수로 보관해야 한다. 모양이 똑같은 화살표 함수를 다시 작성해도 별개의 함수이므로 제거되지 않는다. 이벤트 종류와 capture 설정도 맞아야 한다.

수업의 카운터는 countFunc를 클릭에 등록해 횟수를 올리고, 중지 버튼에서 그 함수 참조를 removeEventListener에 전달한다. 중지 후에는 버튼이 남아 있어도 증가 함수가 실행되지 않는다.

**이벤트 객체**

핸들러의 인수로 받은 이벤트 객체에는 발생한 동작의 정보가 있다. target은 이벤트가 시작된 요소이고 currentTarget은 지금 실행 중인 핸들러가 등록된 요소다. 버튼 속 글자나 자식 요소를 클릭하면 두 대상이 다를 수 있다. clientX·clientY는 현재 보이는 브라우저 화면 영역을 기준으로 한 좌표다.

일반 함수 핸들러의 this는 currentTarget이고 화살표 함수는 바깥 this를 사용한다. 수업은 버튼을 e.currentTarget으로 받아 글자와 색을 바꾼 뒤 2000ms 후 되돌린다. 나중에 실행할 함수에는 이벤트 객체의 currentTarget을 다시 읽기보다 미리 저장한 버튼을 사용한다. 이벤트 처리가 끝난 뒤에는 currentTarget이 null일 수 있기 때문이다.

## ☘️ 전파와 이벤트 위임

이벤트는 캡처링으로 바깥에서 대상 쪽으로 내려오고, 대상에 도착한 뒤 버블링으로 부모 방향에 전달될 수 있다. 따라서 자식을 클릭해도 부모의 클릭 핸들러가 실행된다. 모든 이벤트가 버블링하는 것은 아니지만 click은 이 성질을 활용할 수 있다.

**위임**은 항목마다 함수를 등록하는 대신 공통 부모 하나가 자식의 동작을 처리하는 방식이다. 이후 새로 붙인 항목도 같은 부모로 이벤트가 전달되므로 별도 등록 없이 처리할 수 있다.

closest는 클릭한 요소 자신부터 부모 방향으로 올라가 조건에 맞는 가장 가까운 요소를 찾는다. 버튼 안쪽의 글자나 strong을 눌러도 실제 처리할 항목을 찾을 수 있다. contains로 목록 내부 항목인지 확인할 수 있다. 수업의 음료 목록은 closest로 항목을 구한 뒤 다시 target이 li인지 검사해, 안쪽 요소를 클릭한 경우 처리가 누락되는 부분이 있다. 찾은 항목을 처리 대상으로 써야 한다.

메뉴 선택 과제는 클릭 위치에서 `.select-menu` 버튼을 찾고 기존 selected를 모두 제거한 뒤 해당 메뉴에만 selected를 붙인다. 버튼의 data-menu-id와 메뉴 안의 글자로 선택 정보를 출력한다. data-product-id도 dataset.productId로 읽으며, 가격은 문자열이므로 Number로 바꾸어 숫자 형식으로 표시한다. dataset은 값을 대입해 설정하고 delete로 제거할 수 있다.

## ☘️ 기본 동작과 입력 다루기

preventDefault는 링크 이동이나 폼 제출처럼 브라우저가 정한 기본 동작을 취소한다. stopPropagation은 다른 요소로의 이벤트 전파를 막는다. 서로 다른 동작이므로 모달 내부 클릭이 배경 닫기로 전달되지 않게 하려면 전파를 막고, 내부 링크 이동을 취소하려면 그 링크의 기본 동작을 별도로 막는다.

마우스의 dblclick은 두 번 클릭, mousedown은 누르는 순간을 다룬다. event.button은 0이 왼쪽, 1이 가운데, 2가 오른쪽 버튼이다. keydown과 keyup은 키 누름과 뗌이며 key는 Enter 같은 키 값, code는 KeyA 같은 물리적 키 위치를 알려 준다.

입력값의 변경은 input 이벤트로 처리한다. 키보드 이벤트만 보면 붙여넣기 등 다른 입력 방식을 놓칠 수 있다. 수업의 메시지 과제는 input 때 글자 수를 표시하고 Enter 때 공백을 제거한 메시지를 확인한다. 제출 후 코드로 value를 비워도 input이 자동 발생하는 것은 아니므로 글자 수 역시 직접 0으로 초기화한다. focus와 blur는 입력 칸에 포커스가 들어오고 나갈 때 스타일을 바꾸는 데 썼다.

## ☘️ 폼 검증과 DOM 과제 보완

폼의 submit을 처리하면 버튼 클릭뿐 아니라 Enter 제출도 다룰 수 있다. document.forms와 폼의 name을 사용해 입력 요소를 찾는 방법도 실습했다. 체크박스는 value가 아니라 checked로 선택 상태를 읽고, 여러 항목을 배열로 바꾸어 선택 개수를 셀 수 있다.

기본 폼 실습은 이름 두 글자 이상, 관심사 두 개 이상을 검사한다. 이벤트 종합 과제는 이름 두 글자 이상 → 비밀번호 여섯 글자 이상 → 약관 동의 순서다. 실패하면 안내를 표시하고 return으로 다음 단계를 중단한다. 모든 검사가 통과해야 성공 표시를 한다. 종합 과제는 처음부터 기본 제출을 막으므로 서버에 회원을 저장하는 구현까지 포함하지 않는다.

**DOM 과제의 실제 완성 흐름**

이번 커밋에는 이전 DOM 과제의 채워진 풀이도 있다. 검색은 trim·소문자 변환 후 includes로 비교하고 빈 검색 시 모든 표시를 해제한다. 관계 탐색은 기준 요소에서 부모·첫 자식·마지막 자식·이전과 다음 형제로 이동한다.

할 일 추가에서는 함수 안에서 새 li를 만들고 빈 입력을 차단하며, 삭제 전 마지막 요소의 존재를 확인한다. 상품 선택에서는 전체 선택 표시를 지운 후 한 카드에만 클래스와 data-selected를 설정한다. 프로필은 최신 value를 textContent에 반영하고 borderColor와 compact를 바꾸며, dark는 카드에 토글하고 버튼 글자를 맞춘다. 앞선 날짜의 빈 함수와 잘못된 노드 재사용·클래스 대상 문제가 이 풀이에서 어떻게 해결됐는지 연결해 이해할 수 있다.

NodeList의 forEach는 실제 배열이어서 가능한 것이 아니라 해당 메서드를 제공하기 때문이다. map·filter·reduce가 필요하면 배열로 변환한다. querySelectorAll의 결과는 정적이지만 “모든 NodeList는 정적”이라는 원본 주석은 일반화할 수 없다. DOM 문자열 삽입과 현재 value의 차이도 이전 실습과 같은 기준으로 구분한다.
