## ☘️ 계산 결과와 함수 참조 기억하기

컴포넌트가 다시 실행되면 본문에서 작성한 계산도 다시 실행되고 객체·함수도 새로 만들어질 수 있다. useMemo와 useCallback은 의존성이 같을 때 이전 결과나 참조를 재사용하는 기능이다. 컴포넌트 자체의 렌더링을 무조건 막는 기능은 아니다.

useMemo는 함수가 계산한 **결과**를 기억한다. 수업에서는 hardNumber가 바뀔 때만 hardCalculator를 실행하고 easyNumber만 바뀌면 결과를 재사용했다. 다만 원본 hardCalculator는 반복문 첫 회에 return하므로 실제로 긴 반복 계산을 하지는 않는다. 실행 로그를 보는 학습과 실제 성능 측정은 구분한다.

객체는 내용이 같아도 새로 만들면 다른 참조다. 위치 객체를 렌더링마다 만들면 숫자 입력만 바뀌어도 location 참조가 바뀌어 이를 의존성으로 둔 Effect가 실행된다. 수업은 useMemo의 의존성을 isKorea로 두어 국가가 같으면 location 객체도 재사용하게 했다.

useCallback은 계산 결과가 아니라 **함수 참조**를 기억한다. number를 출력하는 함수는 number를 의존성으로 두어야 새 숫자를 사용한다. 사각형 스타일을 만드는 함수는 size에만 의존하게 해서 테마 변경 시 자식의 Effect가 불필요하게 다시 실행되는 것을 줄였다. 자식 렌더링 자체가 생략된다는 뜻은 아니다.

## ☘️ ref와 커스텀 Hook

일반 지역 변수는 렌더링마다 다시 초기화된다. state는 렌더링 사이에 값을 기억하고 setter가 화면 갱신을 요청한다. ref도 값을 기억하지만 current를 바꾸어도 그 자체로 다시 렌더링하지 않는다. 화면에 바로 표시할 데이터는 state, 타이머 id나 DOM 참조처럼 기억하되 즉시 그릴 필요 없는 값은 ref로 관리한다.

수업의 ref 카운터는 current를 증가시켜도 화면이 즉시 바뀌지 않는다. 다른 이유로 렌더링될 때 현재 값이 보일 수는 있지만, ref를 JSX에 쓴다고 반응형 값이 되는 것은 아니다.

로그인 입력의 ref를 usernameRef에 연결하면 React가 DOM을 만든 뒤 current에 input을 넣어 준다. 마운트 Effect에서 focus를 호출해 커서를 두고, 로그인 후 state로 입력을 비운 뒤 다시 포커스한다. DOM이 준비되기 전 본문에서 접근하는 것과 실행 시점을 구분한다.

**커스텀 Hook**

여러 컴포넌트에서 반복되는 상태·Effect 로직을 use로 시작하는 함수에 묶은 것이 커스텀 Hook이다. 컴포넌트나 다른 Hook의 최상위에서 호출한다. 수업의 useDelayTimer는 대기 상태를 false로 시작하고 지정 시간이 지나면 true를 반환한다. delay가 바뀌면 이전 타이머를 정리하고 다시 시작한다. 3000ms는 3초이며 원본 로그의 “초” 표시는 단위를 혼동한 것이다.

```jsx
useEffect(() => {
  setIsReady(false)
  const timer = setTimeout(() => {
    setIsReady(true)
  }, delay)
  return () => clearTimeout(timer)
}, [delay])
```

이는 수업의 useDelayTimer 내부 흐름을 발췌한 것이다. 별도 useDelayReady 과제는 false 초기화를 cleanup에 넣었다. 새 대기의 시작 상태는 setup에서 정하고 cleanup은 기존 타이머 해제를 담당하도록 역할을 구분하는 편이 명확하다. Hook은 로직을 공유하지만 각 호출의 상태까지 하나로 공유하지 않는다.

## ☘️ 비동기 순서와 Promise

비동기는 시간이 걸리는 작업을 예약하고 다음 코드를 계속 실행하는 방식이다. 햄버거 주문 뒤 setTimeout을 예약해도 감자튀김 주문은 3초를 기다리지 않는다. 앞의 결과가 있어야 다음 작업을 할 수 있다면 순서를 연결해야 한다. 콜백을 계속 안쪽으로 넣으면 구조가 깊어져 흐름을 읽기 어려워진다.

Promise는 아직 끝나지 않은 작업의 결과를 나타낸다. pending은 대기, fulfilled는 성공, rejected는 실패다. resolve로 성공값을, reject로 실패 이유를 전달한다. then은 성공 후 처리, catch는 실패 처리, finally는 성공·실패 모두의 마무리를 담당한다.

수업의 addAfterOneSecond는 1초 뒤 10을 더하고 결과가 30을 넘으면 Error로 실패시킨다. 0에서 시작해 then마다 다음 Promise를 return하면 10 → 20 → 30을 출력하고 다음 40에서 catch로 이동한다. 각 단계가 **다음 Promise를 반환해야** 기다림과 결과 전달이 이어진다. 원본 catch는 Error 객체를 출력하지만 과제는 error.message만 출력하도록 요구한다.

## ☘️ 검색 과제의 상태와 오류

검색은 입력 중 값 inputText와 실제 적용된 query를 나눈다. 입력만 할 때는 query가 바뀌지 않으며 버튼을 누를 때 입력을 query로 저장한다. useMemo는 query로 상품 목록을 거르고 useCallback은 검색 함수를 자식에게 안정적으로 전달하는 역할이다.

원본 filter의 콜백은 중괄호 안에서 includes를 호출하고 반환하지 않았다. 그러면 모든 항목이 통과하지 못해 빈 결과가 된다. 또한 과제가 요구한 앞뒤 공백 제거와 대소문자 정리가 빠져 있다. 검색 함수는 인수로 받은 값으로 setter만 호출하므로 query를 읽지 않는데도 의존성에 넣어, query 변경 때 참조가 바뀐다. 계산 결과 재사용과 함수 참조 재사용을 각각 확인해야 한다.
