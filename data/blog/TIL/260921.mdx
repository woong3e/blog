## ☘️ 계산과 참조

- `useMemo(() => hardCalculator(hardNumber), [hardNumber])`: 의존성이 같으면 **계산 결과** 재사용. easyNumber만 바뀌어도 컴포넌트 자체는 렌더링됨
- `useCallback(() => console.log(number), [number])`: 실행 결과가 아니라 **함수 참조** 재사용
- 객체·함수를 렌더링마다 새로 만들면 내용이 같아도 참조가 달라 Effect 의존성이 변경됨
- location 객체는 `useMemo(() => ({ country: isKorea ? '한국' : '외국' }), [isKorea])`로 참조 유지
- 사각형 스타일 함수는 `[size]`로 유지해 테마 변경 때 자식 Effect 재실행을 줄임. 자식 렌더링 생략과는 별개

**실습 오류도 기억하기**

hardCalculator는 반복문 첫 회에 return해 실제로 무거운 계산이 아니었다. 호출 로그와 실제 성능 측정은 구분한다.

검색은 inputText(입력 중)와 query(검색 적용)를 분리했다. 원본 filter는 return이 빠져 항상 빈 결과였다.

```jsx
const searchProducts = useCallback((nextQuery) => setQuery(nextQuery), [])
const filteredProducts = useMemo(() => {
  const normalized = query.trim().toLowerCase()
  return PRODUCTS.filter((product) => product.name.toLowerCase().includes(normalized))
}, [query])
```

공백·대소문자를 정리하고 결과를 반환한다. 검색 함수는 query를 읽지 않으므로 의존성에 필요 없으며, setter 참조는 안정적이다.

## ☘️ 값 유지와 로직 재사용

| 방식        | 렌더링 사이 유지 | 변경 시 렌더링 |
| ----------- | ---------------- | -------------- |
| 지역 변수   | 다시 초기화      | 요청 안 함     |
| state       | 유지             | setter로 요청  |
| ref.current | 유지             | 요청 안 함     |

화면 데이터는 state, 타이머 id·DOM 참조 등은 ref로 관리한다. 원본처럼 ref를 JSX에 출력해도 ref 변경만으로 즉시 화면이 바뀌지 않는다.

`const usernameRef = useRef(null)`을 input의 ref에 연결하면 DOM 생성 후 current에 요소가 들어간다. 마운트 Effect에서 `usernameRef.current?.focus()`를 호출하고 로그인 후 입력을 비워 다시 포커스했다.

```jsx
function useDelayReady(delay) {
  const [isReady, setIsReady] = useState(false)
  useEffect(() => {
    setIsReady(false)
    const id = setTimeout(() => setIsReady(true), delay)
    return () => clearTimeout(id)
  }, [delay])
  return isReady
}
```

useDelayTimer·useDelayReady로 상태 로직을 재사용했다. 원본의 cleanup 초기화는 setup으로 옮겨, 새 대기 시작 시 false·정리 시 타이머 해제로 구분했다. 3000ms는 3초다. 커스텀 Hook은 use로 시작하고 컴포넌트·Hook 최상위에서 호출하며, **호출마다 독립 상태**를 갖는다.

## ☘️ 비동기와 Promise

햄버거 주문의 setTimeout을 예약해도 다음 감자튀김 주문은 기다리지 않는다. 순서가 필요한 +10 작업은 중첩 콜백 대신 Promise로 이어 썼다.

- 상태: pending(대기) → fulfilled(성공) 또는 rejected(실패)
- `resolve`: 성공값 / `reject`: 실패 이유
- `then`: 성공 처리 / `catch`: 실패 처리 / `finally`: 공통 마무리

```js
function addAfterOneSecond(number) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      const result = number + 10
      if (result > 30) {
        reject(new Error('30 초과'))
        return
      }
      resolve(result)
    }, 1000)
  })
}
addAfterOneSecond(0)
  .then((n) => {
    console.log(n)
    return addAfterOneSecond(n)
  })
  .then((n) => {
    console.log(n)
    return addAfterOneSecond(n)
  })
  .then((n) => {
    console.log(n)
    return addAfterOneSecond(n)
  })
  .catch((error) => console.log(error.message))
  .finally(() => console.log('작업 종료'))
```

10 → 20 → 30 출력 후 40에서 실패한다. 원본은 Error 객체를 출력했고, message로 메시지만 얻는다. **다음 Promise를 return해야 기다림과 결과 전달이 이어진다.** 빠뜨리면 다음 핸들러에 undefined가 전달될 수 있다.
