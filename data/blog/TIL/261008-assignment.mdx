Java chap1~6 과제를 복습했다. chap1·2·4·5는 코드의 문제 주석, chap3·6은 제공된 PDF 1~2쪽의 구조·조건·출력을 기준으로 비교한 기록이다. 아래 보완점은 **원본 코드에 적용된 수정이 아니라 복습 메모**다.

**chap1: 변수와 형변환 — 4문제**

- 20·30 사칙연산: 합 50, 차 -10, 곱 600, 몫 0, 나머지 20. int 나눗셈은 소수 버림. 출력 문자열보다 덧셈을 먼저 하려면 괄호 사용
- 너비 12.5·높이 36.4: 넓이 455.0, 둘레 97.8. 원본은 바로 출력했지만 요구사항은 **각 계산값을 변수에 저장 후 출력**
- 문자 'a'를 int로 변환하면 97. 원본은 숫자만 출력해 `문자 a의 unicode : 97` 설명 문구가 빠짐

**chap2: 연산자와 조건 — 5문제**

- 큰 수: `a > b ? a : b`. 같으면 b를 골라도 값은 같음
- 합격: `score >= 60 ? "합격" : "불합격"`. 경계 60 포함
- 짝홀: `number % 2 == 0 ? "짝수" : "홀수"`. 홀수를 나머지 1로 한정하지 않아 음수도 구분
- 등급: 실수를 int로 자른 뒤 /10으로 switch. 89.9→89.0→8→B, case 10·9는 A, 8 B, 7 C, 6 D, 나머지 F. 원본은 double 변수에 정수화한 값을 저장했으며 등급만 출력해 이름·문구 누락. 110은 F가 되므로 0~100 제한 또는 높은 기준부터 &gt;= 비교가 필요
- 생일: 1~6월 **이면서** 1~15일은 배민 쿠폰, 7~12월 **이면서** 16~31일은 스타벅스, 나머지는 사탕. 월·일 하한과 상한 모두 &&로 묶음. 7/16은 커피, 7/15는 사탕. 원본 이름 박지성을 본인 이름으로 바꿔야 함

PDF는 com.greedy.level01.basic의 Calculator·Application 이름을 유지하고 main에서 호출하도록 요구한다. 구조도의 +는 public이다.

PDF의 고정 인자로 호출하고 **반환값은 main에서 출력**해야 한다. 원본은 Scanner로 인자를 받고 합계·합·차도 Calculator 안에서 출력해, 반환값을 main에서 사용하지 않았다. 고정 인자 흐름으로 바꾸고 중복 출력은 제거해야 한다. 메소드/메서드, 와/과, 콜론 공백 등 출력 문구도 다르다. println은 출력, return은 값 전달이다.

큰 수 비교는 PDF의 (10,20)과 달리 원본은 (1,20)을 썼으며 Math.max로 20을 출력했다. 덧셈은 (10,20)→30, 뺄셈은 (10,5)→5가 지정 인자다. sum1to10은 0부터 1~10을 누적해 55를 반환한다. 반환값을 `int total = cal.sumTwoNumber(10, 20);`처럼 받아 사용해야 한다.

**chap4: 조건·반복 — 4문제**

- 합격: 평균 &gt;=60 **그리고** 전 과목 &gt;=40. 평균은 /3.0. 불합격 사유는 독립 if로 **모두** 출력. 60/30/20은 평균·영어·수학, 100/100/39는 수학, 40/70/70은 합격
- 급여: 매출 5천만 이상 5%, 3천만 이상 3%, 1천만 이상 1%, 미만 0%. 높은 기준부터 else if. 총 급여=월급+매출×비율. 월급 300만·매출 2천만이면 보너스 20만·총 320만. 원본은 보너스 **출력 누락**, 총액은 int로 소수 버림. 출력할 비율만 ×100, 숫자의 \_는 가독성용
- 수박: i=1부터 입력값까지, 홀수 순서 '수'·짝수 '박', print로 줄바꿈 없이 연결. 5→수박수박수
- 난수 맞추기: 정답 1~100은 **반복 밖에서 한 번**, 입력 직후 count++로 마지막 정답도 포함. 크고 작음 안내 후 맞히면 종료. 첫 시도 정답은 1회. 원본 double 난수 변수는 int로 표현하면 명확함

## ☘️ chap5와 chap6

**chap5-1: 가운데가 가장 큰 배열**

양의 홀수 n만 허용한다. `n <= 0 || n % 2 == 0`이면 안내 후 재입력하며, 유효성 확인 후 배열을 만든다. 재입력은 원본이 추가한 동작이다.

```java
int middle = n / 2;
for (int i = 0; i < n; i++) {
    arr[i] = i <= middle ? i + 1 : n - i;
}
```

7→1 2 3 4 3 2 1, 1→1. 가운데 최고값은 한 번만 들어간다. 저장은 인덱스 for, 출력은 향상된 for로 읽는다. middle은 반복 밖에서 계산해도 된다.

**chap5-2: 숫자 야구**

- 정답은 0~9의 중복 없는 4개. 새 난수를 **이미 저장한 j&lt;i 범위만** 검사(빈 칸 기본값 0 제외)
- 중복이면 i--·continue 후 for의 i++로 같은 칸 재시도. 안쪽 break는 중복 검사만 끝냄
- 정수 입력 1000~9999만 허용. 유효성 검사 후 count++라 999·10000은 10회 기회에서 차감 안 됨
- `%10`으로 끝자리 추출, `/=10`으로 제거하며 오른쪽부터 저장. 7416→[7,4,1,6]
- 매 입력마다 strike·ball 초기화. 각 입력 숫자를 정답 전체와 비교해 숫자·자리 같음은 S, 숫자만 같음은 B
- 정답 [7,4,1,6]일 때 1234·5678은 0S 2B, 7416은 4S. 정답이면 종료, 10회 실패면 소진 안내. 열 번째 정답에는 소진 메시지를 출력하지 않음

**주의:** 정답 첫 자리 0은 정수 입력으로 맞힐 수 없다(0123→123). 보완 시 첫 자리만 1~9로 생성한다. 입력의 중복 숫자도 검사하지 않아 정답 [1,2,3,4]에 1111은 1S 3B로 반복 집계된다. 문제는 입력 중복 규칙을 명시하지 않았으므로 금지·허용 시 계산 규칙을 정해야 한다.

**chap6: BookDTO 생성자**

PDF의 com.greedy.level02.normal.book.model.dto.BookDTO는 private title·publisher·author·price·discountRate, public getter/setter·printInformation()과 생성자 3개를 요구한다. 구조도의 -는 private, +는 public이다.

- 기본 생성자: 참조 필드 null, price 0, discountRate 0.0
- 문자열 3개 생성자: 제목·출판사·저자만 초기화, 가격·할인율 기본값 유지
- 전체 5개 생성자: 모든 필드 초기화. 예시 가격 5,000,000·할인율 0.5도 저장·출력만 하며 할인액 계산은 요구 아님
- this.title은 필드, title은 인자. 매개변수 생성자를 만들면 기본 생성자도 직접 선언해야 함
- 원본은 패키지·클래스·필드·생성자·저장값이 맞고 getter/setter도 구현. 출력 구분자는 공백뿐이라 PDF의 쉼표+공백과 다름
- Application은 생성자·출력만 호출. PDF의 구체적 실행 안내에는 부합하지만, “모든 메소드 호출” 표까지 적용하면 getter/setter 호출도 확인 필요(별도 입력값은 제시 안 됨)

계산 결과뿐 아니라 **지정한 구현 방식·반환값 사용·전체 출력 항목·경계값**까지 대조한다.
