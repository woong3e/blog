## ☘️ 테이블에서 원하는 데이터 조회하기

관계형 데이터베이스는 데이터를 테이블로 보관한다. 열(컬럼)은 이름·가격 같은 항목, 행은 메뉴 하나 같은 개별 데이터다. SQL은 이 데이터를 조회하고 변경하며 저장 구조를 정의하는 언어다. 수업은 메뉴·분류 테이블로 기본 문법을 익히고 직원·부서·직급 데이터로 관계 조회를 연습했다.

**SELECT와 조건**

SELECT에는 가져올 열을, FROM에는 읽을 테이블을 쓴다. 여러 열은 쉼표로 나열하며 `*`는 모든 열이다. AS로 결과 열에 별칭을 붙일 수 있다. 수업에서는 숫자 계산, NOW로 현재 시각, CONCAT으로 문자열 연결도 조회했다.

WHERE는 조건이 참인 행을 남긴다. `=`, `<>`, `>`, `<`, `>=`, `<=`로 비교하며 AND는 둘 다, OR는 하나 이상을 만족하는 조건이다. AND가 OR보다 먼저 처리되므로 의도한 묶음에 괄호를 쓴다.

BETWEEN은 양 끝을 포함한다. 수업의 10000~25000 조건에서 미만·초과만 원하면 별도의 `<`와 `>`로 표현해야 한다. NOT BETWEEN은 그 범위 밖이다. LIKE는 문자열 패턴을 찾고 `%마늘%`는 어느 위치든 마늘을 포함하는 이름, 앞이나 뒤의 % 하나는 끝 또는 시작 조건을 만든다. IN은 괄호 안 후보 중 하나인지 검사하고 NOT IN은 후보 제외다.

NULL은 값이 없거나 알 수 없다는 상태다. 일반 등호 대신 IS NULL·IS NOT NULL로 확인한다. 숫자 0이나 빈 문자열과 같은 값으로 취급하지 않는다.

**정렬·중복·개수 제한**

ORDER BY의 ASC는 오름차순이며 생략할 수 있다. DESC는 내림차순이다. 가격 내림차순 뒤 이름 오름차순을 쓰면 가격이 같은 행만 이름으로 다시 정렬한다. 계산식의 별칭도 정렬 기준으로 쓸 수 있다. ORDER BY가 없으면 원하는 순서가 유지된다고 가정하지 않는다.

FIELD는 값이 지정한 목록에서 몇 번째인지 반환하므로 N을 먼저, Y를 나중으로 정렬하는 데 사용했다. NULL 위치는 IS NULL의 참·거짓을 첫 기준으로 정하고 값 자체를 둘째 기준으로 정렬했다.

DISTINCT는 선택한 열의 중복 조합을 제거한다. 열 두 개면 한 열만 같은 것으로는 제거하지 않는다. LIMIT 5는 다섯 행, LIMIT 1,4는 한 행을 건너뛴 다음 네 행이다. 원하는 상위 데이터를 제한하려면 정렬 기준도 함께 지정한다.

## ☘️ 여러 행을 집계하고 테이블 연결하기

GROUP BY는 같은 기준값의 행을 묶는다. COUNT(\*)는 행 수, SUM은 합계, AVG는 평균을 계산한다. 수업은 분류별 메뉴 수·가격 합·평균을 구했다. 그룹 결과에서는 어떤 값을 보여 줄지 명확하도록 그룹 기준이나 집계식을 선택한다.

WHERE는 그룹화 전에 개별 행을 거르고 HAVING은 만들어진 그룹의 집계 결과를 거른다. 메뉴가 세 개 이상인 분류는 HAVING COUNT(\*) 조건이다. WITH ROLLUP은 그룹 단계에 따른 소계·총계를 추가한다. 합계 표시의 NULL과 실제 데이터의 NULL도 문맥으로 구분해야 한다.

**JOIN**

JOIN은 여러 테이블의 행을 조건에 따라 연결한다. 메뉴의 category_code와 분류의 category_code가 같다는 ON 조건으로 이름과 분류명을 함께 읽는다. 테이블 별칭은 열의 소속을 짧고 분명하게 보여 준다. 별칭 자체가 모든 JOIN의 필수 문법인 것은 아니지만 같은 테이블을 여러 역할로 쓸 때는 구분이 필요하다.

INNER JOIN은 조건에 맞는 짝이 있는 행을 남긴다. LEFT JOIN은 왼쪽 행을 모두 유지하고 오른쪽 짝이 없으면 오른쪽 열을 NULL로 채운다. RIGHT JOIN은 반대로 오른쪽을 유지한다. 조건이 여러 짝을 만들면 한 행이 여러 결과 행으로 나타날 수 있어 단순히 “교집합”이라는 말만으로 행 수를 판단하지 않는다.

SELF JOIN은 같은 테이블을 서로 다른 역할로 연결하는 것이다. 분류 테이블의 하위 분류 ref_category_code와 상위 분류 category_code를 연결했고, 직원 예제에서는 직원과 관리자를 각각 별칭으로 구분했다. 관리자 번호가 있는 행 수와 실제 관리자 행에 연결되는 수는 참조 대상 존재 여부에 따라 다를 수 있다.

## ☘️ 서브쿼리와 결과 합치기

서브쿼리는 다른 SQL 안에 들어 있는 조회다. 민트미역국의 분류를 먼저 찾아 그 값으로 같은 분류 메뉴를 고르는 데 썼다. 등호 오른쪽의 단일값 서브쿼리는 그 자리에 맞는 결과 개수를 반환해야 한다.

FROM 안의 서브쿼리는 조회 결과를 테이블처럼 사용한다. 분류별 메뉴 수를 먼저 구한 뒤 바깥에서 MAX를 계산하면 가장 큰 분류의 메뉴 수를 얻는다. 이런 파생 테이블에는 별칭을 지정한다. 상관 서브쿼리는 바깥 행의 분류 코드를 참조해 해당 분류 평균보다 비싼 메뉴인지 검사한다.

UNION은 두 조회 결과를 위아래로 합치고 중복 행을 제거한다. UNION ALL은 중복도 유지한다. 대응하는 열 수와 타입이 맞아야 한다. JOIN이 관련 열을 옆으로 연결하는 것과 구분한다. 수업은 10번 분류이면서 9000원 미만인 메뉴를 IN으로 공통 조건에 남기고, LEFT JOIN 후 오른쪽 키가 NULL인 행으로 차집합도 표현했다.

## ☘️ 데이터 변경과 트랜잭션

INSERT는 행을 추가한다. 열 목록을 지정하면 그 순서대로 값을 넣고, 생략하면 전체 열 순서를 맞춰야 한다. 여러 행은 VALUES 뒤의 괄호 묶음을 쉼표로 연결한다. 수업은 메뉴를 등록하며 자동 번호 자리에 NULL을 사용했다.

UPDATE는 SET에 바꿀 내용, WHERE에 대상을 쓴다. DELETE는 WHERE로 고른 행을 지운다. 같은 조건의 SELECT로 대상을 먼저 확인한 뒤 변경하면 실수를 줄일 수 있다. WHERE를 생략하면 모든 행이 대상이다. REPLACE는 기본 키나 고유 키가 충돌할 때 기존 행을 삭제하고 새로 넣는 동작이므로 일부 열만 고치는 UPDATE와 다르다.

**트랜잭션**은 함께 성공하거나 함께 취소해야 하는 작업 묶음이다. MySQL의 자동 커밋이 켜져 있으면 일반적으로 각 문장의 변경이 바로 확정된다. 수업은 autocommit을 끄고 START TRANSACTION 뒤 메뉴 추가·수정·삭제를 수행해 현재 연결에서 결과를 확인했다. ROLLBACK하면 아직 확정하지 않은 변경을 취소하고 COMMIT하면 확정한다. 이미 커밋한 변경을 이후 ROLLBACK으로 되돌릴 수는 없다. 실습 종료 시 autocommit을 다시 켰다.

## ☘️ 테이블 구조와 저장 규칙

DDL은 CREATE·ALTER·DROP처럼 구조를 정의하는 명령이다. CREATE TABLE IF NOT EXISTS는 없을 때 테이블을 만든다. DESCRIBE로 열 정의를 확인하고 AUTO_INCREMENT는 새 행의 번호를 자동 생성한다. ALTER의 ADD는 열 추가, DROP COLUMN은 열 제거, CHANGE COLUMN은 이름을 포함한 정의 변경, MODIFY는 이름을 유지한 정의 변경이다.

DROP TABLE은 구조와 데이터를 삭제한다. TRUNCATE는 구조를 남기고 전체 데이터를 비우며 수업의 자동 번호도 초기화된다. MySQL DDL은 일반 DML의 롤백 실험과 같은 방식으로 취소된다고 생각하면 안 된다.

**제약 조건**

- NOT NULL은 값 누락을 금지한다. 빈 문자열까지 금지하는 규칙은 아니다.
- UNIQUE는 중복을 제한한다. PRIMARY KEY는 행을 식별하며 NULL과 중복을 허용하지 않는다.
- FOREIGN KEY는 다른 테이블의 키를 참조해 존재하는 대상과의 관계를 유지한다. 수업의 회원 등급 50은 등급 테이블에 없어 거부된다. 참조 열의 NULL 허용은 NOT NULL 여부도 함께 본다.
- ON UPDATE·DELETE의 SET NULL은 부모 변경·삭제에 관련 참조값을 NULL로, CASCADE는 변경을 따라가거나 자식 행도 삭제하게 한다.
- CHECK는 성별 후보나 나이 19 이상처럼 값 조건을 제한한다. NULL도 막아야 한다면 NOT NULL을 함께 생각한다.
- DEFAULT는 열 값을 생략하거나 DEFAULT를 지정했을 때 채울 기본값이다. 직접 NULL을 넣는 것과는 다르다.

CAST와 CONVERT는 값을 명시적으로 다른 타입으로 바꾼다. 수업은 평균 가격을 SIGNED 정수로, 날짜 문자열을 DATE로, 가격을 CHAR로 바꿨다. 문자 길이를 제한하면 긴 내용이 잘릴 수 있다. 암시적 변환도 있어 문자열 '1'+'2'는 MySQL에서 숫자 계산이 된다. 프로그래밍 언어의 문자열 +와 같은 규칙으로 읽지 않는다.

## ☘️ 인덱스와 직원 과제

인덱스는 조건에 맞는 행을 빠르게 찾는 데 사용할 수 있는 자료구조다. 수업은 phone_name 조건의 조회 계획을 EXPLAIN으로 살펴보고 CREATE INDEX로 이름 인덱스를 만든 뒤 SHOW INDEX로 확인하고 DROP INDEX로 지웠다. 인덱스를 만들었다고 모든 조회가 반드시 그것을 쓰거나 빨라지는 것은 아니다. 데이터 변경에는 인덱스 유지 비용도 있다.

직원 과제는 퇴직 여부·전화번호 끝자리·입사일 순서·LIMIT을 조합하고, 직급과 부서를 JOIN해 이름·급여를 조회했다. 부서별 급여는 재직자를 WHERE로 먼저 고른 뒤 그룹과 ROLLUP을 계산한다. 관리자와 직원은 SELF JOIN으로 연결하며 부서가 없는 경우 LEFT JOIN으로 유지한다.

부서별 급여 합 중 최대는 그룹 합을 내림차순 정렬해 한 행만 얻고, 영업 부서는 서브쿼리로 찾은 코드 목록을 IN 조건으로 사용했다. 이름·가격 검색에서는 LIKE 앞에 등호를 붙이지 않으며 IN·NOT IN의 후보는 괄호로 묶는다. BETWEEN의 양 끝 포함과 정렬 기준의 적용 순서도 과제에서 확인한 경계다.
