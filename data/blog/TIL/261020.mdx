관계형 데이터베이스는 데이터를 행과 열로 구성한 테이블에 보관한다. SQL은 필요한 행을 조회하고 데이터를 변경하며 저장 규칙을 정의하는 언어다. 쿼리의 결과를 예상하려면 어떤 행을 고르고, 어떻게 묶고, 어떤 열을 반환하는지 나누어 읽는다.

## ☘️ 조회 조건과 결과 순서

SELECT는 반환할 열, FROM은 읽을 테이블, WHERE는 행을 고르는 조건이다. 비교·BETWEEN·IN·LIKE를 사용해 범위·목록·문자 패턴 조건을 표현한다. NULL은 값이 없음을 뜻하므로 일반 등호 비교 대신 IS NULL을 사용한다.

DISTINCT는 선택한 결과의 중복을 제거한다. ORDER BY는 결과의 정렬 기준을 정하고 LIMIT은 반환할 개수를 제한한다. 순서를 보장하려면 ORDER BY를 명시한다. 저장되어 보이는 순서와 조회 결과의 순서는 같은 약속이 아니다.

## ☘️ 집계와 테이블 연결

COUNT·SUM·AVG 같은 집계 함수는 여러 행에서 하나의 값을 만든다. GROUP BY는 같은 기준의 행들을 묶고 HAVING은 묶음의 집계 결과를 검사한다. WHERE는 묶기 전 행 조건이므로 HAVING과 적용 대상이 다르다. ROLLUP은 전체나 단계별 합계를 함께 만들 때 사용한다.

JOIN은 키가 연결되는 행을 함께 읽는다. 메뉴의 분류 번호로 분류 테이블의 이름을 찾는 형태다. INNER JOIN은 양쪽에 맞는 행을, LEFT JOIN은 왼쪽 행을 유지하면서 오른쪽 일치값을 연결한다. 오른쪽이 없으면 해당 열은 NULL이 된다.

서브쿼리는 다른 쿼리의 결과를 조건이나 중간 데이터로 사용한다. 한 값인지 여러 행인지에 따라 비교 연산을 맞춘다. UNION은 결과들을 합치면서 중복을 제거하고 UNION ALL은 중복을 유지한다. 연결되는 열의 개수와 의미도 맞아야 한다.

## ☘️ 데이터 변경과 트랜잭션

INSERT는 새 행, UPDATE는 기존 행의 값 변경, DELETE는 행 제거다. UPDATE와 DELETE의 WHERE가 빠지면 전체 행이 대상이 될 수 있다. 실행 전에 같은 조건의 SELECT로 대상을 확인하는 습관이 도움이 된다.

트랜잭션은 여러 변경을 하나의 처리 단위로 묶는다. COMMIT은 확정하고 ROLLBACK은 아직 확정하지 않은 변경을 취소한다. 아래 데이터 변경은 ROLLBACK하므로 초기 세 메뉴가 유지된다. MySQL의 구조 변경 명령은 암묵적 커밋을 일으킬 수 있어 일반 데이터 변경과 같은 방식으로 모두 취소된다고 가정하지 않는다.

## ☘️ 테이블 규칙과 인덱스

CREATE·ALTER·DROP은 테이블 구조를 만들고 바꾸고 없앤다. 기본 키는 행을 구분하고 외래 키는 다른 테이블과의 참조를 제한한다. NOT NULL·UNIQUE·DEFAULT 같은 규칙은 저장 가능한 값의 조건을 정한다. TRUNCATE는 전체 데이터 제거와 관련된 구조 명령이며 조건별 DELETE와 다르다.

인덱스는 검색할 위치를 찾는 데 사용하는 별도 구조다. 조회에 유리할 수 있지만 저장 공간과 쓰기 비용도 든다. EXPLAIN은 데이터베이스가 어떤 접근 방법을 계획했는지 보여 준다. 작은 예제 테이블에서 인덱스를 만들었다고 반드시 사용되거나 더 빠르다고 단정하지 않는다.

## ☘️ 조회·변경·구조·인덱스를 한 데이터에서 확인하기

다음은 연결된 학습 코드의 핵심 동작을 한 파일에서 확인하도록 정리한 설명용 예제다. 원본 프로젝트 전체를 그대로 옮긴 것은 아니다. 필요한 선언과 실행 부분을 함께 두었으며, 아래 코드만 저장해 흐름을 따라갈 수 있다.

**sql-demo.sql**

```sql
CREATE DATABASE til_sql_demo CHARACTER SET utf8mb4;
USE til_sql_demo;
CREATE TABLE tbl_category (category_code INT PRIMARY KEY, category_name VARCHAR(30) NOT NULL, ref_category_code INT);
CREATE TABLE tbl_menu (menu_code INT AUTO_INCREMENT PRIMARY KEY, menu_name VARCHAR(50) NOT NULL UNIQUE, menu_price INT CHECK (menu_price >= 0), category_code INT, orderable_status CHAR(1) DEFAULT 'Y', FOREIGN KEY (category_code) REFERENCES tbl_category(category_code) ON UPDATE CASCADE ON DELETE SET NULL);
INSERT INTO tbl_category VALUES (1, '전체', NULL), (4, '한식', 1), (10, '음료', 1);
INSERT INTO tbl_menu(menu_name, menu_price, category_code) VALUES ('열무김치라떼', 4500, 10), ('우럭스무디', 5000, 10), ('민트미역국', 6000, 4);
SELECT menu_name, menu_price FROM tbl_menu WHERE orderable_status = 'Y' AND menu_price BETWEEN 4500 AND 6000 ORDER BY menu_price DESC LIMIT 1, 2;
SELECT DISTINCT category_code, orderable_status FROM tbl_menu;
SELECT menu_name FROM tbl_menu WHERE menu_name LIKE '%김치%' OR category_code IN (4, 10);
SELECT category_name FROM tbl_category WHERE ref_category_code IS NULL;
SELECT menu_name FROM tbl_menu ORDER BY FIELD(orderable_status, 'N', 'Y'), menu_name;
SELECT category_code, COUNT(*) AS menu_count, SUM(menu_price) AS total FROM tbl_menu GROUP BY category_code WITH ROLLUP;
SELECT category_code, COUNT(*) AS menu_count FROM tbl_menu GROUP BY category_code HAVING COUNT(*) >= 2;
SELECT c.category_name, m.menu_name FROM tbl_category c LEFT JOIN tbl_menu m ON c.category_code = m.category_code;
SELECT child.category_name, parent.category_name AS parent_name FROM tbl_category child JOIN tbl_category parent ON child.ref_category_code = parent.category_code;
SELECT menu_name FROM tbl_menu WHERE category_code = (SELECT category_code FROM tbl_menu WHERE menu_name = '민트미역국');
SELECT MAX(menu_count) FROM (SELECT COUNT(*) AS menu_count FROM tbl_menu GROUP BY category_code) counts;
SELECT m.menu_name FROM tbl_menu m WHERE m.menu_price > (SELECT AVG(menu_price) FROM tbl_menu WHERE category_code = m.category_code);
SELECT menu_name FROM tbl_menu WHERE category_code = 10 UNION SELECT menu_name FROM tbl_menu WHERE menu_price < 6000;
SELECT menu_name FROM tbl_menu WHERE category_code = 10 UNION ALL SELECT menu_name FROM tbl_menu WHERE menu_price < 6000;
SET autocommit = OFF;
START TRANSACTION;
INSERT INTO tbl_menu VALUES (NULL, '순대국밥', 9000, 4, 'Y');
UPDATE tbl_menu SET menu_price = 5500 WHERE menu_code = 1;
DELETE FROM tbl_menu WHERE menu_code = 2;
ROLLBACK;
SET autocommit = ON;
CREATE TABLE structure_demo (pk INT AUTO_INCREMENT PRIMARY KEY, value_text VARCHAR(30));
ALTER TABLE structure_demo ADD extra_number INT;
ALTER TABLE structure_demo CHANGE COLUMN extra_number renamed_number BIGINT;
ALTER TABLE structure_demo MODIFY renamed_number INT;
ALTER TABLE structure_demo DROP COLUMN renamed_number;
INSERT INTO structure_demo(value_text) VALUES ('테스트');
TRUNCATE TABLE structure_demo;
DROP TABLE structure_demo;
CREATE TABLE phone (phone_code INT PRIMARY KEY, phone_name VARCHAR(100) NOT NULL, phone_price DECIMAL(10,2));
INSERT INTO phone VALUES (1, 'iPhone', 2400000), (2, 'Galaxy', 2000000);
EXPLAIN SELECT * FROM phone WHERE phone_name = 'iPhone';
CREATE INDEX idx_phone_name ON phone(phone_name);
EXPLAIN SELECT * FROM phone WHERE phone_name = 'iPhone';
SHOW INDEX FROM phone;
DROP INDEX idx_phone_name ON phone;
SELECT CAST(AVG(menu_price) AS SIGNED) AS average_price, CONCAT(CAST(MAX(menu_price) AS CHAR(10)), '원') AS maximum_price FROM tbl_menu;
SELECT COUNT(*) AS menu_count, SUM(menu_price) AS total_price FROM tbl_menu;
```

독립된 til_sql_demo 데이터베이스를 만들고 분류 세 개와 메뉴 세 개를 넣는다. SELECT는 행 조건을 WHERE로, 묶음 조건을 HAVING으로 거르며 GROUP BY로 묶고 ORDER BY로 결과 순서를 정한다. JOIN은 메뉴의 category_code로 분류 이름을 연결한다. 트랜잭션 안의 등록·수정·삭제는 ROLLBACK하므로 최종 메뉴는 처음의 세 행으로 돌아온다. 별도의 구조 연습 테이블만 ALTER·TRUNCATE·DROP하고 메뉴 테이블은 남긴다. 인덱스 전후 EXPLAIN은 실행 계획을 비교하는 도구이며 작은 데이터에서 인덱스가 반드시 선택된다고 보장하지 않는다. 마지막 결과의 메뉴 수는 3, 단가 합계는 15500이다.

마지막 SELECT의 예상 결과(앞선 조회·구조 명령의 출력과는 별개):

```text
menu_count | total_price
3          | 15500
```
