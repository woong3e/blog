## 학습 내용

오늘은 `06_mysql/01_select.sql`부터 `10_DML.sql`까지의 실습을 바탕으로, MySQL에서 메뉴와 카테고리 데이터를 조회하고 변경하는 방법을 정리했다. 예제는 수업에서 사용한 `tbl_menu`와 `tbl_category`를 기준으로 한다.

### SELECT와 WHERE로 조회하기

`SELECT`는 결과로 볼 컬럼이나 식을 지정하고, `FROM`은 조회할 테이블을 지정한다. `WHERE`는 조건에 맞는 행을 선택한다. **어떤 값을 볼지와 어떤 행을 볼지를 나누어 생각하면 쿼리를 읽기 쉽다.**

```sql
SELECT
    menu_name,
    menu_price
FROM tbl_menu
WHERE orderable_status = 'Y' AND category_code = 10;
```

주문 가능하면서 카테고리 코드가 10인 메뉴의 이름과 가격을 조회한다. 모든 컬럼을 확인하려면 `SELECT * FROM tbl_menu;`처럼 `*`를 사용한다.

테이블 없이 계산식이나 함수 결과를 조회할 수도 있다. `AS`는 결과 컬럼에 별칭을 붙인다.

```sql
SELECT 6 + 3;                        -- 9
SELECT NOW();                       -- 현재 날짜와 시간
SELECT CONCAT('홍', '길동') AS name; -- 문자열을 합쳐 name으로 표시
```

#### 조건에 맞는 연산자 선택

| 연산자                  | 의미                              | 수업 예시                                       |
| ----------------------- | --------------------------------- | ----------------------------------------------- |
| `=`, `<>`, `>`, `<=` 등 | 값을 비교한다.                    | `orderable_status <> 'Y'`                       |
| `AND`, `OR`             | 여러 조건을 조합한다.             | `orderable_status = 'Y' AND category_code = 10` |
| `BETWEEN ... AND ...`   | 양 끝값을 포함한 범위를 확인한다. | `menu_price BETWEEN 10000 AND 25000`            |
| `LIKE`                  | 문자열 패턴을 확인한다.           | `menu_name LIKE '%마늘%'`                       |
| `IN (...)`              | 목록에 포함되는지 확인한다.       | `category_code IN (4, 5, 6)`                    |
| `IS NULL`               | 값이 NULL인지 확인한다.           | `ref_category_code IS NULL`                     |

`LIKE`의 `%`는 문자가 없거나 여러 개 있는 경우를 표현한다. `'%마늘%'`은 어느 위치든 마늘이 포함된 이름, `'마늘%'`은 마늘로 시작하는 이름, `'%마늘'`은 마늘로 끝나는 이름을 찾는다.

범위·패턴·목록을 제외하려면 각각 `NOT BETWEEN`, `NOT LIKE`, `NOT IN`을 사용한다. NULL이 아닌 값은 `IS NOT NULL`로 확인한다. NULL 여부는 `= NULL`이 아니라 `IS NULL`로 검사한다.

수업의 범위 예제에서 실행한 `NOT BETWEEN 10000 AND 25000`은 **10,000원 이상 25,000원 이하인 범위 밖**을 찾는다. 해당 범위 안을 찾으려면 `BETWEEN`을 사용한다.

#### AND와 OR의 우선순위

```sql
SELECT 1 OR 0 AND 0;   -- 1
SELECT (1 OR 0) AND 0; -- 0
```

MySQL에서 이 예제의 1은 참, 0은 거짓을 나타낸다. `AND`가 `OR`보다 먼저 계산되므로 첫 식은 `1 OR (0 AND 0)`으로 처리된다. 조건을 어떤 단위로 묶을지 명확히 하려면 괄호를 사용한다.

### 정렬과 중복 제거, 조회 개수 제한

`ORDER BY`는 결과를 정렬한다. `ASC`는 오름차순이며 생략할 수 있고, `DESC`는 내림차순이다. 여러 기준을 지정하면 앞의 값이 같은 행끼리 다음 기준을 적용한다.

```sql
SELECT menu_code, menu_name, menu_price
FROM tbl_menu
ORDER BY menu_price DESC, menu_name ASC;
```

가격이 높은 순서로 정렬하고, 같은 가격이면 이름을 오름차순으로 정렬한다. 수업에서는 `menu_code * menu_price AS calculated_value`처럼 계산 결과에 별칭을 붙이고 `ORDER BY calculated_value DESC`로 정렬하기도 했다.

#### 원하는 순서와 NULL의 위치

`FIELD(값, 목록...)`는 값이 목록의 몇 번째에 있는지 반환한다. 수업의 `FIELD('B', 'A', 'B', 'C')`는 2를 반환한다. 이를 정렬 기준으로 사용하면 지정한 순서를 반영할 수 있다.

```sql
SELECT menu_name, orderable_status
FROM tbl_menu
ORDER BY FIELD(orderable_status, 'N', 'Y');
```

상태가 N 또는 Y인 메뉴에서 N이 1, Y가 2가 되어 N이 먼저 나온다.

```sql
SELECT *
FROM tbl_category
ORDER BY ref_category_code IS NULL, ref_category_code;
```

`IS NULL`의 결과는 NULL이면 1, 아니면 0이다. 따라서 위 쿼리는 NULL이 아닌 행을 먼저 정렬하고 NULL인 행을 뒤에 둔다. 수업의 `ref_category_code IS NULL DESC, ref_category_code DESC`는 NULL인 행을 먼저 두고 나머지 값을 내림차순으로 정렬한다.

#### DISTINCT와 LIMIT

`DISTINCT`는 조회 결과의 중복을 제거한다. 여러 컬럼을 지정하면 **지정한 컬럼 값의 조합 전체**가 같은 행을 중복으로 판단한다.

```sql
SELECT DISTINCT category_code, orderable_status
FROM tbl_menu;
```

같은 카테고리라도 주문 가능 상태가 다르면 서로 다른 조합으로 남는다.

`LIMIT`은 가져올 행의 개수를 제한한다. 수업의 `ORDER BY menu_price DESC LIMIT 5`는 가격이 비싼 순서로 최대 5행을 조회한다.

```sql
SELECT *
FROM tbl_menu
ORDER BY menu_price DESC
LIMIT 1, 4;
```

`LIMIT 시작 위치, 개수`에서 시작 위치는 **건너뛸 행의 수**다. 위 쿼리는 정렬 결과의 첫 행을 건너뛰고 최대 4행을 가져온다. 이 예제에서 `LIMIT`은 `ORDER BY` 뒤에 작성한다.

### JOIN으로 테이블 연결하기

`JOIN`은 테이블 사이의 관계를 이용해 행을 연결하고 필요한 컬럼을 함께 조회한다. 메뉴의 카테고리 코드로 카테고리 이름을 찾을 때 사용할 수 있다. `ON`에는 연결 조건을 작성한다.

```sql
SELECT a.menu_name, b.category_name
FROM tbl_menu a
JOIN tbl_category b ON a.category_code = b.category_code;
```

`a`, `b`는 테이블 별칭이며 `AS`를 생략한 형태다. 별칭은 컬럼이 어느 테이블에 속하는지 구분하고 표현을 짧게 만든다. 일반적인 JOIN에서 별칭이 항상 필수인 것은 아니지만, 같은 테이블을 두 번 사용하는 셀프 조인에서는 서로를 구분해야 한다.

| 방식                     | 연결되는 행                            | 연결할 행이 없는 경우        |
| ------------------------ | -------------------------------------- | ---------------------------- |
| `INNER JOIN` 또는 `JOIN` | `ON` 조건에 맞는 양쪽 행               | 결과에서 제외한다.           |
| `LEFT JOIN`              | 왼쪽의 모든 행과 조건에 맞는 오른쪽 행 | 오른쪽 컬럼을 NULL로 채운다. |
| `RIGHT JOIN`             | 오른쪽의 모든 행과 조건에 맞는 왼쪽 행 | 왼쪽 컬럼을 NULL로 채운다.   |

```sql
SELECT a.category_name, b.menu_name
FROM tbl_category a
LEFT JOIN tbl_menu b ON a.category_code = b.category_code;
```

카테고리를 왼쪽에 두었으므로 메뉴가 없는 카테고리도 결과에 남는다. 그 행의 `menu_name`은 NULL이다. INNER JOIN을 사용하면 연결되는 메뉴가 있는 카테고리만 조회된다.

#### 같은 테이블을 연결하는 SELF JOIN

```sql
SELECT
    a.category_name AS '하위 카테고리',
    b.category_name AS '상위 카테고리'
FROM tbl_category a
JOIN tbl_category b ON a.ref_category_code = b.category_code;
```

같은 테이블을 `a`는 하위 카테고리, `b`는 상위 카테고리 역할로 사용한다. 하위 행의 `ref_category_code`와 상위 행의 `category_code`를 연결한다. 이 예제는 INNER JOIN이므로 연결할 상위 카테고리가 없는 행은 제외된다.

### GROUP BY와 HAVING으로 집계하기

`GROUP BY`는 지정한 컬럼의 값이 같은 행들을 묶는다. 집계 함수와 함께 사용하면 개별 메뉴 대신 카테고리별 메뉴 수나 가격 통계를 조회할 수 있다.

```sql
SELECT
    category_code,
    COUNT(*) AS menu_count,
    SUM(menu_price) AS total_price,
    AVG(menu_price) AS average_price
FROM tbl_menu
GROUP BY category_code;
```

`COUNT(*)`는 행 수, `SUM()`은 합계, `AVG()`는 평균을 구한다. 위 코드는 수업의 메뉴 수·가격 합계·평균 조회를 한 쿼리로 묶은 것이다.

집계 결과에서는 각 값이 어떤 그룹을 대표하는지 분명해야 한다. 이 예제는 그룹 기준인 `category_code`와 집계 값들을 조회한다. 같은 카테고리에 여러 `menu_code`가 있으므로, 개별 메뉴 코드를 그대로 추가하면 그룹을 대표할 값이 명확하지 않다.

#### WHERE와 HAVING의 차이

| 구문     | 조건을 적용하는 대상과 시점 | 예시                     |
| -------- | --------------------------- | ------------------------ |
| `WHERE`  | 그룹화하기 전의 개별 행     | `orderable_status = 'Y'` |
| `HAVING` | 그룹화하고 집계한 결과      | `COUNT(*) >= 3`          |

```sql
SELECT category_code, COUNT(*) AS menu_count
FROM tbl_menu
GROUP BY category_code
HAVING COUNT(*) >= 3;
```

카테고리별로 메뉴 수를 계산한 다음, 메뉴가 3개 이상인 그룹만 남긴다. 그룹의 메뉴 수에 대한 조건이므로 `HAVING`에 작성한다.

#### WITH ROLLUP으로 소계와 총계 조회

```sql
SELECT menu_price, category_code, SUM(menu_price) AS total_price
FROM tbl_menu
GROUP BY menu_price, category_code WITH ROLLUP;
```

수업처럼 가격과 카테고리 순서로 그룹화하면 가격·카테고리 조합별 합계, 가격별 소계, 전체 총계를 함께 구할 수 있다. 그룹 컬럼이 하나인 `GROUP BY category_code WITH ROLLUP`은 카테고리별 합계에 전체 총계를 추가한다.

ROLLUP이 추가하는 집계 행에서는 해당 집계 수준에서 묶인 컬럼이 NULL로 표시된다. 예를 들어 가격별 소계는 `category_code`가 NULL이고, 전체 총계는 두 그룹 컬럼이 모두 NULL이다.

### 서브쿼리로 조회 결과 활용하기

서브쿼리는 다른 SQL 문 안에 포함된 조회문이다. 먼저 필요한 값을 조회하고 그 결과를 바깥 쿼리의 조건이나 조회 대상으로 활용한다.

#### 조건에 조회 결과 사용

```sql
SELECT menu_name, category_code
FROM tbl_menu
WHERE category_code = (
    SELECT category_code
    FROM tbl_menu
    WHERE menu_name = '민트미역국'
);
```

안쪽 쿼리로 민트미역국의 카테고리 코드를 구하고, 바깥에서 같은 카테고리의 메뉴를 찾는다. 비교 연산자 `=` 오른쪽에서 사용하므로 이 예제는 안쪽 조회가 하나의 값을 반환하는 것을 전제로 한다. 여러 행을 비교할 때는 결과 형태에 맞는 연산자가 필요하다.

#### FROM 절의 파생 테이블

```sql
SELECT MAX(menu_count) AS max_menu_count
FROM (
    SELECT COUNT(*) AS menu_count
    FROM tbl_menu
    GROUP BY category_code
) AS count_table;
```

안쪽 쿼리는 카테고리별 메뉴 수를 구하고, 바깥 쿼리는 그중 최댓값을 찾는다. 결과는 **가장 많은 메뉴가 속한 카테고리의 메뉴 수**이며, 그 카테고리 코드 자체를 조회하는 것은 아니다.

`FROM` 안의 서브쿼리는 조회 결과를 테이블처럼 사용하는 **파생 테이블**이다. MySQL에서는 `count_table`처럼 별칭을 지정해야 한다. 위 코드는 수업의 `count` 별칭을 의미가 드러나도록 `menu_count`로 바꿨다.

#### 바깥 행을 참조하는 상관 서브쿼리

```sql
SELECT a.menu_code, a.menu_name, a.menu_price
FROM tbl_menu a
WHERE a.menu_price > (
    SELECT AVG(b.menu_price)
    FROM tbl_menu b
    WHERE b.category_code = a.category_code
);
```

각 메뉴의 가격을 **자신이 속한 카테고리의 평균 가격**과 비교한다. 안쪽 쿼리의 `a.category_code`는 바깥 쿼리에서 현재 비교하는 메뉴의 카테고리를 참조한다.

이처럼 서브쿼리가 바깥 행의 값을 참조하면 상관 서브쿼리다. 모든 메뉴를 하나의 고정된 평균과 비교하는 것이 아니라, 각 메뉴의 카테고리에 맞는 평균을 기준으로 판단한다.

### 조회 결과의 집합 연산

수업에서는 다음 두 집합을 사용했다.

- A: 카테고리 코드가 10인 메뉴
- B: 가격이 9,000원 미만인 메뉴

#### UNION과 UNION ALL

```sql
SELECT menu_name, menu_price, category_code
FROM tbl_menu
WHERE category_code = 10
UNION
SELECT menu_name, menu_price, category_code
FROM tbl_menu
WHERE menu_price < 9000;
```

`UNION`은 두 결과를 합치면서 조회한 컬럼 조합이 같은 중복 행을 제거한다. `UNION ALL`로 바꾸면 중복 행도 그대로 남긴다. 두 조회에는 같은 개수의 컬럼을 대응되는 순서로 작성하고, 서로 호환되는 타입의 값을 조회해야 한다.

#### IN으로 교집합 조회

```sql
SELECT menu_code, menu_price, category_code
FROM tbl_menu
WHERE category_code = 10
  AND menu_code IN (
      SELECT menu_code
      FROM tbl_menu
      WHERE menu_price < 9000
  );
```

A에 속한 메뉴 중 B에도 메뉴 코드가 있는 행을 남긴다. 따라서 카테고리가 10이면서 가격이 9,000원 미만인 메뉴를 조회한다.

#### LEFT JOIN과 IS NULL로 차집합 조회

```sql
SELECT a.menu_code, a.menu_price, a.category_code
FROM tbl_menu a
LEFT JOIN (
    SELECT menu_code
    FROM tbl_menu
    WHERE menu_price < 9000
) b ON a.menu_code = b.menu_code
WHERE a.category_code = 10 AND b.menu_code IS NULL;
```

가격이 9,000원 미만인 메뉴를 오른쪽에 연결한 뒤, 오른쪽 메뉴 코드가 NULL인 행만 남긴다. **A에 속하지만 B에는 없는 메뉴**를 찾는 방식이다.

JOIN은 연결 조건에 따라 양쪽 행의 컬럼을 함께 조회하고, UNION은 여러 조회 결과의 행을 합친다. 목적에 맞게 구분해서 사용한다.

### DML로 데이터 변경하기

`INSERT`, `UPDATE`, `DELETE`는 각각 행을 추가·수정·삭제한다. 수업에서는 조회 구문 `SELECT`도 함께 다뤘으며, 조회를 별도로 DQL이라고 구분하기도 했다.

#### INSERT로 행 추가

```sql
INSERT INTO tbl_menu (menu_name, menu_price, orderable_status, category_code)
VALUES ('초콜릿', 5000, 'Y', 7);
```

지정한 컬럼 순서에 맞춰 값을 작성한다. 수업의 `INSERT INTO tbl_menu VALUES (...)`처럼 컬럼 목록을 생략하면 테이블 컬럼 순서에 맞춰 값을 모두 작성해야 한다.

여러 행은 `VALUES` 뒤에 괄호 묶음을 쉼표로 이어 한 번에 추가할 수 있다.

```sql
INSERT INTO tbl_menu
VALUES
    (NULL, '바닐라아이스크림', 2000, 12, 'Y'),
    (NULL, '딸기아이스크림', 1000, 11, 'Y'),
    (NULL, '녹차아이스크림', 1700, 8, 'Y');
```

이 예제는 수업 테이블의 컬럼 순서와 메뉴 코드 생성 설정을 전제로 한다.

#### UPDATE와 DELETE의 대상 확인

```sql
SELECT menu_code, menu_name, category_code
FROM tbl_menu
WHERE menu_name = '순대국밥';

UPDATE tbl_menu
SET category_code = 7
WHERE menu_code = 22;
```

`SET`에는 바꿀 값을, `WHERE`에는 바꿀 행의 조건을 작성한다. 수업에서는 순대국밥의 메뉴 코드를 조회한 뒤 22번 행을 수정했다. 실제 메뉴 코드는 데이터 상태에 따라 다를 수 있으므로 조회 결과를 확인하고 사용한다.

```sql
SELECT *
FROM tbl_menu
WHERE menu_code = 22;

DELETE FROM tbl_menu
WHERE menu_code = 22;
```

삭제도 같은 조건으로 먼저 조회해 대상을 확인한다. `UPDATE`나 `DELETE`에서 `WHERE`를 생략하면 테이블의 모든 행이 대상이 된다.

#### REPLACE는 삭제 후 삽입

```sql
REPLACE INTO tbl_menu
VALUES (17, '참기름', 5000, 10, 'Y');
```

기본 키 또는 UNIQUE 키가 충돌하면 일반 `INSERT`는 중복 오류가 발생할 수 있다. `REPLACE`는 충돌하는 기존 행을 삭제하고 새 행을 삽입하며, 충돌이 없으면 새 행을 삽입한다.

따라서 `REPLACE`를 기존 행의 일부 컬럼만 바꾸는 `UPDATE`와 같은 동작으로 이해하면 안 된다. 수업 예제는 17번 키가 이미 있을 때 해당 행을 새 값으로 대체하는 경우다.
