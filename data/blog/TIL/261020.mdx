## ☘️ 조회와 집계

**조회는 행을 고르고, 집계는 행을 묶어 계산한다.**

- `SELECT`: 볼 컬럼 / `FROM`: 테이블 / `WHERE`: 행 조건
- `SELECT *`: 모든 컬럼. 테이블 없이 `SELECT 6 + 3`, `NOW()`, `CONCAT('홍', '길동')`처럼 계산·함수 조회도 가능. `AS`는 결과 별칭
- `ORDER BY`: 정렬. `ASC`는 오름차순, `DESC`는 내림차순
- `DISTINCT`: 중복 제거. 여러 컬럼이면 값의 조합을 기준으로 판단
- `LIMIT 1, 4`: 첫 행을 건너뛰고 최대 4행 조회

**조건 고르기**

- `=`, `<>`, `>`, `<=`: 같음·다름·크기 비교. `AND`는 모두 만족, `OR`는 하나 이상 만족
- `BETWEEN 10000 AND 25000`: 양 끝을 포함한 범위. `NOT BETWEEN`은 범위 밖
- `LIKE '%마늘%'`: 마늘 포함. `'마늘%'`는 시작, `'%마늘'`은 끝. `%`는 0개 이상의 문자
- `IN (4, 5, 6)`: 목록에 포함. `NOT IN`, `NOT LIKE`는 해당 조건 제외
- `IS NULL` / `IS NOT NULL`: NULL 여부. `= NULL`로 검사하지 않는다.

`AND`가 `OR`보다 먼저 계산된다. `1 OR 0 AND 0`은 1, `(1 OR 0) AND 0`은 0이므로 의도한 묶음에 괄호를 쓴다.

**정렬 기억하기**

`ORDER BY menu_price DESC, menu_name ASC`는 가격 내림차순 → 같은 가격끼리 이름 오름차순이다. 계산식에 붙인 별칭도 정렬 기준으로 쓸 수 있다.

- `FIELD('B', 'A', 'B', 'C')`는 2. `ORDER BY FIELD(orderable_status, 'N', 'Y')`로 N → Y 순서를 지정한다(값이 N·Y인 경우).
- `ORDER BY ref_category_code IS NULL, ref_category_code`: NULL 아닌 행부터 정렬. `IS NULL DESC`면 NULL 먼저
- `DISTINCT category_code, orderable_status`: 두 값이 모두 같은 조합만 중복 제거
- `ORDER BY menu_price DESC LIMIT 5`: 비싼 메뉴 최대 5개. `LIMIT`은 정렬 뒤에 작성

**그룹으로 계산하기**

```sql
SELECT category_code, COUNT(*) AS menu_count
FROM tbl_menu
WHERE orderable_status = 'Y'
GROUP BY category_code
HAVING COUNT(*) >= 3;
```

주문 가능한 메뉴를 고르고 → 카테고리별로 묶고 → 메뉴가 3개 이상인 그룹만 남긴다.

**WHERE는 그룹화 전의 행, HAVING은 집계 후의 그룹을 거른다.** `COUNT(*)`는 행 수, `SUM()`은 합계, `AVG()`는 평균이다. `WITH ROLLUP`을 붙이면 그룹 기준에 따른 소계·총계도 나온다.

조회 컬럼은 그룹 기준이나 집계 값으로 구성한다. 카테고리별 집계에 개별 `menu_code`를 그대로 넣으면 어떤 메뉴를 대표하는지 불분명하다.

`GROUP BY menu_price, category_code WITH ROLLUP`은 가격·카테고리별 합계 → 가격별 소계 → 총계 순으로 집계한다. 소계는 `category_code`, 총계는 두 그룹 컬럼이 NULL로 표시된다. 그룹 기준이 하나면 그룹별 합계와 총계를 구한다.

## ☘️ 조인과 서브쿼리

**JOIN은 테이블을 옆으로 연결하고, UNION은 조회 결과를 아래로 합친다.**

- `INNER JOIN`: 연결 조건에 맞는 행만 남긴다.
- `LEFT JOIN`: 왼쪽 행을 모두 남기고, 연결할 오른쪽 값이 없으면 NULL로 채운다. `RIGHT JOIN`은 반대다.
- `SELF JOIN`: 같은 테이블에 서로 다른 별칭을 붙여 연결한다.
- `UNION`: 합친 결과의 중복 제거. `UNION ALL`은 중복 유지.

`ON`은 연결 조건이다. `tbl_menu m`의 `m`은 테이블 별칭(`AS` 생략)이며 컬럼의 소속을 구분한다. 일반 조인에서 별칭은 필수가 아니지만 셀프 조인에서는 역할을 구분해야 한다.

```sql
SELECT c.category_name, m.menu_name
FROM tbl_category c
LEFT JOIN tbl_menu m ON c.category_code = m.category_code;
```

메뉴가 없는 카테고리도 남는다. 이때 `m.menu_name`은 NULL이다.

상·하위 카테고리는 `tbl_category a JOIN tbl_category b ON a.ref_category_code = b.category_code`로 연결한다. `a`는 하위, `b`는 상위이며, INNER JOIN이므로 상위가 없는 행은 제외된다.

**서브쿼리는 SQL 안의 조회문이다.** 조건에 값을 전달하거나, `FROM`에서 테이블처럼 쓸 수 있다. `FROM` 안의 서브쿼리에는 별칭이 필요하다.

- **조건의 서브쿼리**: `WHERE category_code = (SELECT category_code FROM tbl_menu WHERE menu_name = '민트미역국')` → 같은 카테고리 메뉴 조회. `=` 오른쪽은 단일 값이어야 한다.
- **파생 테이블**: `FROM (SELECT COUNT(*) AS menu_count FROM tbl_menu GROUP BY category_code) AS counts` → 카테고리별 메뉴 수를 테이블처럼 사용. 바깥에서 `MAX(menu_count)`를 구하면 최대 메뉴 수이며, 카테고리 코드 자체는 아니다.
- **상관 서브쿼리**: 바깥 행을 참조해 해당 행에 맞는 기준으로 비교한다.

```sql
SELECT a.menu_name, a.menu_price
FROM tbl_menu a
WHERE a.menu_price > (
    SELECT AVG(b.menu_price)
    FROM tbl_menu b
    WHERE b.category_code = a.category_code
);
```

자기 카테고리의 평균보다 비싼 메뉴를 찾는다. 안쪽에서 바깥 행의 `a.category_code`를 참조하므로 **상관 서브쿼리**다.

집합을 비교할 때는 `IN`으로 양쪽에 속한 행을, `LEFT JOIN` 후 오른쪽 키의 `IS NULL` 조건으로 왼쪽에만 속한 행을 찾을 수 있다.

수업의 A는 카테고리 10, B는 가격 9,000원 미만인 메뉴다. 교집합은 A에서 B의 메뉴 코드에 `IN`인 행, 차집합은 A에 B를 연결한 뒤 `b.menu_code IS NULL`인 행이다.

`UNION`은 두 SELECT의 컬럼 개수와 대응 순서를 맞추고 타입이 호환되어야 한다. 중복은 조회한 컬럼 조합 전체로 판단한다.

## ☘️ 데이터 변경

- `INSERT`: 새 행 추가
- `UPDATE`: 기존 행의 지정한 컬럼 수정
- `DELETE`: 행 삭제
- `REPLACE`: 키 충돌 시 기존 행을 삭제하고 새 행 삽입. 충돌이 없으면 추가

수업에서는 SELECT도 함께 다뤘으며, 조회를 별도로 DQL이라고 구분하기도 한다.

**추가할 컬럼과 값의 순서를 맞춘다.** 컬럼 목록을 생략하면 테이블의 전체 컬럼 순서에 맞춰 값을 작성해야 한다. 여러 행은 VALUES 뒤에 괄호 묶음을 쉼표로 잇는다.

```sql
INSERT INTO tbl_menu (menu_name, menu_price, orderable_status, category_code)
VALUES ('초콜릿', 5000, 'Y', 7), ('바닐라아이스크림', 2000, 'Y', 12);
```

수업의 전체 컬럼 삽입 예제는 메뉴 코드 자리에 NULL을 넣어 자동 생성 설정을 활용했다.

```sql
SELECT * FROM tbl_menu WHERE menu_code = 22;

UPDATE tbl_menu
SET category_code = 7
WHERE menu_code = 22;

-- 삭제할 때도 같은 조건으로 먼저 조회한다.
DELETE FROM tbl_menu WHERE menu_code = 22;
```

**UPDATE·DELETE는 실행 전 같은 WHERE로 대상을 조회한다.** WHERE를 빼면 모든 행이 대상이 된다. REPLACE는 일부 컬럼만 고치는 UPDATE와 동작이 다르다.

`SET`에 바꿀 컬럼과 값을 쓴다. 예제의 22번은 수업에서 조회한 메뉴 코드이므로 실제 실행 시 조회 결과로 확인한다. `REPLACE INTO tbl_menu VALUES (17, '참기름', 5000, 10, 'Y')`는 기본 키·UNIQUE 키 충돌 시 삭제 후 삽입하며, 일반 INSERT는 중복 오류가 날 수 있다.
