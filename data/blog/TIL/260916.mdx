## ☘️ React가 화면을 표현하는 방법

React는 화면을 재사용 가능한 **컴포넌트**로 나누어 만드는 라이브러리다. 컴포넌트는 헤더나 학생 카드처럼 화면의 한 부분을 담당한다. 수업에서는 화면을 나타내는 값을 만들고 root에 렌더링한 뒤, 함수와 props로 화면을 나누었다. 렌더링은 화면에 필요한 구조를 계산하는 과정이라고 이해하면 된다.

React.createElement는 태그·속성·자식 내용으로 React 엘리먼트를 만든다. 이 값은 실제 DOM 노드 자체가 아니라 어떤 화면을 만들지 설명하는 값이다. ReactDOM.createRoot로 HTML의 root 요소와 연결하고 render에 전달하면 React가 실제 DOM에 반영한다.

**JSX와 컴포넌트**

JSX는 자바스크립트 안에서 HTML처럼 생긴 화면 구조를 작성하는 문법이다. 브라우저가 그대로 실행하는 HTML은 아니며 수업에서는 Babel을 사용해 변환했다. createElement를 여러 겹 호출하는 대신 JSX로 중첩 구조를 읽기 쉽게 표현했다.

함수형 컴포넌트는 화면 구조를 반환하는 함수이고 이름은 대문자로 시작한다. 클래스형 컴포넌트는 React.Component를 상속하고 render 메서드를 구현한다. 여러 컴포넌트를 App 안에 배치하는 것을 합성이라고 한다.

JSX의 중괄호 안에는 변수나 함수 호출처럼 값을 만드는 표현식을 넣는다. class는 className, onclick은 onClick으로 쓰고, 스타일은 문자열이 아닌 객체로 전달한다. 객체의 backgroundColor처럼 CSS 속성은 카멜 표기법을 사용한다. 모든 태그를 닫아야 하며 여러 요소를 반환할 때는 하나로 묶는다. 빈 태그 Fragment를 쓰면 불필요한 실제 DOM 태그 없이 묶을 수 있다.

## ☘️ props와 children으로 값 전달하기

props는 부모가 자식에게 전달하는 값들을 담은 객체다. 함수의 매개변수처럼 자식은 전달받은 값으로 화면을 만들며, 같은 컴포넌트에 다른 값을 주어 재사용한다. 자식은 받은 props를 직접 수정하지 않는다. 기본 데이터 흐름은 부모에서 자식으로 향한다.

수업의 StudentCard는 매개변수에서 name·age·track을 구조 분해로 꺼낸다.

```jsx
function StudentCard({ name, age, track = '미정' }) {
  return (
    <div className="student-card">
      안녕하세요 {name} {age} {track}
    </div>
  )
}
```

App은 박지성·30·track 5를 전달한 카드와 손흥민·20만 전달한 카드를 만든다. 두 번째 track은 없으므로 기본값 미정이 표시된다. 글자는 따옴표로, 숫자나 변수 같은 자바스크립트 값은 중괄호로 전달한다.

CourseHeader는 title과 teacher로 과정 제목을 만들고, InfoPanel은 title과 children을 받는다. children은 컴포넌트의 여는 태그와 닫는 태그 사이에 작성한 내용이다. 자식이 children을 출력하는 위치에 그 내용이 들어간다. 글자뿐 아니라 여러 JSX 요소도 전달할 수 있으며, 같은 패널 안에 서로 다른 내용을 넣기 위한 구성 방식이다.

기본값은 전달받은 값이 undefined일 때 적용된다. 수업의 Greeting은 이름과 나이의 기본값, InfoPanel은 안내라는 기본 제목을 지정했다. 실제 과제의 InfoPanel 호출에는 별도의 제목을 전달하므로 그 제목이 기본값 대신 표시된다.

## ☘️ 브라우저와 React의 화면 갱신

브라우저는 HTML을 읽어 DOM을, CSS를 읽어 스타일 구조인 CSSOM을 만든다. 표시할 요소와 스타일을 바탕으로 렌더 트리를 구성한 뒤 위치와 크기를 계산하는 레이아웃, 픽셀을 그리는 페인트를 거친다. 배치가 달라지면 레이아웃 재계산(reflow), 색처럼 그리는 모습이 바뀌면 다시 그리기(repaint)가 필요할 수 있다.

직접 DOM을 다룰 때는 개발자가 어떤 노드의 글자와 스타일을 바꿀지 지정했다. React에서는 주어진 데이터에 어떤 화면이 대응하는지 작성한다. 새 React 엘리먼트 구조와 이전 구조를 비교하는 조정 과정(reconciliation)을 거쳐 필요한 실제 DOM 변경을 반영한다.

수업의 시계는 1초마다 root.render로 Clock을 다시 전달한다. 매번 화면 설명을 계산해도 모든 DOM 노드를 무조건 새로 만드는 것은 아니다. 이전 구조와 비교해 변경할 부분을 정한다. 일반 트리 비교의 높은 비용과 React가 가정에 따라 선형 수준으로 비교한다는 점을 학습했지만, 이것이 모든 화면 갱신이 언제나 빠르다는 보장은 아니다.
