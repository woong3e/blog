## ☘️ 상속과 오버라이딩

extends로 공통 상태·기능을 재사용하고 확장한다. Car의 FireCar는 물 뿌리기를 추가하고 경적을 재정의했다.

- super()·super(...): 부모 생성자 호출. 부모 → 자식 생성자 순서. 생성자는 상속되지 않음
- super.method(): 부모 구현 재사용. RacingCar.run은 부모의 주행 상태 변경 후 추가 동작
- 부모 private 필드는 직접 접근하지 않고 생성자·메서드로 처리. runningStatus는 protected isRunning으로 확인
- protected: 같은 패키지, 다른 패키지는 상속 규칙에 따른 접근
- Product→Computer: 부모 생성자가 code·name·price, 자식은 cpu·ram 초기화. getInformation도 부모 결과 확장
- 매개변수 생성자만 있는 SmartPhone은 인자 없는 new SmartPhone() 불가

**오버라이딩**은 부모 동작을 같은 호출 형태로 재정의한다. VendingMachine.vend의 밀크 커피를 CoffeeVendingMachine이 아이스 아메리카노로 바꿨다. @Override로 컴파일러 검사를 받는다.

- 이름·매개변수 동일 / 반환 타입 동일 또는 참조형의 하위 타입
- 접근 범위는 같거나 넓게 / 검사 예외는 같거나 좁게
- private은 상속된 메서드 재정의 대상 아님 / final은 호출 가능하지만 재정의 불가
- 오버로딩은 매개변수 구성이 다른 같은 이름의 메서드 추가

수업은 protected clean()을 public으로 넓혔다. vend()의 반환형만 String→int로 바꾸면 재정의가 아니며, vend(String type)은 오버로딩이라 @Override를 붙이면 오류다.

## ☘️ 다형성과 형변환

```java
Animal animal = new Rabbit(); // 자동 업캐스팅
animal.cry();                 // Rabbit의 재정의한 cry
if (animal instanceof Rabbit) ((Rabbit) animal).jump();
```

부모 타입으로 여러 자식 객체를 매개변수·배열에 담아 같은 기능을 호출한다. **동적 바인딩은 실제 객체의 재정의된 동작을 선택**하며 객체 자체가 부모로 바뀌지는 않는다.

컴파일 때는 참조 타입의 호출 가능 메서드를 확인한다. ZooKeeper의 feed(Rabbit)·feed(Tiger)·feed(Animal) 중 `feed(new Rabbit())`은 Rabbit 버전, Animal 타입 변수·배열 요소를 전달하면 Animal 버전이 선택된다. 그 안의 animal.eat()은 실제 동물의 구현으로 실행된다. **오버로딩 선택과 오버라이딩 실행을 구분한다.**

부모에 없는 jump는 Rabbit으로 다운캐스팅해야 한다. 실제 Tiger를 Rabbit으로 변환하면 ClassCastException이므로 instanceof로 확인한다. 배열 처리에서는 검사한 현재 변수 animal을 변환한다. 원본의 바깥 tiger 변수를 사용하면 같은 호랑이를 반복 처리한다.

## ☘️ 공통 구현과 기능 약속

```java
abstract class Player {
    public abstract void attack();
    public void levelUp() { System.out.println("레벨업"); }
}
interface IConnectable {
    void connect();
    void disconnect();
}
```

- 추상 클래스는 직접 new 불가. 참조·배열 타입으로는 가능. 구체 자식 Warrior·Wizard가 attack을 검·마법으로 구현하고 levelUp은 공통 사용
- 추상 자식은 구현을 더 미룰 수 있지만 최종 구체 클래스는 남은 추상 메서드 구현 필요
- 인터페이스는 기능의 약속. `implements IConnectable`인 Keyboard·Mouse가 public connect/disconnect 구현
- 수업의 인터페이스 추상 메서드는 public abstract 생략 가능. 인터페이스 자체 new는 불가
- Computer.connectDevice(IConnectable device)는 device.connect만 호출하면 실제 장치 동작 실행. 해제도 같은 방식

| 기준      | 추상 클래스                  | 인터페이스                 |
| --------- | ---------------------------- | -------------------------- |
| 목적      | 공통 상태·구현과 개별 동작   | 제공할 기능의 약속         |
| 사용      | extends Player               | implements IConnectable    |
| 여러 타입 | 부모 클래스 하나 상속        | 여러 인터페이스 구현 가능  |
| 수업 선택 | 캐릭터 공통 레벨업+개별 공격 | 서로 다른 장치의 연결·해제 |

둘 다 다형성의 타입이 된다. **공통 기반 구현이 필요한지, 같은 기능 규약이 필요한지**로 선택한다.
