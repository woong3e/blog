### 상속과 super

상속은 공통 상태와 기능을 부모 클래스에 정의하고, 자식 클래스가 이를 재사용하거나 자신의 목적에 맞게 확장하는 방법이다. `extends`로 부모 클래스를 지정한다.

수업에서는 `Car`를 부모로 두고 `FireCar`와 `RacingCar`를 만들었다. 소방차는 자동차의 주행 기능을 사용하면서 물을 뿌리는 기능을 추가하고, 경적 동작을 재정의했다.

```java
public class FireCar extends Car {
    public FireCar() {
        super();
        System.out.println("FireCar 클래스 기본 생성자 호출");
    }

    @Override
    public void soundHorn() {
        if (isRunning()) {
            System.out.println("FireCar 경적 울린다");
        } else {
            System.out.println("FireCar가 멈춰있다");
        }
    }

    public void sprayWater() {
        System.out.println("물 뿌리기");
    }
}
```

`new FireCar()`를 실행하면 부모 생성자가 먼저 실행되어 `Car 클래스 기본 생성자 호출`, `FireCar 클래스 기본 생성자 호출` 순서로 출력된다.

`Car`의 `runningStatus`는 private이므로 자식이 직접 접근하지 않는다. 대신 부모가 제공한 protected 메서드 `isRunning()`으로 주행 상태를 확인한다. protected는 같은 패키지에서 접근할 수 있고, 다른 패키지에서는 상속 관계에 따른 접근을 허용한다.

| 표현             | 역할                         | 수업 예시                             |
| ---------------- | ---------------------------- | ------------------------------------- |
| `super()`        | 부모의 인자 없는 생성자 호출 | `FireCar`에서 `Car` 초기화            |
| `super(...)`     | 인자에 맞는 부모 생성자 호출 | `Computer`에서 상품 정보 초기화       |
| `super.메서드()` | 부모가 구현한 메서드 호출    | `RacingCar`에서 부모의 주행 처리 실행 |

아래는 `Product`를 상속한 `Computer`의 생성자다.

```java
public Computer(String code, String name, int price, String cpu, int ram) {
    super(code, name, price);
    this.cpu = cpu;
    this.ram = ram;
    System.out.println("Computer 매개변수 있는 생성자 호출");
}
```

부모의 private 필드인 `code`, `name`, `price`는 부모 생성자에서 초기화하고, 자식의 `cpu`, `ram`은 자식 생성자에서 초기화한다. 생성자는 상속받는 것이 아니라 각 클래스에서 정의하고 호출한다.

`RacingCar.run()`은 `super.run()`으로 주행 상태를 먼저 true로 바꾼 뒤 추가 메시지를 출력한다. `Computer.getInformation()`도 `super.getInformation()`의 결과에 CPU와 RAM을 이어 붙여 부모 구현을 재사용한다.

매개변수 있는 생성자만 작성한 `SmartPhone`에는 인자 없는 생성자가 자동으로 생기지 않는다. 따라서 수업의 `new SmartPhone()`은 사용할 수 없으며, 정의된 생성자에 맞게 인자를 전달해야 한다.

### 오버라이딩의 조건

오버라이딩은 부모에게 물려받은 메서드를 자식의 목적에 맞게 재정의하는 것이다. 같은 호출 방식으로 자식마다 다른 동작을 제공할 수 있다.

```java
// VendingMachine
public String vend() {
    return "밀크 커피";
}

// CoffeeVendingMachine extends VendingMachine
@Override
public String vend() {
    return "아이스 아메리카노";
}
```

위 코드는 각각의 클래스에 선언한 메서드다. 부모 객체의 `vend()`는 밀크 커피를, 자식 객체의 `vend()`는 아이스 아메리카노를 반환한다. `@Override`는 부모 메서드를 올바르게 재정의했는지 컴파일러가 확인하게 한다.

| 확인할 항목                 | 오버라이딩 규칙                                                     |
| --------------------------- | ------------------------------------------------------------------- |
| 메서드 이름과 매개변수 목록 | 부모와 같아야 한다.                                                 |
| 반환 타입                   | 부모와 같아야 한다. 참조형은 부모 반환 타입의 하위 타입도 가능하다. |
| 접근제한자                  | 부모와 같거나 더 넓어야 한다.                                       |
| 부모의 private 메서드       | 자식에서 오버라이딩할 수 없다.                                      |
| 부모의 final 메서드         | 호출할 수 있지만 오버라이딩할 수 없다.                              |

접근 범위는 `private → 접근제한자 생략 → protected → public` 순으로 넓어진다. 수업에서는 부모의 protected `clean()`을 자식에서 public으로 재정의했다. 반대로 접근 범위를 좁히면 컴파일 오류가 발생한다.

`vend()`의 반환 타입만 String에서 int로 바꾸면 오버라이딩이 성립하지 않는다. 매개변수를 추가한 `vend(String type)`은 **오버로딩**에 해당하며, `@Override`를 붙이면 오류가 발생한다. 오버로딩은 매개변수 구성이 다른 메서드를 추가하는 것이고, 오버라이딩은 상속받은 메서드의 동작을 바꾸는 것이다.

### 다형성과 동적 바인딩

다형성은 부모 타입 하나로 여러 자식 객체를 다루고, 같은 메서드를 호출해도 실제 객체에 따라 다른 동작이 실행되는 성질이다.

```java
Animal rabbit = new Rabbit();
Animal tiger = new Tiger();

rabbit.cry(); // 토끼가 운다.
tiger.cry();  // 호랑이가 운다.
```

컴파일할 때는 참조 변수의 타입인 `Animal`에서 호출 가능한 메서드를 확인한다. 실행할 때는 실제 객체가 `Rabbit`인지 `Tiger`인지에 따라 오버라이딩된 `cry()`가 실행된다. 이처럼 실행 시점에 호출할 구현이 결정되는 원리를 **동적 바인딩**이라고 한다.

#### 매개변수에 다형성 적용

수업의 `ZooKeeper`에는 토끼와 호랑이를 각각 받는 메서드와, 부모 타입을 받는 메서드가 함께 있다.

```java
public void feed(Animal animal) {
    System.out.println("다형성 적용");
    animal.eat();
}
```

`feed(Animal)`은 `Animal`의 자식 객체를 받아 각 객체의 `eat()`을 실행한다. 공통 기능으로 처리할 수 있다면 동물마다 별도의 매개변수 타입을 받는 메서드를 만들 필요가 줄어든다.

현재 수업 코드에는 `feed(Rabbit)`, `feed(Tiger)`도 남아 있다. 따라서 `feed(new Rabbit())`는 `feed(Rabbit)`을 호출한다. 아래처럼 `Animal` 타입 변수로 전달하면 `feed(Animal)`이 선택되고, 그 안의 `eat()`은 실제 토끼 구현을 실행한다.

```java
ZooKeeper zooKeeper = new ZooKeeper();
Animal animal = new Rabbit();
zooKeeper.feed(animal);
```

#### 객체 배열에 다형성 적용

```java
Animal[] animals = {new Rabbit(), new Tiger(), new Rabbit()};

for (Animal animal : animals) {
    animal.cry();
    zooKeeper.feed(animal);
}
```

수업의 배열 초기화를 세 객체로 줄인 예시다. 부모 타입 배열에 서로 다른 자식 객체를 담으면 반복문 하나로 공통 기능을 호출할 수 있다. 배열을 순회하는 변수도 `Animal`이므로 `feed(Animal)`이 호출된다.

### 업캐스팅과 다운캐스팅

업캐스팅은 자식 객체의 참조값을 부모 타입 변수에 저장하는 것이다. `Animal rabbit = new Rabbit()`처럼 자동으로 처리된다. 객체 자체가 부모 객체로 바뀌는 것은 아니다.

부모 타입으로 참조하면 부모 타입에 없는 자식 고유 메서드는 바로 호출할 수 없다. 토끼의 `jump()`를 호출하려면 `Rabbit`으로 다운캐스팅한다.

```java
Animal rabbit = new Rabbit();

// rabbit.jump(); // Animal에는 jump()가 없으므로 컴파일 오류
if (rabbit instanceof Rabbit) {
    ((Rabbit) rabbit).jump();
}
```

다운캐스팅은 실제 객체가 해당 타입으로 다뤄질 수 있을 때만 가능하다. `Animal tiger = new Tiger()`를 `Rabbit`으로 변환하면 실제 객체와 맞지 않아 실행 중 ClassCastException이 발생한다. `instanceof`로 타입을 확인한 뒤 변환하면 이런 잘못된 호출을 피할 수 있다.

```java
for (Animal animal : animals) {
    if (animal instanceof Rabbit) {
        ((Rabbit) animal).jump();
    } else if (animal instanceof Tiger) {
        ((Tiger) animal).bite();
    }
}
```

수업 코드의 호랑이 분기에는 `((Tiger) tiger).bite()`가 들어 있었다. 배열의 현재 요소를 처리하려면 위 예시처럼 **검사한 변수 `animal`을 변환해야 한다.** 바깥의 `tiger`를 사용하면 배열에 있는 호랑이 대신 같은 객체를 반복해서 호출하게 된다.

### 추상 클래스와 공통 기능

추상 클래스는 `abstract class`로 선언하며, 직접 객체를 생성할 수 없다. 자식 클래스의 공통 기능을 정의하고, 자식마다 달라야 하는 동작은 추상 메서드로 남길 수 있다.

```java
public abstract class Player {
    public abstract void attack();

    public void levelUp() {
        System.out.println("레벨업");
    }
}
```

`attack()`은 몸체가 없는 추상 메서드다. `Player`를 상속한 구체 클래스는 이를 구현해야 한다. 자식도 추상 클래스로 선언한다면 구현을 다음 자식에게 맡길 수 있지만, 실제 객체로 만들 구체 클래스에는 구현이 필요하다.

`levelUp()`은 이미 몸체가 있는 일반 메서드이므로 자식이 공통 구현을 사용할 수 있다.

```java
public class Warrior extends Player {
    @Override
    public void attack() {
        System.out.println("전사가 검으로 베기 공격을 합니다.");
    }
}
```

수업의 `Wizard`는 같은 `attack()`을 마법 공격으로 구현했다. `new Player()`는 불가능하지만 `Player`를 참조 변수나 배열의 타입으로 사용하는 것은 가능하다.

```java
Player[] players = {new Warrior(), new Wizard()};

for (Player player : players) {
    player.attack();
    player.levelUp();
}
```

전사는 검 공격 후 레벨업, 마법사는 마법 공격 후 레벨업 메시지를 출력한다. **달라지는 공격은 자식이 구현하고, 공통 레벨업은 부모 구현을 사용한다.** 추상 클래스는 이런 공통 기능과 개별 동작을 함께 정의하는 기반이 된다.

### 인터페이스와 기능의 약속

인터페이스는 구현 클래스가 제공해야 할 기능의 규칙을 정의한다. 수업에서는 장치가 연결과 연결 해제 기능을 제공하도록 `IConnectable`을 선언했다.

```java
public interface IConnectable {
    public abstract void connect();
    void disconnect();
}
```

위 인터페이스의 추상 메서드에는 `public abstract`가 자동으로 적용되므로 `disconnect()`처럼 생략할 수 있다. 클래스는 `implements`로 인터페이스를 구현하고, 구체 클래스에서 추상 메서드의 동작을 작성한다. 구현 메서드는 public이어야 한다.

```java
public class Keyboard implements IConnectable {
    @Override
    public void connect() {
        System.out.println("키보드가 usb 포트에 연결되었습니다.");
    }

    @Override
    public void disconnect() {
        System.out.println("키보드가 연결해제되었습니다.");
    }
}
```

`Mouse`도 같은 인터페이스를 구현하면서 마우스에 맞는 연결·해제 메시지를 출력한다. 인터페이스는 직접 객체로 생성할 수 없지만 구현 객체를 참조하는 타입으로 사용할 수 있다.

```java
// Computer 클래스의 메서드
public void connectDevice(IConnectable device) {
    System.out.println("컴퓨터의 usb 포트에 장치를 연결합니다.");
    device.connect();
}
```

```java
Computer computer = new Computer();
computer.connectDevice(new Keyboard());
computer.connectDevice(new Mouse());
```

`Computer`는 전달된 장치가 제공하는 `connect()`를 호출한다. 키보드와 마우스 모두 `IConnectable`을 구현하므로 같은 매개변수로 받을 수 있으며, 실행 시 실제 장치의 메서드가 호출된다. `disconnectDevice(IConnectable device)`도 같은 방식으로 `disconnect()`를 호출한다.

**사용하는 쪽은 연결 기능의 약속을 기준으로 요청하고, 각 장치는 자신의 동작을 구현한다.**

| 비교 항목              | 추상 클래스                                             | 인터페이스                                                   |
| ---------------------- | ------------------------------------------------------- | ------------------------------------------------------------ |
| 핵심 역할              | 자식들의 공통 상태와 기능을 정의하는 부모 클래스        | 구현 객체가 제공해야 할 기능의 약속                          |
| 선언                   | `abstract class Player`                                 | `interface IConnectable`                                     |
| 사용하는 클래스의 선언 | `class Warrior extends Player`                          | `class Keyboard implements IConnectable`                     |
| 여러 타입 적용         | 클래스는 부모 클래스 하나만 상속 가능                   | 클래스는 여러 인터페이스를 동시에 구현 가능                  |
| 직접 객체 생성         | 불가능. `new Player()` 사용 불가                        | 불가능. `new IConnectable()` 사용 불가                       |
| 추상 메서드            | `public abstract void attack()`처럼 선언                | 수업의 `void disconnect()`에는 `public abstract`가 자동 적용 |
| 구현 책임              | 구체 자식 클래스가 남아 있는 추상 메서드를 구현         | 구체 구현 클래스가 남아 있는 인터페이스 추상 메서드를 구현   |
| 공통 구현의 수업 예시  | `levelUp()`의 몸체를 부모에 작성하고 자식이 재사용      | `IConnectable`은 몸체 없이 연결·해제 규칙만 정의             |
| 다형성                 | `Player` 타입으로 `Warrior`, `Wizard` 참조              | `IConnectable` 타입으로 `Keyboard`, `Mouse` 참조             |
| 선택 기준              | 공통 기능을 재사용하면서 일부 동작을 자식별로 구현할 때 | 서로 다른 클래스가 같은 기능을 제공하도록 약속할 때          |

캐릭터 예제는 공통 레벨업 기능을 물려주면서 공격 방식만 다르게 구현하므로 추상 클래스를 사용했다. 장치 예제는 키보드와 마우스가 연결·해제 기능을 제공하도록 규칙을 정하므로 인터페이스를 사용했다.

두 방식 모두 타입을 기준으로 여러 객체를 다룰 수 있다. 선택할 때는 **공통 구현을 상속할 기반이 필요한지, 함께 사용할 기능의 약속이 필요한지**를 먼저 생각한다.
