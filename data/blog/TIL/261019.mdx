### 람다와 함수형 인터페이스

람다는 **하나의 추상 메서드를 가진 함수형 인터페이스의 구현을 간결하게 표현하는 문법**이다. 수업에서는 계산 동작을 메서드의 인자로 전달했다.

```java
@FunctionalInterface
public interface Calculator {
    int operate(int a, int b);
}
```

`@FunctionalInterface`를 붙이면 함수형 인터페이스 조건을 컴파일러가 확인한다. 여기에 다른 추상 메서드를 추가하면 컴파일 오류가 발생한다.

```java
public static int calculate(int first, int second, Calculator calculator) {
    return calculator.operate(first, second);
}

// 호출하는 곳
Calculator lambdaAdd = (a, b) -> a + b;
System.out.println(calculate(10, 19, lambdaAdd));       // 29
System.out.println(calculate(10, 19, (a, b) -> a * b)); // 190
```

`calculate()`는 전달된 Calculator의 `operate()`를 호출한다. 계산 메서드는 그대로 두고, 호출자가 전달하는 동작을 바꿀 수 있다. 익명 클래스에서 작성했던 객체 생성·메서드 재정의 코드를 람다로 줄인 것이다.

기본 형태는 `(매개변수) -> { 실행할 코드 }`다. 대상 메서드로 타입을 추론할 수 있어 매개변수 타입을 생략하며, 반환할 식이 하나라면 중괄호와 return도 생략할 수 있다.

### 람다와 지역 변수

```java
int bonus = 5;
Calculator bonusCalculator = (a, b) -> a + b + bonus;
// bonus = 10; // 주석을 해제하면 컴파일 오류
System.out.println(calculate(10, 20, bonusCalculator)); // 35
```

람다에서 참조하는 바깥 **지역 변수는 final이거나 사실상 final이어야 한다.** 사실상 final은 final을 쓰지 않았더라도 초기화한 뒤 다시 대입하지 않는다는 뜻이다.

람다는 선언된 자리에서 바로 실행되지 않고 나중에 호출될 수도 있다. 자바는 이때 참조하는 지역 변수의 값이 바뀌지 않도록 제한한다. 위 코드에서 bonus에 다시 대입하면 람다에서 사용할 수 없다.

### 표준 함수형 인터페이스

`java.util.function`에는 자주 쓰는 입력·출력 형태가 정의되어 있다. 동작의 형태에 맞는 인터페이스를 선택하면 매번 새 인터페이스를 만들 필요가 없다.

| 인터페이스         | 입력   | 반환    | 호출 메서드 | 수업 예시              |
| ------------------ | ------ | ------- | ----------- | ---------------------- |
| `Consumer<T>`      | T 하나 | 없음    | `accept()`  | 결과 출력              |
| `Supplier<T>`      | 없음   | T       | `get()`     | 기본값 제공            |
| `Function<T, R>`   | T 하나 | R       | `apply()`   | 문자열 길이 계산       |
| `Predicate<T>`     | T 하나 | boolean | `test()`    | 유효한 문자열인지 검사 |
| `UnaryOperator<T>` | T 하나 | T       | `apply()`   | 문자열 정규화          |

```java
Predicate<String> hasText = value -> value != null && !value.trim().isEmpty();
UnaryOperator<String> normalize = value -> value.trim().toUpperCase();
Consumer<String> printer = value -> System.out.println("처리결과: " + value);
Function<String, Integer> length = value -> value.length();
Supplier<String> defaultValue = () -> "GUEST";

String input = "   java   ";
String result = hasText.test(input) ? normalize.apply(input) : defaultValue.get();
printer.accept(result);                    // 처리결과: JAVA
System.out.println(length.apply(result)); // 4
```

공백만 있는 문자열은 hasText의 결과가 false이므로 기본값 GUEST를 사용한다. 검사·변환·출력·기본값 제공을 각각 다른 동작으로 표현했다. `UnaryOperator<T>`는 Function 중에서도 입력과 반환 타입이 같은 경우다.

### 메서드 참조와 생성자 참조

람다가 기존 메서드 하나를 그대로 호출한다면 `::`로 줄여 표현할 수 있다. **대상 함수형 인터페이스의 입력·반환 형태와 호출할 메서드가 맞아야 한다.**

| 형태                        | 수업 코드             | 대응하는 람다                            |
| --------------------------- | --------------------- | ---------------------------------------- |
| 정적 메서드 참조            | `Integer::parseInt`   | `value -> Integer.parseInt(value)`       |
| 특정 객체의 메서드 참조     | `System.out::println` | `message -> System.out.println(message)` |
| 타입의 인스턴스 메서드 참조 | `String::equals`      | `(left, right) -> left.equals(right)`    |

```java
Function<String, Integer> parseInt = Integer::parseInt;
Consumer<String> printer = System.out::println;
BiPredicate<String, String> sameText = String::equals;

System.out.println(parseInt.apply("123"));           // 123
System.out.println(sameText.test("hello", "hello")); // true
System.out.println(sameText.test("hello", "world")); // false
```

`BiPredicate<T, U>`는 값 두 개를 받아 boolean을 반환한다. `String::equals`에서는 첫 번째 인자가 메서드를 호출하는 객체가 되고, 두 번째 인자가 equals의 인자로 들어간다.

생성자는 `클래스이름::new`로 참조한다. 수업의 Account에는 인자가 없는 생성자, 이름을 받는 생성자, 이름과 잔액을 받는 생성자가 있다.

```java
Supplier<Account> newAccount = Account::new;
Function<String, Account> newAccountWithName = Account::new;
BiFunction<String, Integer, Account> newAccountFull = Account::new;

Account first = newAccount.get();
Account second = newAccountWithName.apply("홍길동");
Account third = newAccountFull.apply("판다", 10000);
```

같은 Account::new라도 함수형 인터페이스가 요구하는 인자의 개수와 타입에 따라 호출할 생성자가 결정된다. `BiFunction<T, U, R>`는 값 두 개를 받아 R을 반환한다.

### Stream 파이프라인

Stream API는 여러 데이터를 **거르고, 변환하고, 결과로 모으는 처리 흐름**을 표현한다. 컬렉션의 `stream()`으로 시작해 중간 연산을 연결하고 최종 연산으로 결과를 얻는다.

```java
List<String> names = Arrays.asList(
        "홍길동", "유관순", "이순신", "신사임당", "장보고", "강감찬", "이성계");

names.stream()
        .filter(name -> name.length() == 3)
        .map(name -> "[" + name + "]")
        .forEach(System.out::println);
```

`filter()`는 조건에 맞는 요소를 남기고, `map()`은 남은 요소를 다른 값으로 변환한다. 이 예제는 이름이 세 글자인 사람만 골라 대괄호를 붙여 출력한다. 신사임당은 제외된다.

| 구분      | 수업에서 사용한 연산                                                      | 역할                         |
| --------- | ------------------------------------------------------------------------- | ---------------------------- |
| 중간 연산 | `filter`, `map`, `sorted`, `distinct`, `mapToInt`                         | 다음 처리를 위한 스트림 연결 |
| 최종 연산 | `forEach`, `collect`, `count`, `anyMatch`, `allMatch`, `findFirst`, `sum` | 출력하거나 결과 반환         |

중간 연산은 처리 과정을 구성하며, 실제 요소 처리는 최종 연산이 실행될 때 이루어진다.

```java
List<String> leeFamily = names.stream()
        .filter(name -> name.startsWith("이"))
        .sorted(Comparator.reverseOrder())
        .collect(Collectors.toList());
// [이순신, 이성계]
```

문자열의 역순으로 정렬한 결과를 새 List로 수집한다. 이 파이프라인의 필터링·정렬은 원본 names의 내용이나 순서를 변경하지 않는다.

### 최종 연산과 스트림의 재사용 제한

위 이름 목록에 대한 결과는 다음과 같다.

| 연산                                            | 확인하는 내용            | 결과  |
| ----------------------------------------------- | ------------------------ | ----- |
| `filter(name -> name.startsWith("이")).count()` | 이씨의 수                | `2L`  |
| `anyMatch(name -> name.equals("장보고"))`       | 장보고가 하나라도 있는지 | true  |
| `allMatch(name -> name.length() == 3)`          | 모두 세 글자인지         | false |

`count()`는 long을 반환한다. anyMatch는 하나라도 조건에 맞으면 true, allMatch는 모든 요소가 조건에 맞으면 true다. 수업 목록에는 네 글자인 신사임당이 있어 allMatch 결과는 false다.

`findFirst()`는 첫 번째 요소를 찾지만, 조건에 맞는 요소가 없을 수 있으므로 Optional로 반환한다.

```java
Optional<OnlineCourse> firstRecommendedCourse = courses.stream()
        .filter(c -> "Programming".equals(c.getCategory()))
        .filter(c -> c.getDuration() > 200)
        .findFirst();

firstRecommendedCourse.ifPresent(c -> System.out.println(c.getTitle()));
// Spring 완전 정복
```

`ifPresent()`는 값이 있을 때만 전달한 Consumer를 실행한다. 수업 목록에서는 조건을 만족하는 첫 강의가 Spring 완전 정복이다.

**최종 연산으로 소비한 스트림은 다시 사용할 수 없다.**

```java
Stream<String> stream = names.stream();
System.out.println(stream.count()); // 7
stream.forEach(System.out::println); // IllegalStateException 발생
```

이 코드는 수업에서 재사용 제한을 확인하는 예제다. count 이후 forEach에서 예외가 발생한다. 같은 원본을 다시 처리하려면 `names.stream()`으로 새 스트림을 만든다.

### 강의 목록의 정렬과 집계

수업의 OnlineCourse는 제목·카테고리·수강 시간·무료 여부를 가진 객체다. courses는 이 객체 일곱 개가 담긴 목록이다.

#### 무료 강의를 시간순으로 정렬

```java
courses.stream()
        .filter(OnlineCourse::isFree)
        .sorted((c1, c2) -> Integer.compare(c1.getDuration(), c2.getDuration()))
        .forEach(System.out::println);
```

무료 강의만 남긴 뒤 수강 시간을 오름차순으로 비교한다. 결과는 SQL 첫걸음 80분, 포토샵 마스터 90분, 일러스트레이터 시작하기 110분 순서다.

#### 무료 강의의 총 시간

```java
int totalDurationOfFree = courses.stream()
        .filter(OnlineCourse::isFree)
        .mapToInt(OnlineCourse::getDuration)
        .sum();
System.out.println(totalDurationOfFree); // 280
```

`mapToInt()`는 강의 객체에서 시간을 꺼내 IntStream으로 변환한다. 그 뒤 sum으로 `80 + 90 + 110 = 280`을 구한다. 수업에서는 개수를 구하는 count와 합계를 구하는 sum, 평균을 구하는 average의 역할도 구분했다.

#### 카테고리 중복 제거와 그룹화

```java
courses.stream()
        .map(OnlineCourse::getCategory)
        .distinct()
        .forEach(System.out::println);
// Programming, Design, Database 순서로 출력
```

map으로 카테고리 문자열을 꺼내고 distinct로 중복을 제거한다. 이 결과에는 카테고리 이름만 남는다.

```java
Map<String, List<OnlineCourse>> courseByCategory = courses.stream()
        .collect(Collectors.groupingBy(OnlineCourse::getCategory));

courseByCategory.forEach((category, courseList) -> {
    System.out.println("[" + category + "]");
    courseList.forEach(c -> System.out.println(" - " + c.getTitle()));
});
```

groupingBy는 카테고리를 키로, 해당 강의 목록을 값으로 모은다. Programming에는 세 강의, Design과 Database에는 각각 두 강의가 들어간다. **distinct는 중복 없는 값 목록을 만들고, groupingBy는 같은 기준을 가진 원본 요소들을 묶는다.** 반환된 Map의 카테고리 출력 순서는 보장하지 않는다.
