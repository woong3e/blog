## ☘️ 람다와 함수형 인터페이스

람다는 **추상 메서드가 하나인 함수형 인터페이스** 구현을 간결하게 표현한다. @FunctionalInterface로 조건을 검사하며 추상 메서드를 더하면 컴파일 오류다.

```java
calculate(10, 20, (a, b) -> a + b);
calculate(10, 20, (a, b) -> a * b);
```

calculate가 전달받은 Calculator.operate를 호출하므로 같은 흐름에 덧셈·곱셈을 바꿔 넣는다. 익명 클래스의 구현을 줄인 것으로, `(매개변수) -> { 코드 }`에서 타입 추론·단일 식의 중괄호/return 생략이 가능하다.

바깥 지역 변수 bonus는 **final 또는 사실상 final**이어야 한다. 초기화 후 재대입하면 람다에서 사용할 수 없다. 나중에 실행될 수도 있는 동작이 참조하는 지역값을 고정한다.

| 인터페이스             | 입력 → 반환 | 호출   |
| ---------------------- | ----------- | ------ |
| Consumer&lt;T&gt;      | T → 없음    | accept |
| Supplier&lt;T&gt;      | 없음 → T    | get    |
| Function&lt;T,R&gt;    | T → R       | apply  |
| Predicate&lt;T&gt;     | T → boolean | test   |
| UnaryOperator&lt;T&gt; | T → T       | apply  |

java.util.function을 쓰면 형태마다 직접 인터페이스를 만들 필요가 없다. 문자열 검사(Predicate) → trim·대문자 정규화(UnaryOperator) → 길이 계산(Function) → 출력(Consumer)로 나눴다. 공백뿐이면 Supplier의 GUEST를 사용한다. UnaryOperator는 입력·반환 타입이 같은 Function이다.

## ☘️ 메서드와 생성자 참조

기존 메서드를 그대로 부르는 람다는 대상 인터페이스의 입력·반환이 맞을 때 ::로 줄인다.

- `Integer::parseInt` ↔ value → Integer.parseInt(value): 정적 메서드
- `System.out::println` ↔ message → System.out.println(message): 특정 객체 메서드
- `String::equals` ↔ (left,right) → left.equals(right): 타입의 인스턴스 메서드. 첫 인자가 호출 객체
- BiPredicate&lt;T,U&gt;는 두 입력→boolean, BiFunction&lt;T,U,R&gt;는 두 입력→R
- `Account::new`: Supplier&lt;Account&gt;면 인자 없음, Function&lt;String,Account&gt;면 이름 하나, BiFunction&lt;String,Integer,Account&gt;면 이름·잔액 생성자 선택

같은 생성자 참조도 대상 함수형 인터페이스의 인자 개수·타입에 따라 생성자가 결정된다.

## ☘️ Stream과 강의 목록

**원본.stream() → 중간 연산 → 최종 연산**으로 데이터를 처리한다. 중간은 처리 흐름을 연결하고, 최종 연산 시 실제 처리한다. 필터·정렬로 원본 List 자체를 바꾸지 않는다.

- 중간: filter(조건 유지), map(값 변환), sorted(정렬), distinct(중복 제거), mapToInt(IntStream 변환)
- 최종: forEach(출력), collect(수집), count(long 개수), anyMatch(하나라도), allMatch(전부), findFirst(Optional), sum(합계). average는 평균
- 이름 3글자만 filter 후 대괄호로 map하면 신사임당 제외. 역순 정렬·collect로 새 List 생성
- 수업 이름 목록의 이씨 count는 2L, 장보고 anyMatch는 true, 모두 3글자 allMatch는 false
- findFirst는 없을 수 있어 Optional 반환. ifPresent는 있을 때만 Consumer 실행. 첫 조건 충족 강의는 Spring 완전 정복
- **최종 연산 뒤 스트림 재사용 불가**: count 후 forEach하면 예외. 원본에서 새 stream 생성

OnlineCourse는 제목·카테고리·수강 시간·무료 여부이며 7개 목록을 처리했다.

```java
List<OnlineCourse> free = courses.stream()
    .filter(OnlineCourse::isFree)
    .sorted(Comparator.comparingInt(OnlineCourse::getDuration))
    .collect(Collectors.toList());
int total = courses.stream().filter(OnlineCourse::isFree)
    .mapToInt(OnlineCourse::getDuration).sum();
```

무료 강의는 SQL 첫걸음 80분 → 포토샵 마스터 90분 → 일러스트레이터 시작하기 110분, 총 280분이다.

- `map(OnlineCourse::getCategory).distinct()`: 중복 없는 **카테고리 이름** 목록
- `collect(Collectors.groupingBy(OnlineCourse::getCategory))`: 카테고리→**원본 강의 목록** Map. Programming 3개, Design·Database 각 2개이며 키 순서 미보장
