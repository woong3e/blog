## ☘️ 값이 없을 때 안전하게 읽기

객체에서 프로퍼티를 읽으려면 먼저 읽을 대상이 있어야 한다. 대상 자체가 null이나 undefined인데 점으로 접근하면 오류가 난다. **옵셔널 체이닝** `?.`는 그 대상이 null 또는 undefined이면 조회를 멈추고 undefined를 반환한다.

수업에서는 obj를 null로 두고 `obj?.value`를 읽었다. 이 경우 value 조회를 시도하지 않으므로 오류 대신 undefined가 나온다. 빈 문자열은 null도 undefined도 아니므로 `str?.length`로 길이 0을 얻을 수 있다. 이전에 사용하던 `str && str.length`는 빈 문자열을 거짓처럼 취급해 빈 문자열 자체를 반환한다는 차이가 있다.

**null 병합** `??`는 왼쪽이 null 또는 undefined일 때만 오른쪽 기본값을 선택한다. `null ?? '기본 값'`은 기본 값을, `'' ?? '기본 값'`은 빈 문자열을 유지한다. `||`는 빈 문자열도 거짓처럼 취급하므로 기본값으로 바뀐다. 값이 없는 경우만 대체할지, 거짓처럼 취급되는 값까지 대체할지에 따라 구분한다.

## ☘️ 생성자 함수로 객체 만들기

이름과 나이가 다른 학생을 매번 객체 리터럴로 작성하면 같은 구조와 메서드를 반복하게 된다. 생성자 함수는 객체를 만드는 공통 절차를 한곳에 정의한다. `new Student(...)`로 만든 개별 객체를 인스턴스라고 한다.

`new`로 호출하면 빈 객체가 마련되고 그 객체가 함수 내부의 `this`로 연결된다. 생성자가 `this.name`, `this.age`에 전달값을 저장하면 새 객체의 초기 데이터가 된다. 일반적인 경우 생성자 실행이 끝난 뒤 그 객체를 돌려받는다. 이름이 같아 보여도 각각 new로 만든 객체는 서로 다른 객체다.

수업의 Dog는 `new.target`으로 new 호출인지 확인했다. 일반 함수로 호출하면 new.target이 undefined이므로 내부에서 new Dog로 다시 호출한다. 생성자처럼 작성한 함수를 new 없이 호출했을 때 this가 새 객체라고 가정해서는 안 된다.

## ☘️ 프로토타입과 메서드 공유

프로토타입은 객체에서 프로퍼티를 찾지 못했을 때 이어서 살펴보는 객체다. `Object.create(user)`로 만든 student는 user와 연결된다. student에 직접 있는 passion은 자신에게서 찾고, 자신에게 없는 activate는 user에서 찾는다. 이 연결이 여러 단계로 이어지는 것이 프로토타입 체인이다. 끝까지 없으면 undefined다.

`Object.hasOwn`은 객체 자신에게 직접 있는지 확인하고, `in`은 연결된 프로토타입까지 포함해 확인한다. student의 activate는 읽을 수 있어도 자기 소유는 아니므로 hasOwn은 false다. 자식 객체에 같은 키를 대입하면 자기 값이 부모 값을 가리며, 자기 값을 삭제하면 부모의 값이 다시 조회된다. 부모 값을 복사해 넣는 동작은 아니다.

**수업의 도서 총액 계산**

```js
function Book(title, price) {
  this.title = title
  this.price = price
}
Book.prototype.getTotal = function (quantity) {
  return this.price * quantity
}
const book1 = new Book('책1', 15000)
const book2 = new Book('책2', 20000)
```

각 책은 제목과 가격을 자기 데이터로 가진다. getTotal은 개별 객체를 만들 때마다 새로 넣지 않고 Book.prototype에 한 번 정의한다. new로 만든 책들은 이 프로토타입에 연결되므로 같은 계산 함수를 찾아 쓸 수 있다.

`book1.getTotal(2)`는 30000, book2의 두 권은 40000이다. 함수는 같아도 `this`는 점 앞에서 호출한 책이기 때문에 각 책의 가격을 읽는다. 첫 책 가격을 18000으로 바꾸면 첫 결과만 36000으로 바뀌고 두 번째는 40000을 유지한다. 수량이 0이면 둘 다 0이다.

`book1.getTotal === book2.getTotal`은 true다. 두 책이 같은 함수 객체를 찾는다는 뜻이다. `Object.hasOwn(book1, 'getTotal')`은 false이고 Book.prototype에 대해서는 true다. 생성자의 prototype이라는 프로퍼티와 개별 인스턴스의 내부 프로토타입 연결은 관련이 있지만 같은 종류의 프로퍼티로 혼동하지 않는다.

원본 user.login은 this.name을 출력하지만 user와 파생 객체에 name이 없어 undefined가 표시될 수 있다. 메서드를 공유하는 것과 그 메서드가 요구하는 데이터를 갖추는 것은 별도로 확인해야 한다.
