객체를 다룰 때는 값이 없는 경우와 여러 객체가 기능을 공유하는 경우를 함께 고려한다. 옵셔널 체이닝은 없는 값을 안전하게 읽는 문법이고, 생성자와 프로토타입은 같은 구조의 객체를 만들고 공통 동작을 찾는 방법이다.

## ☘️ 없는 값과 기본값

중첩 객체에 바로 접근하면 중간 값이 null이나 undefined일 때 오류가 난다. 옵셔널 체이닝 ?.은 그 위치에서 접근을 멈추고 undefined를 반환한다. 모든 잘못된 코드를 무시하는 문법은 아니며 선언하지 않은 변수 자체를 안전하게 만들어 주지는 않는다.

??는 왼쪽 값이 null이나 undefined일 때 오른쪽 기본값을 사용한다. ||는 0·빈 문자열·false도 거짓으로 판단해 기본값으로 바꿀 수 있다. 수량 0처럼 의미 있는 값을 유지해야 하면 ??가 적합하다. 아래 첫 출력에서 기본값으로 바뀌는 값과 그대로 남는 값을 비교한다.

## ☘️ 생성자 함수가 객체를 만드는 순서

생성자 함수는 new로 호출해 새 객체를 초기화한다. 새 객체가 만들어지고 함수 안의 this가 그 객체에 연결되며 이름·나이 같은 필드가 저장된다. 명시적으로 다른 객체를 반환하지 않는 일반적인 생성자 호출은 초기화한 객체를 결과로 돌려준다.

new.target은 new로 호출했는지 확인하는 데 쓸 수 있다. new 없이 호출하면 일반 함수 호출이므로 this와 반환 동작이 달라진다. 같은 함수를 호출했다고 항상 같은 종류의 객체가 생기는 것은 아니다.

## ☘️ 자기 프로퍼티와 공유 프로토타입

프로퍼티를 읽을 때 객체 자신에게 값이 없으면 연결된 프로토타입에서 찾는다. 그곳에도 없으면 더 위로 찾는 경로를 프로토타입 체인이라고 한다. 생성자 함수의 prototype과 그 함수로 만든 객체의 내부 프로토타입 연결을 구분한다.

메서드를 생성자 안에서 만들면 객체마다 별도 함수를 가질 수 있다. prototype에 넣으면 여러 객체가 같은 메서드를 찾는다. hasOwnProperty는 객체 자신이 가진 값인지 확인하고 in은 프로토타입에서 찾을 수 있는 값도 포함한다.

공유된 가격을 두 객체가 읽다가 한 객체에 직접 같은 이름의 가격을 넣으면 그 객체에서는 직접 가진 값이 우선한다. 원본 프로토타입의 가격을 바꾼 뒤에도 자기 값을 가진 객체와 공유 값을 읽는 객체의 결과는 달라진다. 참조의 연결과 값 검색 순서를 함께 봐야 한다.

## ☘️ 안전한 접근과 생성자·프로토타입의 연결

다음은 연결된 학습 코드의 핵심 동작을 한 파일에서 확인하도록 정리한 설명용 예제다. 원본 프로젝트 전체를 그대로 옮긴 것은 아니다. 필요한 선언과 실행 부분을 함께 두었으며, 아래 코드만 저장해 흐름을 따라갈 수 있다.

**js-prototype.js**

```js
const obj = null,
  str = ''
console.log(obj?.value, str?.length, null ?? '기본 값', '' ?? '기본 값')
function Student(name, age) {
  this.name = name
  this.age = age
}
Student.prototype.getInfo = function () {
  return `${this.name}: ${this.age}`
}
const student = new Student('판다', 8)
console.log(student.getInfo())
function Dog(name) {
  if (!new.target) return new Dog(name)
  this.name = name
}
console.log(Dog('바둑이').name)
const user = { id: 'user', activate: true }
const child = Object.create(user)
child.passion = true
console.log(child.activate, Object.hasOwn(child, 'activate'), 'activate' in child)
child.id = 'student01'
console.log(child.id, user.id)
delete child.id
console.log(child.id)
function Book(title, price) {
  this.title = title
  this.price = price
}
Book.prototype.getTotal = function (quantity) {
  return this.price * quantity
}
const book1 = new Book('책1', 15000),
  book2 = new Book('책2', 20000)
console.log(book1.getTotal(2), book2.getTotal(2))
console.log(book1.getTotal === book2.getTotal)
console.log(Object.hasOwn(book1, 'getTotal'), Object.hasOwn(Book.prototype, 'getTotal'))
book1.price = 18000
console.log(book1.getTotal(2), book2.getTotal(2), book1.getTotal(0))
```

옵셔널 체이닝은 중간 값이 null이나 undefined일 때 접근을 멈추고 undefined를 돌려준다. null 병합 연산자는 이 두 값일 때만 기본값을 고르므로 숫자 0이나 빈 문자열을 보존한다. 생성자 함수는 new로 만든 각 객체에 필드를 넣고, prototype의 메서드는 여러 객체가 함께 찾는다. 객체에 같은 이름의 프로퍼티를 추가하면 그 객체에서는 직접 가진 값이 먼저 선택된다. 부모 프로토타입을 연결하면 없는 메서드를 부모 쪽에서 찾을 수 있지만 생성자 실행과 프로토타입 연결은 서로 다른 작업이다.
