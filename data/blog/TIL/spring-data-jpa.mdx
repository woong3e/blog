`EntityManager`를 직접 호출하는 리포지토리 클래스는 엔티티마다 비슷한 코드가 반복된다. Spring Data JPA는 `JpaRepository`를 상속한 인터페이스만 선언하면 구현 클래스를 자동으로 만들어 저장·조회·수정·삭제를 제공한다. 이 글은 메뉴 REST API를 만들며 CRUD, 조건 조회와 페이징, 네이티브 쿼리를 차례로 확인한다. 세 챕터는 같은 프로젝트에 기능을 더해 간 구성이라, 아래 코드는 마지막 단계인 chap06의 최종본을 기준으로 단계별로 설명한다.

## ☘️ 프로젝트 구성

**계층과 설정**

요청은 컨트롤러(`MenuController`)가 받고, 서비스(`MenuService`)가 업무 로직과 트랜잭션을 맡으며, 리포지토리(`MenuRepository`)가 데이터베이스에 접근한다. 요청과 응답은 엔티티가 아니라 DTO(Data Transfer Object, 데이터 전달용 객체)로 주고받는다. 엔티티를 그대로 응답으로 내보내면 내부 구조와 연관 객체가 외부에 노출되고, 지연 로딩 객체를 JSON으로 바꾸다가 예외가 발생할 수 있다.

의존성은 JPA, 요청 검증(`validation`), 웹(`webmvc`)과 MySQL 드라이버다.

`application.yml`에서 중요한 설정은 두 가지다. `ddl-auto: none`은 이미 있는 `menudb`의 테이블을 건드리지 않고, `open-in-view: false`는 영속성 컨텍스트가 서비스의 트랜잭션이 끝날 때까지만 열려 있게 한다. Spring Boot는 이 값이 기본으로 `true`여서 웹 요청이 끝날 때까지 `EntityManager`를 열어 두는데, `false`로 하면 트랜잭션 밖(컨트롤러 등)에서 지연 로딩 객체에 접근할 수 없다. 그래서 이 예제의 서비스는 트랜잭션 안에서 엔티티를 DTO로 바꾸어 반환한다. 비밀번호는 환경에 맞게 `<DB 비밀번호>` 자리에 직접 채운다.

```java
package com.woong3e.springdatajpa.menu.entity;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.FetchType;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;

import jakarta.persistence.Table;

@Entity
@Table(name = "tbl_menu")
public class Menu {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "menu_code")

    @Column(name = "menu_name", nullable = false)

        this.menuName = menuName;
        this.menuPrice = menuPrice;
        this.category = category;
        this.orderableStatus = orderableStatus;
    }

    public void update(String menuName, int menuPrice, Category category, String orderableStatus) {
        this.menuName = menuName;
        this.menuPrice = menuPrice;
        this.category = category;
        this.orderableStatus = orderableStatus;
    }

    public int getMenuCode() {
        return menuCode;
    }

    public String getMenuName() {
        return menuName;
    }

    public int getMenuPrice() {
        return menuPrice;
    }

    public Category getCategory() {
        return category;
    }

    public String getOrderableStatus() {
        return orderableStatus;
    }
}
```

## ☘️ CRUD: JpaRepository

`JpaRepository<Menu, Integer>`의 두 타입 인자는 다루는 엔티티와 그 엔티티의 기본 키 타입이다. 인터페이스를 선언만 하면 Spring Data JPA가 실행 시점에 구현체를 만들어 스프링 빈으로 등록한다. 서비스는 다음 메서드를 사용한다.

| 메서드           | 동작                                                                   |
| ---------------- | ---------------------------------------------------------------------- |
| `save(entity)`   | 새 엔티티는 저장(`persist`)하고, 이미 있는 엔티티는 병합(`merge`)한다. |
| `findById(id)`   | 기본 키로 조회하고 결과를 `Optional`로 돌려준다.                       |
| `findAll()`      | 모든 행을 조회한다.                                                    |
| `delete(entity)` | 엔티티를 삭제한다.                                                     |

아래 `MenuRepository`는 chap06의 최종본이며 CRUD 메서드는 상속받으므로 따로 선언하지 않았다. 선언된 세 개의 쿼리 메서드와 두 개의 네이티브 쿼리는 뒤에서 하나씩 설명한다.

**`src/main/java/com/woong3e/springdatajpa/menu/repository/MenuRepository.java`**

```java
package com.woong3e.springdatajpa.menu.repository;

import com.woong3e.springdatajpa.menu.dto.CategoryMenuCountView;
import com.woong3e.springdatajpa.menu.dto.MenuPriceRankView;
import com.woong3e.springdatajpa.menu.entity.Menu;
import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.NativeQuery;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;

import java.util.List;

public interface MenuRepository extends JpaRepository<Menu, Integer> {

    List<Menu> findByMenuPriceGreaterThanEqualOrderByMenuPriceDesc(int minPrice);

    @Query("SELECT m FROM Menu m " +
            "WHERE m.menuName LIKE CONCAT('%', :keyword, '%') " +
            "ORDER BY m.menuCode")
    List<Menu> searchByMenuName(@Param("keyword") String keyword);

    @Query(
            value = "SELECT m FROM Menu m JOIN FETCH m.category",
            countQuery = "SELECT COUNT(m) FROM Menu m"
    )
    Page<Menu> findPageWithCategory(Pageable pageable);
/*=========================아래부터가 native query=====================*/
    @Query(value = """
SELECT  c.category_Code AS categoryCode,
        c.category_name AS categoryName,
        COUNT(m.menu_code) AS menuCount
FROM tbl_category c
LEFT JOIN tbl_menu m ON m.category_code = c.category_code
GROUP BY c.category_code,c.category_name
ORDER BY menuCount DESC,c.category_code
""",nativeQuery = true)
    List<CategoryMenuCountView> findCategoryMenuCounts();


    // 아예 @NativeQuery라는 어노테이션도 있다.
    @NativeQuery(value = """
        SELECT m.menu_code AS menuCode,
               m.menu_name AS menuName,
               m.menu_price AS menuPrice,
               RANK() OVER (ORDER BY m.menu_price DESC) AS priceRank
          FROM tbl_menu m
         ORDER BY priceRank, m.menu_code
        """)
    List<MenuPriceRankView> findMenuPriceRanks();

}
```

**서비스: 변경 감지로 수정하기**

서비스의 핵심 동작은 다음과 같다.

- **조회**: `findById(...).orElseThrow(...)`로 없는 값은 `ResourceNotFoundException`으로 바꾼다. 조회 메서드는 `@Transactional(readOnly = true)`로 읽기 전용 트랜잭션을 연다.
- **등록**: 요청의 `categoryCode`로 `Category`를 먼저 조회하고, 그 객체로 `Menu`를 만들어 `save`한다.
- **수정**: `findMenuEntity`로 영속 상태의 메뉴를 가져와 `menu.update(...)`만 호출한다. `save`를 호출하지 않아도 트랜잭션이 끝날 때 변경 감지가 `UPDATE`를 실행한다. 수정할 때는 영속 상태의 엔티티를 조회해서 값을 바꾸는 방식이 기본이다.
- **삭제**: 엔티티를 조회한 뒤 `delete`에 넘긴다.
- **DTO 변환**: `toResponse`는 메뉴와 카테고리 이름을 `MenuResponse`로 옮긴다. `menu.getCategory().getCategoryName()`은 지연 로딩 객체를 읽으므로 반드시 트랜잭션 안에서 실행되어야 한다.

**`src/main/java/com/woong3e/springdatajpa/menu/service/MenuService.java`**

```java
package com.woong3e.springdatajpa.menu.service;

import com.woong3e.springdatajpa.menu.dto.*;
import com.woong3e.springdatajpa.menu.entity.Category;
import com.woong3e.springdatajpa.menu.entity.Menu;
import com.woong3e.springdatajpa.menu.exception.ResourceNotFoundException;
import com.woong3e.springdatajpa.menu.repository.CategoryRepository;
import com.woong3e.springdatajpa.menu.repository.MenuRepository;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;

import java.util.List;

@Service
public class MenuService {

    private final MenuRepository menuRepository;
    private final CategoryRepository categoryRepository;

    public MenuService(MenuRepository menuRepository, CategoryRepository categoryRepository) {
        this.menuRepository = menuRepository;
        this.categoryRepository = categoryRepository;
    }

    @Transactional(readOnly = true)
    public MenuResponse findMenu(int menuCode) {
        return toResponse(findMenuEntity(menuCode));
    }

    @Transactional(readOnly = true)
    public List<MenuResponse> findMenus() {
        return menuRepository.findAll().stream()
                .map(this::toResponse)
                .toList();
    }

    @Transactional(readOnly = true)
    public List<MenuResponse> findMenusByMinimumPrice(int minPrice) {
        return menuRepository
                .findByMenuPriceGreaterThanEqualOrderByMenuPriceDesc(minPrice)
                .stream()
                .map(this::toResponse)
                .toList();
    }

    @Transactional(readOnly = true)
    public List<MenuResponse> searchMenusByName(String keyword) {
        return menuRepository.searchByMenuName(keyword).stream()
                .map(this::toResponse)
                .toList();
    }

    @Transactional(readOnly = true)
    public PageResponse<MenuResponse> findMenuPage(Pageable pageable) {
        Page<MenuResponse> responsePage = menuRepository
                .findPageWithCategory(pageable)
                .map(this::toResponse);

        return PageResponse.from(responsePage);
    }

    @Transactional
    public MenuResponse createMenu(MenuRequest request) {
        Category category = findCategory(request.getCategoryCode());
        Menu menu = new Menu(
                request.getMenuName(),
                request.getMenuPrice(),
                category,
                request.getOrderableStatus()
        );

        return toResponse(menuRepository.save(menu));
    }

    @Transactional
    public MenuResponse updateMenu(int menuCode, MenuRequest request) {
        Menu menu = findMenuEntity(menuCode);
        Category category = findCategory(request.getCategoryCode());

        menu.update(
                request.getMenuName(),
                request.getMenuPrice(),
                category,
                request.getOrderableStatus()
        );

        return toResponse(menu);
    }

    @Transactional
    public void deleteMenu(int menuCode) {
        Menu menu = findMenuEntity(menuCode);
        menuRepository.delete(menu);
    }

    private Menu findMenuEntity(int menuCode) {
        return menuRepository.findById(menuCode)
                .orElseThrow(() -> new ResourceNotFoundException("메뉴를 찾을 수 없습니다."));
    }

    private Category findCategory(int categoryCode) {
        return categoryRepository.findById(categoryCode)
                .orElseThrow(() -> new ResourceNotFoundException("카테고리를 찾을 수 없습니다."));
    }

    private MenuResponse toResponse(Menu menu) {
        Category category = menu.getCategory();
        return new MenuResponse(
                menu.getMenuCode(),
                menu.getMenuName(),
                menu.getMenuPrice(),
                category.getCategoryCode(),
                category.getCategoryName(),
                menu.getOrderableStatus()
        );
    }

    @Transactional(readOnly = true)
    public List<CategoryMenuCountView> findCategoryMenuCounts() {
        return menuRepository.findCategoryMenuCounts();
    }

    @Transactional(readOnly = true)
    public List<MenuPriceRankView> findMenuPriceRanks(){
        return menuRepository.findMenuPriceRanks();

    }
}
```

**요청·응답 DTO와 예외 처리**

`MenuRequest`는 `@NotBlank`, `@Positive`, `@Pattern`으로 입력값을 검사하고, 컨트롤러에서 `@Valid`를 붙이면 이 검사가 실행된다. `MenuResponse`는 읽기만 하는 값이므로 모든 필드를 `final`로 선언했다. 없는 메뉴나 카테고리는 `ResourceNotFoundException`을 던지고, `@RestControllerAdvice`의 핸들러가 이를 404 상태와 `{"message": ...}` 형태의 본문으로 바꾼다.

**컨트롤러와 HTTP 상태 코드**

컨트롤러는 요청 방식에 따라 메서드를 나누고 결과에 맞는 상태 코드를 돌려준다. 등록은 201 Created, 수정은 200 OK, 삭제는 본문이 없는 204 No Content다. 아래 컨트롤러에는 뒤에서 설명하는 조건 조회와 네이티브 쿼리용 엔드포인트도 함께 들어 있다.

## ☘️ 조건 조회: 쿼리 메서드, JPQL, 페이징

**쿼리 메서드**

메서드 이름을 정해진 규칙에 맞게 쓰면 Spring Data JPA가 이름을 해석해 쿼리를 만든다. `findByMenuPriceGreaterThanEqualOrderByMenuPriceDesc(int minPrice)`는 `findBy`(조회), `MenuPrice`(엔티티 필드), `GreaterThanEqual`(이상), `OrderByMenuPriceDesc`(가격 내림차순)으로 나뉘어 "가격이 `minPrice` 이상인 메뉴를 비싼 순으로 조회"한다. 조건이 단순할 때는 쿼리를 쓰지 않아도 된다. 이름이 길어지는 복잡한 조건에는 맞지 않는다.

**JPQL**

JPQL(Java Persistence Query Language)은 테이블과 컬럼이 아니라 엔티티와 필드를 대상으로 하는 JPA의 쿼리 언어다. `@Query`에 작성하고, 값은 `:keyword`처럼 이름 있는 파라미터로 받아 `@Param`으로 연결한다. 값을 문자열에 직접 이어 붙이지 않고 파라미터로 바인딩하므로 SQL 주입을 막는 데도 도움이 된다. 이 예제는 `LIKE CONCAT('%', :keyword, '%')`로 이름에 검색어가 포함된 메뉴를 찾는다.

**페이징과 fetch join**

`Pageable`은 몇 번째 페이지를 몇 건씩, 어떤 정렬로 가져올지를 담고, 리포지토리가 돌려주는 `Page`는 그 페이지의 내용과 전체 건수를 가진다. 요청에서는 `page`(0부터 시작), `size`, `sort` 파라미터로 전달한다. 컨트롤러의 `@PageableDefault(size = 5, sort = "menuCode")`는 파라미터가 없을 때의 기본값이다. `Page` 객체를 그대로 JSON으로 바꾸지 않고 `PageResponse`로 옮겨 응답 구조를 직접 정한다.

`findPageWithCategory`는 `JOIN FETCH m.category`를 사용한다. 메뉴의 카테고리는 `LAZY`여서 `toResponse`에서 카테고리 이름을 읽을 때마다 카테고리를 따로 조회한다. 한 페이지의 메뉴가 서로 다른 카테고리를 가리키면 그만큼 조회가 늘어난다(실행된 SQL의 수를 세어 확인하지는 않았고 지연 로딩의 일반적인 동작을 설명한 것이다). `JOIN FETCH`는 메뉴를 가져오는 쿼리에서 카테고리를 함께 가져와(조인) 이 추가 조회를 없앤다. 다만 fetch join이 들어간 쿼리를 그대로 전체 건수 계산에 쓸 수 없으므로 `countQuery`를 따로 지정했다. 학습 코드의 서비스에는 `findAll(pageable)`을 쓰던 이전 방식이 주석으로 남아 있었고, 최종본은 fetch join 방식이다.

**`src/main/java/com/woong3e/springdatajpa/menu/dto/PageResponse.java`**

```java
package com.woong3e.springdatajpa.menu.dto;

import org.springframework.data.domain.Page;

import java.util.List;

public class PageResponse<T> {

    private final List<T> content;
    private final int page;
    private final int size;
    private final long totalElements;
    private final int totalPages;

    private PageResponse(
            List<T> content, int page, int size,
            long totalElements, int totalPages
    ) {
        this.content = content;
        this.page = page;
        this.size = size;
        this.totalElements = totalElements;
        this.totalPages = totalPages;
    }

    public static <T> PageResponse<T> from(Page<T> page) {
        return new PageResponse<>(
                page.getContent(),
                page.getNumber(),
                page.getSize(),
                page.getTotalElements(),
                page.getTotalPages()
        );
    }

    public List<T> getContent() {
        return content;
    }

    public int getPage() {
        return page;
    }

    public int getSize() {
        return size;
    }

    public long getTotalElements() {
        return totalElements;
    }

    public int getTotalPages() {
        return totalPages;
    }
}
```

## ☘️ 네이티브 쿼리와 인터페이스 프로젝션

JPQL이나 쿼리 메서드로 표현하기 어려운 집계, 통계, 데이터베이스 전용 기능은 SQL을 그대로 쓰는 네이티브 쿼리로 작성한다. `@Query(nativeQuery = true)`로 쓰거나 전용 어노테이션 `@NativeQuery`를 쓸 수 있다. 이 예제의 두 쿼리는 다음과 같다.

- `findCategoryMenuCounts`: 카테고리별 메뉴 수를 구한다. 메뉴가 없는 카테고리도 보여야 하므로 `LEFT JOIN`으로 카테고리를 기준에 두고 `GROUP BY`로 센다.
- `findMenuPriceRanks`: 가격이 높은 순으로 순위를 매긴다. `RANK() OVER (ORDER BY m.menu_price DESC)`는 윈도우 함수여서 MySQL 8 이상에서 동작한다. `RANK`는 같은 가격에 같은 순위를 주고 다음 순위를 건너뛴다.

네이티브 쿼리는 특정 데이터베이스의 문법에 묶인다. 데이터베이스를 바꾸면 쿼리도 함께 확인해야 한다.

결과는 엔티티가 아니라 **인터페이스 프로젝션**으로 받는다. 읽을 값마다 getter 메서드를 선언한 인터페이스를 반환 타입으로 쓰면 Spring Data JPA가 쿼리 결과의 컬럼을 그 getter에 연결한다. 쿼리의 컬럼 별칭(`AS categoryCode`)이 getter 이름(`getCategoryCode`의 `categoryCode`)과 일치해야 한다. 컨트롤러가 이 인터페이스 객체를 반환하면 Jackson이 getter를 읽어 JSON으로 바꾼다. 흐름은 데이터베이스 결과, Spring Data JPA, 프로젝션 객체, Jackson, JSON 응답 순서다.

## ☘️ 헷갈리기 쉬운 지점

- 수정은 `save`가 아니라 영속 상태의 엔티티를 조회해 값을 바꾸는 방식으로 한다. 변경 감지가 `UPDATE`를 만든다.
- `Page`의 번호는 0부터 시작한다. 첫 페이지는 `page=0`이다.
- `open-in-view: false`이면 서비스의 트랜잭션 밖에서 지연 로딩 객체를 읽을 수 없다. 엔티티는 서비스 안에서 DTO로 바꾼다.
- JPQL은 테이블 이름이 아니라 엔티티 이름(`Menu`)과 필드 이름(`menuName`)을 쓴다.
- 네이티브 쿼리의 컬럼 별칭은 인터페이스 프로젝션의 getter 이름과 맞아야 한다.
- 컬렉션(`@OneToMany`)을 fetch join하면서 페이징하면 데이터베이스가 아니라 메모리에서 페이징하게 되므로 주의해야 한다. 이 예제의 fetch join은 단일 참조(`@ManyToOne`)여서 해당하지 않는다.
