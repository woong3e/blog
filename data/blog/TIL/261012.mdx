## ☘️ 초기화와 값 전달

- `this(...)`: 같은 클래스의 다른 생성자 호출로 초기화 중복 제거. 수업에서는 첫 문장에 작성. 세 문자열 생성자를 호출한 뒤 네 번째 가입일 필드를 설정
- `this.id`: 현재 객체의 필드이며 생성자 호출과 다름
- 오버로딩: 같은 이름, 매개변수 **개수·타입·타입 순서**가 다름. 반환 타입·접근제한자·매개변수 이름만 다른 것은 불가
- 메서드 시그니처: 이름과 매개변수 타입 나열. add(int,int)·add(double,double)처럼 인자에 맞는 메서드 선택. 생성자도 오버로딩 가능

**Java 인자 전달은 항상 값 복사다.** 정수는 값, 배열·객체는 참조값을 복사한다.

```java
void changeNumber(int n) { n = 99; }
void changeArray(int[] arr) { arr[0] = 99; }
// 호출자의 int 20은 유지, 배열 첫 값은 99로 변경
```

배열 자체가 복사된 것은 아니다. 매개변수 arr에 다른 배열을 재대입해도 호출자 변수가 가리키는 배열은 그대로다.

- final 인스턴스 필드: 객체마다 초기화 후 재대입 불가. 선언 시 값이 없다면 생성 완료 전 초기화
- static final: 클래스가 공유하는 상수. `MathConstant.PI`처럼 접근, 대문자·밑줄 명명
- final 참조는 내부 변경까지 막지 않음. final Member[]에 회원 저장은 가능하지만 새 배열 대입은 불가

## ☘️ 변수와 객체 공유

| 종류               | 소속과 초기화                                                          |
| ------------------ | ---------------------------------------------------------------------- |
| 지역 변수·매개변수 | 메서드·블록 범위. 지역 변수는 읽기 전 초기화, 매개변수는 인자로 초기화 |
| 인스턴스 변수      | 객체마다 존재. 별도 값 없으면 기본값                                   |
| static 변수        | 클래스가 공유. 접근 범위는 접근제한자로 결정                           |

Student의 개인 사물함을 +1 하고 공용 사물함도 +1 한 뒤 두 번째 학생을 만들면, 개인 값은 각각 1·0, 공용 값은 둘 다 1이다. static은 메모리 위치보다 **클래스 소속**이라는 의미로 이해한다. private static이 어디서나 보이는 것은 아니다.

싱글톤은 객체 하나를 공유하도록 생성·접근을 제어하는 패턴이다. private 생성자로 외부 new를 막고 static 필드와 getInstance()로 같은 참조를 반환한다. 두 반환값의 ==는 true다.

- 이른 초기화: 클래스 초기화 시 미리 생성
- 게으른 초기화: getInstance 호출 시 없으면 생성. 수업의 순차 실행에서는 최초 한 번 생성
- static은 멤버 소속, 싱글톤은 객체 생성·공유 설계

## ☘️ 배열과 계층 역할

`new Car[3]`은 자동차 3대가 아닌 **null 참조 3칸**이다. 각 칸에 new Car로 객체를 연결한 뒤 순회한다. 향상된 for도 참조값을 복사하며, 빈 칸에서 메서드 호출하면 NullPointerException이다.

가장 빠른 차는 첫 요소를 후보로 두고 인덱스 1부터 더 빠른 참조로 교체한다. 수업은 차arr3(300)이 결과이며, 객체 복사가 아니다. 빈 배열·null이 없는 전제의 예제다.

회원 관리는 Application(메뉴) → MemberService(기능) → MemberRepository(보관)로 나눴다. Member는 번호·아이디·비밀번호·이름·나이 데이터다.

- 등록은 사용자 입력이 아닌 미리 만든 세 회원 전달. Repository의 static 초기화 블록은 한 번 실행해 10칸 배열 생성
- count는 등록 수·다음 위치. members[count++]로 저장. 3→6→9 뒤 네 번째 등록은 용량 확인에서 실패. 중복 id 검사는 없음
- findAllMembers는 배열 **참조 그대로** 반환. 전체 조회는 null 검사 후 getInformation으로 아이디·이름·나이 출력
- 검색은 null 검사 후 id.equals(input) 비교. 찾으면 isFound=true·break, 끝까지 없으면 실패 안내
- nextInt 뒤 nextLine으로 개행을 소비해야 검색 입력이 정상 대기

Spring의 Controller(요청·응답) → Service(업무) → Repository(저장·조회)를 이해하는 기반이다. 현재는 Spring 없이 Service 직접 생성·Repository static 호출이며, Spring에서는 객체 관리·주입을 사용하고 Service의 콘솔 입출력도 요청·응답 계층으로 분리한다.
