## ☘️ 생성자 연결과 오버로딩

객체를 만들 때 일부 초기화가 다른 생성자와 같다면 같은 코드를 반복하지 않고 생성자를 연결할 수 있다. User의 전체 생성자는 `this(id, pwd, name)`으로 세 값을 받는 생성자를 먼저 호출한 뒤 enrollDate를 저장한다. `this(...)`는 같은 클래스의 다른 생성자 호출이고 필드 접근의 `this.name`과는 다르다. 수업 코드는 생성자의 첫 문장에서 호출한다.

**오버로딩**은 같은 이름의 메서드를 매개변수 구성에 따라 여러 개 정의하는 것이다. Calculator의 add는 정수 두 개, 실수 두 개, 정수 세 개를 각각 받는다. 호출한 인자의 개수와 타입에 맞는 메서드가 선택되므로 작업 의미가 같을 때 이름을 여러 개 만들지 않아도 된다.

메서드를 식별하는 시그니처는 이름과 매개변수의 타입·개수·순서다. 반환 타입만, 접근 제한자만, 매개변수 이름만 다르게 해서는 다른 메서드가 되지 않는다. 어느 메서드를 고를지 인수 목록으로 구별할 수 있어야 한다.

## ☘️ 값 전달과 변수의 범위

Java는 인수를 전달할 때 항상 **값을 복사**한다. 기본형은 그 숫자 등을 복사하므로 메서드 안에서 매개변수를 99로 바꿔도 호출부의 20은 유지된다. 배열은 객체를 가리키는 참조값을 복사하므로 두 변수가 같은 배열을 가리킨다. 메서드가 배열 첫 칸을 99로 바꾸면 호출부에서도 그 변경을 본다.

참조값을 복사하는 것과 호출부 변수 자체를 공유하는 것은 다르다. 원본 주석의 Pass by Reference라는 표현은 Java의 인자 전달 방식 설명으로는 정확하지 않다. 객체 내부를 바꾸는 일과 매개변수에 다른 객체를 다시 대입하는 일을 구분해야 한다.

**세 종류의 변수**

인스턴스 필드는 객체마다 따로 존재한다. static 필드는 클래스에 속하며 같은 클래스의 객체들이 공유한다. 메서드의 지역 변수와 매개변수는 해당 호출·블록 안에서만 사용할 수 있고 지역 변수는 초기화 전에 읽을 수 없다.

수업의 Student는 개인 사물함 수는 인스턴스 필드, 공용 사물함 수는 static 필드로 표현한다. 첫 학생이 개인·공용을 하나씩 늘려도 새 학생의 개인 수는 0이지만 공용 수는 이미 증가한 값을 본다. static을 특정 물리적 메모리 이름보다 클래스 소속과 공유 여부로 이해한다. 접근 제한자가 있으므로 static이라고 모든 코드에서 접근할 수 있는 것은 아니다.

final 인스턴스 필드는 객체 생성 시 값을 정한 뒤 재대입하지 않는다. Person의 ssn은 생성자에서 정하고 이름만 setter로 바꾼다. public static final인 PI는 클래스에 하나를 공유하며 값을 재대입하지 않는 상수다. final 참조는 참조값 재대입을 막으며 객체 내부 전체를 불변으로 만들지는 않는다.

## ☘️ 하나의 객체 공유와 객체 배열

싱글톤은 클래스의 객체를 하나 만들어 여러 곳에서 공유하도록 하는 설계다. 생성자를 private으로 잠가 외부 new를 막고 getInstance로 보관한 객체를 돌려준다. EagerSingleton은 클래스 초기화 때 미리 만들고, LazySingleton은 첫 요청에서 null인지 확인해 만든다. 두 번 요청한 결과를 `==`로 비교하면 같은 객체임을 확인한다. 원본의 단순 지연 초기화에는 동시 호출을 조정하는 처리가 없어 여러 스레드에서도 하나임을 보장하는 완성형으로 일반화하지 않는다.

Car 배열은 여러 자동차 참조를 모은다. new Car[3]은 참조 칸 세 개만 만들고 각 칸의 Car는 따로 만들어야 한다. 빈 칸은 null이라 메서드 호출 전에 확인해야 한다. 순회하면서 getMaxSpeed를 비교하고 현재 최고 자동차 참조를 갱신하면 가장 빠른 객체를 보관할 수 있다. 배열은 비어 있지 않다는 전제에서 첫 항목을 초기 기준으로 사용한다.

## ☘️ 회원 관리의 역할 분리

회원 예제는 Application이 메뉴·입력, MemberService가 등록·조회·검색 처리, MemberRepository가 보관을 맡는다. 데이터는 Member 객체로 묶는다. 입력·업무·보관을 나누면 기능 흐름을 역할별로 살펴볼 수 있으며 이후 계층 구조를 이해하는 기초가 된다.

Repository는 클래스 초기화 블록에서 열 칸 배열을 한 번 만든다. count는 저장된 수이고 새 회원 수를 더해 정원을 넘으면 저장 전에 false를 반환한다. 넘지 않으면 count 위치부터 차례로 보관한다. 배열 참조가 final이어도 배열 각 칸의 저장은 가능하다.

전체 조회는 빈 칸 null을 건너뛰고, 검색은 아이디 내용을 equals로 비교해 처음 찾은 회원을 출력한다. 없으면 안내한다. 메뉴의 nextInt 뒤에 nextLine을 호출해 남은 줄바꿈을 소비해야 검색 문자열 입력을 건너뛰지 않는다.

등록은 사용자별 입력이 아니라 고정 회원 세 명을 매번 추가한다. 중복 id 검사도 없고 전체 조회는 내부 배열을 그대로 반환하므로 외부에서 내부 데이터를 바꿀 가능성이 있다. 이 예제의 범위와 제한이다. 별도 StudentDTO는 평균을 정수 나눗셈으로 출력하며 실행 Application은 비어 있어, 학생 입력 프로그램까지 완성된 것은 아니다.
