## ☘️ 자료구조와 정렬

컬렉션 프레임워크는 여러 객체를 관리하는 인터페이스·구현체다. List·Set은 Collection 기반, Map은 별도다. **Collection은 인터페이스, Collections는 static 유틸리티**다.

- List: 순서·인덱스·중복 허용. add 추가, get 조회, set 수정, remove 삭제, size 개수. 인덱스는 0부터
- ArrayList: 배열 기반, 인덱스 접근에 적합 / LinkedList: 이중 연결, 양 끝 삽입·삭제에 적합. 중간 인덱스 탐색 비용은 필요
- raw List는 Object 캐스트가 필요하지만 List&lt;String&gt;은 저장 타입을 컴파일 때 검사
- HashSet: 순서 미보장, equals·hashCode로 중복 판단
- LinkedHashSet: 입력 순서 유지, equals·hashCode로 중복 판단
- TreeSet: 정렬 유지, **비교 결과 0이면 중복**

java·html·css·java는 세 값만 남는다. LinkedHashSet은 입력순, TreeSet은 css·html·java 순이다. Set은 향상된 for 또는 Iterator의 hasNext→next로 순회한다.

**정렬**: 문자열은 Collections.sort(list)로 오름차순, list.sort(Comparator.reverseOrder())로 내림차순이다. 원본 리스트 순서를 변경한다.

- Comparable.compareTo(other): 객체의 기본 기준. BookDTO의 책 번호 오름차순
- Comparator.compare(a,b): 외부의 다른 기준. AscendingPrice의 가격 오름차순
- 음수면 앞의 객체 우선, 양수면 뒤의 객체 우선, 0이면 그 기준에서 같음. 한 번의 비교가 바로 교환 명령인 것은 아님

TreeSet&lt;BookDTO&gt;는 Comparable 또는 생성자의 Comparator가 필요하다. 책 번호만 비교하면 제목·가격이 달라도 같은 2번은 중복이라 먼저 넣은 목민심서가 남고 1·2·4번 세 권이 된다.

로또도 TreeSet에 1~45 난수를 넣어 size가 6일 때 종료하면 중복 제거·오름차순을 함께 처리한다.

## ☘️ 꺼내기와 넣기

ArrayDeque를 스택(Deque)·큐(Queue)로 사용했다.

| 용도      | 넣기  | 조회만 | 꺼내기 | 1·2·3 입력 후 |
| --------- | ----- | ------ | ------ | ------------- |
| 스택 LIFO | push  | peek   | pop    | 3·2·1         |
| 큐 FIFO   | offer | peek   | poll   | 1·2·3         |

스택은 뒤로가기·실행 취소, 큐는 요청 대기열에 사용한다. 빈 상태에서 peek·poll은 null, pop은 예외다. 반복 추출은 isEmpty 검사 후 처리한다.

**와일드카드·PECS**

List&lt;Integer&gt;는 List&lt;Number&gt;의 자식이 아니다. 이를 허용하면 Double을 넣어 정수 리스트의 규칙을 깨뜨릴 수 있다.

| 타입                         | 허용 범위         | 읽기   | 쓰기                   |
| ---------------------------- | ----------------- | ------ | ---------------------- |
| List&lt;?&gt;                | 모든 요소 타입    | Object | 구체 값 안전 추가 불가 |
| List&lt;? extends Number&gt; | Number·하위 타입  | Number | 구체 값 안전 추가 불가 |
| List&lt;? super Integer&gt;  | Integer·상위 타입 | Object | Integer 추가 가능      |

null은 추가 제한의 예외다. extends는 리스트 자체의 불변을 뜻하지 않는다. `printList(List<?>)`는 출력만, `sum(List<? extends Number>)`는 Number로 읽어 합산(30.0·약 30.3), `addInteger(List<? super Integer>)`는 정수 추가에 쓴다. 실수 합에는 부동소수점 오차가 있을 수 있다.

**Producer Extends, Consumer Super**: 꺼내 쓰는 제공자는 extends, 값을 받는 소비자는 super다. super에서 꺼낸 값은 Integer로 바로 보장되지 않는다.

## ☘️ Map과 예외 흐름

Map은 키·값 Entry로 관리한다. HashMap은 순서를 보장하지 않는다. 키는 고유, 값은 중복 가능하다. 같은 키 two로 put하면 기존 jdbc가 html로 바뀌며 one·four의 값이 둘 다 java인 것은 가능하다. 없는 키 get은 null이다.

- keySet(): Set&lt;K&gt;. 키 순회, 필요하면 get
- values(): Collection&lt;V&gt;. 값만 순회하며 중복도 포함
- entrySet(): Set&lt;Map.Entry&lt;K,V&gt;&gt;. getKey·getValue로 함께 사용해 재조회 불필요

**throw와 throws**: throw는 실제 예외 발생, throws는 처리하지 않은 예외를 호출자에게 전달할 수 있다는 선언이다. throws 자체가 발생·해결하는 것은 아니다.

```java
void checkEnoughMoney(int price, int money) throws Exception {
    System.out.println("보유 금액: " + money);
    if (money < price) throw new Exception("돈이 부족해요.");
    System.out.println("구매 가능 / 즐거운 쇼핑");
}
```

가격 1만·보유 3만은 정상 출력 후 복귀, 다음 잔액 부족 호출은 금액 출력 → throw에서 중단해 쇼핑 인사를 건너뛴다. main도 throws로 넘기면 마지막 종료 안내는 실행되지 않고 예외 정보와 함께 종료된다. Exception은 검사 예외라 catch 또는 throws가 필요하며, 이 수업 단계에는 복구 처리가 없다.
