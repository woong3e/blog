## ☘️ List와 정렬 기준

컬렉션 프레임워크는 여러 객체를 저장하고 찾고 바꾸는 공통 인터페이스와 구현 클래스들이다. 배열은 길이가 정해져 있지만 컬렉션은 종류에 따라 데이터 개수와 접근 방식을 더 편리하게 관리한다. List·Set은 Collection 계열이며 Map은 키와 값을 다루는 별도 인터페이스다. Collections는 이들과 이름이 비슷하지만 정렬 같은 정적 도구를 제공하는 클래스다.

List는 순서와 인덱스가 있고 중복을 허용한다. add로 추가하고 get으로 위치를 조회하며 set은 수정, remove는 삭제, size는 개수다. 제네릭 없는 raw List는 꺼낸 값을 Object로 취급해 캐스트가 필요하다. List의 요소 타입을 String으로 지정하면 숫자 저장을 컴파일 때 막고 조회도 String으로 받는다.

ArrayList는 배열 기반이라 위치로 찾는 작업에 적합하다. LinkedList는 앞뒤 노드를 연결해 양 끝 삽입·삭제에 적합하지만 중간 인덱스까지 찾아가는 비용이 있다. 연결 구조라고 모든 위치의 삽입·삭제가 언제나 빠른 것은 아니다.

**객체를 어떤 순서로 놓을지**

문자열은 Collections.sort로 오름차순, reverseOrder 비교자를 전달해 내림차순 정렬했다. 이는 원본 리스트의 순서를 바꾼다. 사용자 정의 객체는 비교 기준을 제공해야 한다.

Comparable의 compareTo는 객체가 제공하는 기본 기준이다. 수업의 BookDTO는 책 번호를 비교한다. Comparator는 바깥에서 다른 기준을 제공하며 AscendingPrice는 가격을 비교한다. 비교 결과가 음수면 앞의 객체가 먼저, 양수면 뒤의 객체가 먼저, 0이면 그 기준에서 같다. 결과 자체가 즉시 두 요소를 교환하라는 명령은 아니다. Integer.compare를 사용해 비교값을 만든다.

## ☘️ Set, 스택과 큐

Set은 중복을 허용하지 않는다. HashSet은 순서를 보장하지 않고 equals·hashCode로 중복을 판단한다. LinkedHashSet은 같은 중복 규칙에 입력 순서를 보존한다. TreeSet은 비교 기준으로 정렬하며 비교 결과 0을 같은 항목으로 본다.

수업의 java·html·css·java는 세 항목만 남는다. LinkedHashSet은 입력순이고 TreeSet은 css·html·java 순이다. BookDTO의 TreeSet은 책 번호만 비교하므로 제목·가격이 달라도 같은 번호 2는 중복이다. 먼저 넣은 목민심서가 남고 번호 1·2·4의 세 권이 된다. equals의 모든 필드 비교와 TreeSet의 비교 결과 중복 판단은 구분한다.

Set은 향상된 for나 Iterator의 hasNext로 남은 항목을 확인한 뒤 next로 읽는다. 로또는 TreeSet에 1~45 난수를 넣어 size가 6이 될 때까지 반복하면 중복 제거와 정렬을 함께 처리한다.

**꺼내는 순서**

ArrayDeque는 양 끝을 사용할 수 있는 자료구조이며 수업은 이를 스택과 큐로 각각 사용했다. 스택은 나중에 넣은 것이 먼저 나오는 LIFO다. push로 넣고 peek로 확인하고 pop으로 제거하며, 1~5를 넣으면 5부터 나온다. 뒤로가기와 실행 취소 같은 흐름에 연결된다.

큐는 먼저 넣은 것이 먼저 나오는 FIFO다. offer로 뒤에 추가하고 peek로 맨 앞을 확인하며 poll로 앞을 제거한다. first·second·third는 같은 순서로 나온다. 빈 상태에서 peek·poll은 null이고 pop은 예외이므로 반복 추출 전 isEmpty를 확인한다.

## ☘️ 와일드카드와 PECS

Integer가 Number의 자식이어도 Integer 리스트를 Number 리스트로 그대로 대입할 수는 없다. 허용하면 그 통로로 Double을 넣어 정수 리스트의 규칙을 깨뜨릴 수 있기 때문이다. 와일드카드 `?`는 정확한 타입 하나 대신 허용 범위를 표현한다.

`List<?>`는 여러 타입의 리스트를 받을 수 있지만 요소를 Object로 읽으며 구체적인 값을 안전하게 추가할 수 없다. 수업의 printAnyList는 읽어 출력만 한다.

`List<? extends Number>`는 Number 또는 하위 타입의 리스트다. 무엇이든 Number로 읽을 수 있어 합계를 구할 수 있지만 실제로 Integer 리스트인지 Double 리스트인지 모르므로 구체 숫자를 추가할 수 없다. 수업 합계는 정수 30.0, 실수는 약 30.3이며 부동소수점 오차가 있을 수 있다.

`List<? super Integer>`는 Integer 또는 상위 타입의 리스트다. Integer를 받아들일 수 있으므로 100을 넣는 addInteger에 사용한다. 그러나 읽은 요소가 모두 Integer라고 보장되지는 않으므로 Object로 받는다. null은 추가 제한의 예외이며 extends가 리스트 자체의 변경 불가를 의미하지는 않는다.

PECS는 읽어서 값을 제공받는 쪽에는 extends, 값을 넣어 소비하게 하는 쪽에는 super를 고른다는 기억법이다. 읽기·쓰기 목적을 먼저 정하고 범위를 고른다.

## ☘️ Map과 예외의 흐름

Map은 키와 값의 쌍인 Entry를 보관한다. 키는 고유하지만 여러 키가 같은 값을 가질 수 있다. HashMap은 입력 순서를 보장하지 않는다. 수업은 키 two에 jdbc를 넣은 뒤 html을 넣어 기존 값을 교체했다. 없는 키를 get하면 null이다. containsKey·containsValue로 존재를 확인하고 remove로 키 항목을 지운다.

keySet은 키들의 Set을, values는 값들의 Collection을, entrySet은 키·값 쌍의 Set을 반환한다. 두 값이 모두 필요하면 Entry에서 getKey·getValue를 읽으면 키로 다시 조회하지 않아도 된다.

**throw와 throws**

예외는 실행 중 정상 흐름을 계속할 수 없는 상황을 알리는 수단이다. throw는 예외 객체를 실제로 던지고, throws는 메서드가 처리하지 않은 예외를 호출자에게 전달할 수 있음을 선언한다. 선언 자체가 문제를 발생시키거나 해결하지는 않는다.

수업의 구매 검사는 가진 돈을 출력한 뒤 부족하면 Exception을 던진다. 가격 10000·돈 30000은 구매 안내와 쇼핑 인사를 출력하지만, 다음 가격 50000에서는 throw 뒤 인사를 건너뛴다. main도 throws로 넘기고 처리하지 않아 마지막 종료 안내까지 도달하지 못한다. Exception은 검사 예외이므로 catch 또는 throws가 필요하며 이 날짜의 실습은 아직 복구 처리 전 단계다.
