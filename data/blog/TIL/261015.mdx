### List와 데이터 관리

컬렉션 프레임워크는 여러 객체를 효과적으로 관리할 수 있도록 제공되는 인터페이스와 구현 클래스의 묶음이다. 데이터를 어떤 기준으로 저장하고 조회할지에 따라 자료구조를 선택한다.

| 구분 | 관리 방식                | 중복과 순서                               | 수업의 구현 클래스              |
| ---- | ------------------------ | ----------------------------------------- | ------------------------------- |
| List | 인덱스로 요소 관리       | 중복 허용, 저장 순서 유지                 | ArrayList, LinkedList           |
| Set  | 중복 없는 요소 관리      | 중복 불가, 순서 특성은 구현체에 따라 다름 | HashSet, LinkedHashSet, TreeSet |
| Map  | 키와 값을 한 쌍으로 관리 | 키 중복 불가, 값 중복 허용                | HashMap                         |

List와 Set은 Collection 인터페이스를 기반으로 하고, Map은 별도의 인터페이스다. **Collection은 인터페이스이고, Collections는 정렬 등의 static 메서드를 제공하는 유틸리티 클래스**라는 점도 구분한다.

#### 제네릭과 기본 메서드

```java
List<String> stringList = new ArrayList<>();
stringList.add("apple");
stringList.add("banana");
stringList.add("orange");
stringList.add("mango");
stringList.add("mango");

String fruit = stringList.get(0); // apple
stringList.set(0, "watermelon");
stringList.remove("orange");
System.out.println(stringList.size()); // 4
System.out.println(stringList);
// [watermelon, banana, mango, mango]
```

List는 같은 값을 여러 번 저장할 수 있으며, 인덱스는 0부터 시작한다. `get()`은 조회, `set()`은 수정, `remove()`는 삭제, `size()`는 현재 요소 개수 확인에 사용한다.

제네릭 없이 `List`를 사용하면 서로 다른 타입을 넣을 수 있지만, 꺼낸 값은 Object로 취급되어 형변환이 필요하다. `List<String>`으로 선언하면 다른 타입을 넣는 실수를 컴파일 시점에 확인하고, 값을 String으로 바로 받을 수 있다.

#### ArrayList와 LinkedList

| 구현체     | 내부 구조                           | 특징                                                          |
| ---------- | ----------------------------------- | ------------------------------------------------------------- |
| ArrayList  | 배열 기반                           | 인덱스로 빠르게 접근하며 일반적인 목록 관리에 적합            |
| LinkedList | 앞뒤 노드를 연결한 이중 연결 리스트 | 양 끝 삽입·삭제에 적합하지만 인덱스 조회에는 노드 탐색이 필요 |

둘 다 List이므로 같은 `add()`·`get()` 등을 사용할 수 있다. 다만 **LinkedList라고 모든 삽입·삭제가 빠른 것은 아니다.** 인덱스로 중간 위치를 지정하면 그 위치까지 찾는 비용이 필요하다.

### Comparable과 Comparator로 정렬

문자열 목록은 `Collections.sort(stringList)`로 오름차순 정렬하고, `stringList.sort(Comparator.reverseOrder())`로 내림차순 정렬했다. 직접 만든 객체는 어떤 필드를 기준으로 비교할지 정해야 한다.

| 구분        | Comparable                      | Comparator                            |
| ----------- | ------------------------------- | ------------------------------------- |
| 역할        | 객체 자신의 기본 정렬 기준 정의 | 외부에서 별도의 정렬 기준 정의        |
| 구현 메서드 | `compareTo(T other)`            | `compare(T first, T second)`          |
| 수업 예제   | BookDTO의 책 번호 오름차순      | AscendingPrice의 가격 오름차순        |
| 사용        | `Collections.sort(bookList)`    | `bookList.sort(new AscendingPrice())` |

```java
// BookDTO 내부: implements Comparable<BookDTO>
@Override
public int compareTo(BookDTO other) {
    return Integer.compare(this.number, other.getNumber());
}
```

```java
public class AscendingPrice implements Comparator<BookDTO> {
    @Override
    public int compare(BookDTO first, BookDTO second) {
        return Integer.compare(first.getPrice(), second.getPrice());
    }
}
```

비교 결과가 음수면 앞의 객체가 먼저, 양수면 뒤의 객체가 먼저 오며, 0이면 **해당 정렬 기준에서 같은 값**이라는 의미다. 비교 한 번이 특정 자리 교환을 직접 지시하는 것으로 이해하지 않는다.

```java
List<BookDTO> bookList = new ArrayList<>();
bookList.add(new BookDTO(1, "홍길동전", "허균", 50_000));
bookList.add(new BookDTO(3, "동의보감", "허준", 32_000));
bookList.add(new BookDTO(2, "삼국사기", "김부식", 46_000));

Collections.sort(bookList);
// 책 번호: 1 → 2 → 3

bookList.sort(new AscendingPrice());
// 가격: 32,000 → 46,000 → 50,000
// 책 제목: 동의보감 → 삼국사기 → 홍길동전
```

기본 기준은 BookDTO에 두고, 상황에 따라 다른 기준을 Comparator로 전달할 수 있다. 두 정렬 호출은 원래 리스트의 순서를 변경한다.

### ArrayDeque로 스택과 큐 사용

스택은 **후입선출(LIFO)**, 큐는 **선입선출(FIFO)** 방식이다. 수업에서는 양 끝에서 요소를 넣고 뺄 수 있는 ArrayDeque를 각각 Deque와 Queue 타입으로 사용했다.

| 용도 | 넣기      | 제거 없이 조회 | 꺼내면서 제거 | 사용 예                              |
| ---- | --------- | -------------- | ------------- | ------------------------------------ |
| 스택 | `push()`  | `peek()`       | `pop()`       | 뒤로가기, 실행 취소                  |
| 큐   | `offer()` | `peek()`       | `poll()`      | 먼저 들어온 요청부터 처리하는 대기열 |

```java
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1);
stack.push(2);
stack.push(3);

System.out.println(stack.peek()); // 3, 제거하지 않음
System.out.println(stack.pop());  // 3, 제거함
System.out.println(stack.pop());  // 2
System.out.println(stack.pop());  // 1
// stack.pop(); // 비어 있으므로 예외 발생
```

수업의 1~5 입력을 1~3으로 줄인 예시다. 나중에 넣은 3부터 꺼내므로 스택으로 동작한다. 반복해서 꺼낼 때는 `while (!stack.isEmpty())`로 비어 있는지 확인했다.

```java
Queue<String> queue = new ArrayDeque<>();
queue.offer("first");
queue.offer("second");
queue.offer("third");

System.out.println(queue.peek()); // first, 제거하지 않음
System.out.println(queue.poll()); // first
System.out.println(queue.poll()); // second
System.out.println(queue.poll()); // third
System.out.println(queue.poll()); // null
```

`peek()`은 스택과 큐 모두 비어 있으면 null을 반환한다. 빈 상태에서 `pop()`은 예외를 발생시키고, `poll()`은 null을 반환한다는 차이를 기억한다.

### 제네릭 와일드카드와 PECS

Integer는 Number의 자식 타입이지만, **`List<Integer>`는 `List<Number>`의 하위 타입이 아니다.**

```java
List<Integer> integerList = new ArrayList<>();
// List<Number> numberList = integerList; // 컴파일 오류
```

이 대입이 가능하다면 numberList를 통해 Double을 넣어도 되어, 정수만 저장한다는 integerList의 규칙이 깨진다. 서로 다른 요소 타입의 리스트를 받아 처리하려면 와일드카드로 허용 범위를 정한다.

| 매개변수 타입            | 받을 수 있는 리스트                | 꺼낼 때 보장되는 타입 | 값을 넣을 때                             |
| ------------------------ | ---------------------------------- | --------------------- | ---------------------------------------- |
| `List<?>`                | 요소 타입에 관계없이 허용          | Object                | 구체 타입의 값을 안전하게 추가할 수 없음 |
| `List<? extends Number>` | Number 또는 그 자식 타입의 리스트  | Number                | 구체 타입의 값을 안전하게 추가할 수 없음 |
| `List<? super Integer>`  | Integer 또는 그 부모 타입의 리스트 | Object                | Integer 값을 추가할 수 있음              |

위 추가 제한은 null을 제외한 값에 대한 설명이다. extends를 쓴다고 리스트 전체가 불변이 되는 것은 아니다. 실제 요소 타입을 모르기 때문에 임의의 값을 추가할 수 없는 것이다.

#### 타입에 관계없이 출력

```java
private static void printAnyList(List<?> list) {
    for (Object value : list) {
        System.out.println(value);
    }
}
```

요소의 고유 기능이 필요 없고 출력만 하면 되므로 Object로 받아 처리한다. 정수 리스트와 실수 리스트 모두 전달할 수 있다.

#### 숫자를 꺼내 합계 계산

```java
private static double sum(List<? extends Number> list) {
    double total = 0;
    for (Number number : list) {
        total += number.doubleValue();
    }
    return total;
}
```

`List<Integer>`와 `List<Double>` 모두 Number의 기능으로 읽을 수 있다. 수업에서는 정수 10·20의 합계로 30.0을, 실수 10.2·20.1의 합계로 약 30.3을 얻었다. 실수 연산 결과의 출력에는 부동소수점 오차가 나타날 수 있다.

#### 정수를 리스트에 추가

```java
private static void addInteger(List<? super Integer> list) {
    list.add(100);
}

// 호출하는 곳
List<Number> numberList = new ArrayList<>();
addInteger(numberList);
System.out.println(numberList); // [100]
```

Integer·Number·Object를 요소 타입으로 갖는 리스트는 모두 Integer 값을 받을 수 있다. 반대로 꺼낼 때는 어떤 부모 타입의 리스트인지 알 수 없으므로 Integer로 바로 받을 수 없다.

**PECS는 Producer Extends, Consumer Super**다. 메서드가 리스트에서 값을 꺼내 사용한다면 리스트가 값을 제공하므로 extends, 메서드가 값을 넣는다면 리스트가 값을 받으므로 super를 기준으로 생각한다. 수업의 `sum()`은 extends, `addInteger()`는 super에 해당한다.

### Set의 중복 제거와 순회

Set은 중복 요소를 저장하지 않는다. 인덱스로 조회하는 List와 달리, 순서와 중복 판단 방식은 구현체의 특징을 확인해야 한다.

| 구현체        | 순서 특성             | 중복 판단              |
| ------------- | --------------------- | ---------------------- |
| HashSet       | 저장 순서 보장 없음   | hashCode와 equals 활용 |
| LinkedHashSet | 입력 순서 유지        | hashCode와 equals 활용 |
| TreeSet       | 비교 기준에 따라 정렬 | 비교 결과가 0이면 중복 |

수업처럼 `"java"`, `"html"`, `"css"`, `"java"`를 넣으면 세 구현체 모두 java를 한 번만 저장한다. LinkedHashSet은 `[java, html, css]`, TreeSet은 `[css, html, java]` 순서이며, HashSet의 출력 순서는 보장되지 않는다.

#### Iterator로 순회

```java
Iterator<String> iter = hset.iterator();
while (iter.hasNext()) {
    System.out.println(iter.next());
}
```

`hasNext()`로 다음 요소가 있는지 확인하고, `next()`로 다음 요소를 얻는다. 수업에서는 향상된 for문으로 순회하는 방식도 함께 사용했다.

#### TreeSet의 정렬과 중복 기준

TreeSet에 넣을 객체는 Comparable로 기본 비교 기준을 제공하거나, TreeSet 생성 시 Comparator를 전달해야 한다.

```java
TreeSet<BookDTO> bookSet = new TreeSet<>();
bookSet.add(new BookDTO(2, "목민심서", "정약용", 30_000));
bookSet.add(new BookDTO(1, "홍길동전", "허균", 50_000));
bookSet.add(new BookDTO(4, "동의보감", "허준", 40_000));
bookSet.add(new BookDTO(2, "제목없음", "저자없음", 18_000));
```

BookDTO의 `compareTo()`는 책 번호만 비교한다. 따라서 마지막 책은 제목과 가격이 달라도 기존 2번 책과 비교 결과가 0이므로 추가되지 않는다. 결과는 책 번호 1·2·4 순서의 세 권이며, 2번 책은 먼저 넣은 목민심서가 남는다.

**TreeSet에서는 정렬 기준이 중복 판단 기준이기도 하다.** 모든 필드가 같은지를 비교하는 것과 구분한다.

```java
Set<Integer> lotto = new TreeSet<>();
while (lotto.size() < 6) {
    lotto.add((int) (Math.random() * 45) + 1);
}
System.out.println(lotto);
```

1~45 범위의 난수를 넣되, 중복 값은 추가되지 않아 요소 수가 늘어나지 않는다. 서로 다른 번호가 여섯 개 모일 때까지 반복하고, TreeSet이므로 결과는 오름차순으로 출력된다.

### Map의 키와 값 관리

Map은 키와 값을 하나의 Entry로 묶어 관리한다. **키는 중복될 수 없고 값은 중복될 수 있다.** 수업의 HashMap은 저장 순서를 보장하지 않는다.

```java
Map<String, String> hmap = new HashMap<>();
hmap.put("one", "java");
hmap.put("two", "jdbc");
hmap.put("three", "mysql");
hmap.put("two", "html");
hmap.put("four", "java");

System.out.println(hmap.get("two"));          // html
System.out.println(hmap.get("five"));         // null
System.out.println(hmap.containsKey("four")); // true
System.out.println(hmap.containsValue("java")); // true
hmap.remove("four");
```

같은 키 two로 다시 `put()`하면 새 항목을 추가하는 대신 기존 jdbc를 html로 바꾼다. 반면 one과 four가 모두 java를 값으로 가지는 것은 가능하다. 수업 예제에서 없는 키를 `get()`하면 null을 반환한다.

#### 필요한 정보에 따른 순회

| 메서드       | 반환 타입              | 사용하는 상황                          |
| ------------ | ---------------------- | -------------------------------------- |
| `keySet()`   | `Set<K>`               | 키를 순회하며 필요하면 get으로 값 조회 |
| `values()`   | `Collection<V>`        | 값만 필요할 때. 중복 값도 포함         |
| `entrySet()` | `Set<Map.Entry<K, V>>` | 키와 값을 함께 사용할 때               |

```java
for (String key : hmap.keySet()) {
    System.out.println(key + " = " + hmap.get(key));
}

for (String value : hmap.values()) {
    System.out.println(value);
}

for (Map.Entry<String, String> entry : hmap.entrySet()) {
    System.out.println(entry.getKey() + " = " + entry.getValue());
}
```

키와 값이 모두 필요하면 entrySet으로 Entry를 받아 사용하는 방식이 직접적이다. keySet처럼 키로 값을 다시 조회할 필요가 없다.

### throw와 throws의 실행 흐름

예외 처리는 실행 중 발생한 문제에 대해 안내·기록·복구 등의 대응을 정하는 것이다. 이번 수업에서는 잔액 부족 상황에 예외를 발생시키고, 호출한 쪽으로 전달하는 단계까지 실습했다.

| 구분   | 역할                                                                   | 수업 코드                               |
| ------ | ---------------------------------------------------------------------- | --------------------------------------- |
| throw  | 현재 위치에서 예외 객체를 직접 던짐                                    | `throw new Exception("돈이 부족해요.")` |
| throws | 처리하지 않은 예외를 호출한 곳으로 전달할 수 있음을 메서드 선언에 표시 | `throws Exception`                      |

```java
public void checkEnoughMoney(int price, int money) throws Exception {
    System.out.println("가지고 계신 돈은 " + money + "원 입니다.");
    if (money >= price) {
        System.out.println("상품을 구입하기 위한 돈이 충분합니다.");
    } else {
        throw new Exception("돈이 부족해요.");
    }
    System.out.println("즐거운 쇼핑하세요.");
}
```

throws 자체가 예외를 발생시키거나 해결하는 것은 아니다. 실제 발생 지점은 else 안의 throw이며, **예외가 던져지면 해당 메서드의 정상적인 다음 문장으로 진행하지 않는다.**

```java
public static void main(String[] args) throws Exception {
    ExceptionTest exceptionTest = new ExceptionTest();
    exceptionTest.checkEnoughMoney(10_000, 30_000);
    exceptionTest.checkEnoughMoney(50_000, 30_000);
    System.out.println("프로그램을 종료합니다.");
}
```

실행 흐름은 다음과 같다.

1. 첫 호출은 가격 10,000원보다 보유 금액 30,000원이 많으므로 금액·구매 가능·쇼핑 인사 메시지를 출력하고 main으로 돌아온다.
2. 두 번째 호출은 보유 금액을 출력한 뒤 잔액 부족으로 예외를 던진다. 이 호출에서는 쇼핑 인사를 출력하지 않는다.
3. main도 예외를 처리하지 않고 throws로 전달하므로, 마지막 `"프로그램을 종료합니다."`는 출력되지 않는다. 처리되지 않은 예외 정보가 출력되고 main의 실행이 끝난다.

`new Exception(...)`으로 발생시킨 예외는 검사 예외이므로, 메서드 안에서 처리하거나 throws로 선언해야 한다. 이번 코드의 throws는 호출자에게 대응을 넘기는 선언이며, 프로그램이 정상적으로 계속 실행되게 하는 복구 처리는 아직 포함되어 있지 않다.
