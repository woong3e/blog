## ☘️ 객체 비교와 문자열 가공

Object는 Java 클래스의 공통 부모다. toString은 객체를 문자열로 표현하고 equals는 동등성을 판단한다. 기본 객체 비교의 동일성과 업무상 같은 데이터라는 동등성은 다를 수 있다. 수업의 Book은 번호·제목·저자·가격을 기준으로 equals와 hashCode를 재정의하고 toString으로 내용을 확인한다.

서로 다른 Book 객체라도 필드가 같으면 equals는 true일 수 있지만 `==`는 같은 객체를 가리키는지를 비교한다. equals가 같은 두 객체는 hashCode도 같아야 해시 기반 컬렉션에서 일관되게 다룰 수 있다. 같은 해시값이라는 이유만으로 모든 객체가 같은 것은 아니다.

**String 가공**

수업은 상품 문자열의 앞뒤 공백을 trim으로 제거하고 대문자로 바꾼 뒤, indexOf로 대괄호 위치를 찾고 substring으로 상품 코드를 꺼냈다. indexOf는 없으면 -1을 반환하고 substring의 끝 위치는 포함하지 않는다. replace는 특정 내용을 바꾼 새 문자열을 만든다.

split은 구분자로 나눈 문자열 배열을 반환한다. 직원 문자열의 연속 구분자 사이 빈 항목은 isEmpty로 확인해 정보 없음으로 표시했다. split의 구분자는 정규식이므로 파일명의 점을 문자 그대로 나누려면 수업처럼 역슬래시로 이스케이프해야 한다. 문자열 자체의 역슬래시도 이스케이프하므로 두 단계 표기를 구분한다. 줄바꿈·탭·따옴표 같은 특별한 문자 역시 이스케이프 표기를 사용한다.

String은 불변이다. 같은 리터럴은 문자열 풀에서 재사용할 수 있지만 new String은 별도 객체다. 내용을 비교하려면 equals를 쓰며 null일 수 있는 변수에서 바로 호출하면 오류가 난다. 수업은 고정 문자열 쪽에서 equals를 호출해 null에도 false를 얻었다. str2에 문자열을 더해 재대입하면 새 문자열을 가리키고 str1이 가리키던 기존 내용은 바뀌지 않는다.

## ☘️ StringBuilder와 Wrapper

StringBuilder는 내부 내용을 바꿀 수 있어 여러 번 문자열을 조립하는 데 쓴다. append는 뒤에 추가하고 자신을 반환하므로 호출을 이어 붙일 수 있다. delete는 시작부터 끝 직전까지 제거하고 insert는 지정 위치에 삽입하며 reverse는 순서를 뒤집는다. 마지막에 toString으로 String을 얻는다.

수업은 숫자 0~9999를 String의 +=와 StringBuilder의 append로 각각 연결하고 nanoTime 차이를 비교했다. 결과 길이가 같아도 구성 방식이 다르며 실제 실행 시간은 환경과 실행 조건에 따라 달라진다. 출력 수치 하나를 고정 성능 차이로 외우지 않는다.

Wrapper는 int를 Integer, double을 Double처럼 객체 형태로 다루는 클래스다. 문자열 키·몸무게를 그냥 더하면 글자 연결이므로 Double.parseDouble로 변환한 뒤 BMI를 계산한다. parse 메서드는 문자열을 기본형 값으로 바꾸며, 반대로 String.valueOf는 숫자를 문자열로 만든다.

기본형을 Wrapper로 감싸는 것이 박싱, 다시 기본형으로 꺼내는 것이 언박싱이다. 자동 변환도 지원한다. Wrapper 변수에는 null이 가능하며 null을 언박싱하면 NullPointerException이다. 원본의 “Wrapper는 null 불가” 주석은 반대다. Wrapper 값 비교는 equals를 사용하되 호출 변수의 null 가능성을 확인한다. `==`는 참조 비교여서 내부 객체 재사용에 영향을 받을 수 있다.

## ☘️ 날짜와 시간의 계산·표시

LocalDate는 날짜, LocalTime은 시간, LocalDateTime은 둘을 함께 담는다. 이 타입들은 시간대가 없고, 시간대가 필요하면 수업에서 소개한 ZonedDateTime·ZoneId를 별도로 고려한다. 열차 출발 날짜와 시간을 따로 만든 뒤 LocalDateTime으로 합쳤다.

java.time 객체는 불변이므로 minusMinutes(20)은 원본을 바꾸지 않고 계산된 새 값을 돌려준다. 반환값을 받아 도착 마감 시각으로 사용한다. getYear·getMonth·getMonthValue·getDayOfWeek로 일부 정보를 읽으며 getMonth는 월 이름, getMonthValue는 숫자 월이다.

isBefore·isAfter·isEqual로 앞뒤와 같은 시각인지 비교한다. 같은 날짜여도 시·분·초·나노초가 다르면 같지 않다. format은 날짜를 문자열로, parse는 문자열을 날짜로 바꾼다. DateTimeFormatter의 MM은 월, mm은 분이며 HH는 24시간, hh는 12시간이다. 원본의 13시 출발에 hh를 사용하면 01시로 표시되므로 표시 목적에 맞는 패턴을 골라야 한다. 문자열 20261225는 yyyyMMdd 패턴으로 LocalDate로 읽었다.

## ☘️ 제네릭으로 저장 타입 제한하기

NormalBox는 Object를 보관해 여러 타입을 넣지만 꺼낼 때 캐스트가 필요하다. 숫자를 넣고 String으로 캐스트하면 컴파일이 되더라도 실행 시 ClassCastException이다. 제네릭은 사용할 때 타입을 정해 이런 잘못된 저장을 컴파일 단계에서 막는다.

```java
GenericBox<String> stringBox = new GenericBox<>();
stringBox.setContent("하이");
String strContent = stringBox.getContent();
```

수업의 GenericBox는 content와 메서드 타입을 T로 선언한다. String으로 사용하면 저장·반환 모두 String이 되어 꺼낼 때 별도 캐스트가 필요 없다. T는 관례적 이름이며 E는 요소, K·V는 키·값을 나타내는 데 자주 쓴다. 생성자의 다이아몬드는 앞의 타입으로 추론한다. 타입 인자는 참조형이므로 int 대신 Integer다.

RabbitFarm의 `T extends Rabbit`은 Rabbit과 그 하위 타입만 허용한다. Bunny·DrunkenBunny는 가능하지만 Snake는 같은 Animal 계열이어도 Rabbit의 하위가 아니라 불가능하다. 수업에서 Animal은 인터페이스, Mammal은 이를 구현한 클래스다. 타입 인자는 보관·반환 타입을 정하고, 반환 객체의 cry는 실제 객체의 오버라이딩 구현으로 실행된다.
