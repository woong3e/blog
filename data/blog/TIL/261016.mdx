## ☘️ 예외 처리

try는 실패 가능 작업, catch는 해당 예외 대응, finally는 정상·예외 여부와 관계없는 마무리다. getMessage는 메시지, printStackTrace는 예외·호출 경로를 출력한다.

구매 검사에서 throw가 발생하면 메서드의 다음 문장은 건너뛰고 catch로 이동한다. 처리 후 finally와 try-catch 다음의 종료 안내로 이어진다.

- PriceNegativeException·MoneyNegativeException·NotEnoughMoneyException을 Exception 상속으로 정의하고 생성자에서 super(message) 호출
- 검사 순서는 가격 음수 → 보유금 음수 → 잔액 부족. 동시에 음수여도 먼저 검사한 가격 예외 발생
- catch는 **자식 타입 먼저, 부모 Exception 나중**. 거꾸로면 뒤 catch에 도달할 수 없어 컴파일 오류. 한 예외가 모든 catch를 거치는 것은 아님
- NegativeException도 Exception을 직접 상속하며 이름이 비슷한 다른 음수 예외의 부모가 아님

**검사 예외**는 컴파일러가 catch/throws를 확인한다(Exception 직접 상속 예외·IOException). 컴파일 때 발생한다는 뜻이 아니다. **비검사 예외**는 처리 선언을 강제하지 않지만 catch 가능하다(빈 deque의 pop에서 NoSuchElementException).

오버라이딩은 부모보다 넓은 **검사 예외**를 선언할 수 없다. 부모 throws IOException이면 자식은 생략·같은 IOException·하위 FileNotFoundException 가능, 상위 Exception 불가다. 부모 타입 호출자의 대응 약속을 유지하기 위해서다.

## ☘️ 파일과 입출력

File은 경로·정보를 다루며 **new File만으로 실제 파일은 생기지 않는다.** createNewFile은 생성 시 true·기존 파일이면 false(IOException 처리 필요), delete는 성공 여부를 반환한다. 상대 경로는 실행 작업 폴더 기준이다.

- 바이트: FileInputStream·FileOutputStream. 바이너리 포함 바이트 처리
- 문자: FileReader·FileWriter. 문자·문자열·문자 배열 처리
- read(): int 반환, 끝이면 -1. 바이트 입력은 0~255이며 한글의 각 바이트를 char로 바꾸면 깨질 수 있음
- 출력 기본은 덮어쓰기, 두 번째 인자 true는 이어쓰기. 반복 실행하면 내용 누적
- 스트림은 자원이므로 닫기 필요. finally의 null 확인+close 또는 **try-with-resources 자동 반납** 사용

```java
try (BufferedWriter writer = new BufferedWriter(
        new OutputStreamWriter(new FileOutputStream("note.txt"), StandardCharsets.UTF_8))) {
    writer.write("안녕하세요");
    writer.newLine();
}
```

InputStreamReader는 바이트→문자 입력, OutputStreamWriter는 문자→바이트 출력이다. 인코딩은 문자·바이트의 대응 규칙이며 **저장과 읽기의 문자셋을 맞춘다.** FileReader/Writer의 기본 문자셋에 의존하기보다 수업처럼 UTF-8 명시가 분명하다.

BufferedReader/Writer는 Reader/Writer를 감싸 데이터를 모아 실제 입출력 횟수를 줄인다. flush는 하위 스트림에 내보내기, close는 자원 종료이며 BufferedWriter는 닫힐 때 남은 내용을 내보낸다.

- readLine(): 줄바꿈 제외 한 줄, 끝은 null(read의 -1과 구분)
- 키보드: `new BufferedReader(new InputStreamReader(System.in))`으로 바이트 입력을 문자·줄 단위로 연결

## ☘️ 설정과 enum

**Properties**는 문자열 키·값 설정을 관리한다. setProperty → store(writer, 주석) → 새 Properties에 load(reader) → getProperty 순서로 저장·조회했다. application.properties는 app.name=fullstack-course 같은 형식이며 주석·저장 시각을 포함한다. 이름·버전·언어를 읽고 쓸 때 모두 UTF-8을 사용했다.

**enum**은 사용할 상수를 타입으로 묶는다. int 과목 상수는 숫자 중복·임의 100도 전달 가능하지만 Subjects 매개변수는 정해진 열거형 값만 받게 한다. int 예제의 100은 컴파일되지만 빈 과목명이 나온다.

- Subjects.JAVA와 HTML은 다른 상수, ==로 비교 가능
- values(): 선언 순서의 상수 배열 / name(): 상수명 / ordinal(): 0부터 선언 위치
- JAVA~CSS 순회에 ordinal+1로 1~5 출력. 순서 바꾸면 ordinal도 달라짐
- 필드·생성자·메서드를 둘 수 있음. UserRole의 ADMIN("관리자")는 생성자로 description 저장
- 외부 new UserRole은 불가. **처음 ADMIN을 참조할 때 GUEST→CONSUMER→PRODUCER→ADMIN 전체가 순서대로 초기화**되어 생성자 메시지 4회
- 이후 GUEST는 기존 상수라 생성자 재실행 없음. 특정 상수를 참조할 때마다 새 객체를 만든다는 뜻이 아님
