## 학습 내용

오늘은 배열의 값을 읽는 방법과 수정하는 방법을 비교하고, 값을 교환해 정렬하거나 중복 없는 난수를 저장하는 실습을 했다. 이어서 데이터를 클래스로 묶고 객체를 생성한 뒤, 접근 범위와 메서드로 상태를 관리하고 생성자로 초기값을 설정하는 방법을 학습했다.

### 향상된 for문과 배열 요소 수정

향상된 for문은 인덱스를 직접 관리하지 않고 배열의 요소를 하나씩 꺼내는 반복문이다. 값을 차례로 읽을 때 간단하게 사용할 수 있다.

```java
int[] arr = {1, 2, 3, 4, 5};

for (int value : arr) {
    value += 10;
    System.out.println(value); // 차례로 11, 12, 13, 14, 15
}
System.out.println(Arrays.toString(arr)); // [1, 2, 3, 4, 5]
```

위 예시는 `java.util.Arrays`를 import한 상태다. `int` 요소의 값이 반복 변수 `value`에 복사되므로, `value`에 다시 대입해도 배열의 요소는 바뀌지 않는다. 배열 자체가 복사되는 것은 아니다.

원본 배열의 값을 바꾸려면 인덱스로 해당 요소에 직접 대입한다.

```java
for (int i = 0; i < arr.length; i++) {
    arr[i] += 10;
}
System.out.println(Arrays.toString(arr)); // [11, 12, 13, 14, 15]
```

수업의 `int[]` 예시에서는 **값을 읽을 때는 향상된 for문, 각 요소를 수정할 때는 인덱스를 사용하는 for문**으로 구분할 수 있다.

### 값 교환과 배열 정렬

두 값을 교환하려면 먼저 한 값을 임시 변수에 보관한다. `num1 = num2`부터 실행하면 원래 `num1` 값이 사라지므로, 나중에 `num2`에 넣을 값을 보존해야 한다.

```java
int num1 = 10;
int num2 = 20;

int temp = num1;
num1 = num2;
num2 = temp;

System.out.println(num1); // 20
System.out.println(num2); // 10
```

배열에서도 같은 방식으로 두 요소를 교환한다. 정렬은 값을 비교하고 필요한 위치로 옮기는 과정을 반복한다.

| 방법            | 비교와 이동 방식                                           | 한 회차가 끝난 뒤                              |
| --------------- | ---------------------------------------------------------- | ---------------------------------------------- |
| 선택 정렬       | 미정렬 범위의 최소값 위치를 찾고, 그 범위의 첫 요소와 교환 | 앞쪽부터 가장 작은 값의 위치가 확정된다.       |
| 버블 정렬       | 인접한 두 요소를 비교하고, 왼쪽 값이 더 크면 교환          | 미정렬 범위의 가장 큰 값이 오른쪽 끝에 놓인다. |
| `Arrays.sort()` | Java가 제공하는 정렬 기능을 호출                           | `int[]`의 요소가 숫자 오름차순으로 정렬된다.   |

#### 선택 정렬

`i`는 이번에 최소값을 놓을 위치이고, `minIndex`는 지금까지 찾은 최소값의 위치다. 안쪽 반복문으로 남은 범위를 모두 검사한 뒤 한 번 교환한다.

```java
int[] arr = {2, 5, 4, 6, 1, 3};

for (int i = 0; i < arr.length - 1; i++) {
    int minIndex = i;
    for (int j = i + 1; j < arr.length; j++) {
        if (arr[minIndex] > arr[j]) {
            minIndex = j;
        }
    }
    int temp = arr[minIndex];
    arr[minIndex] = arr[i];
    arr[i] = temp;
}
```

첫 회차에는 최소값 1을 찾아 맨 앞에 놓는다. 다음 회차부터는 이미 확정된 앞부분을 제외하고 검사한다. 마지막 한 요소는 앞의 위치가 모두 정해지면 함께 확정되므로 바깥 반복문은 `arr.length - 1`번 실행한다.

#### 버블 정렬

버블 정렬은 바로 옆의 두 값을 비교한다. 큰 값이 오른쪽으로 계속 이동하면서 회차마다 미정렬 범위의 마지막 위치가 확정된다.

```java
int[] arr = {2, 7, 3, 6, 1, 4};

for (int i = arr.length - 1; i > 0; i--) {
    for (int j = 0; j < i; j++) {
        if (arr[j] > arr[j + 1]) {
            int temp = arr[j];
            arr[j] = arr[j + 1];
            arr[j + 1] = temp;
        }
    }
}
```

첫 회차가 끝나면 7이 맨 뒤에 놓인다. 이후에는 확정된 뒷부분을 제외하도록 `i`를 줄인다. `j + 1`도 접근하므로 안쪽 반복 조건은 `j < i`다.

직접 정렬 과정을 작성하지 않고 결과가 필요할 때는 `Arrays.sort()`를 사용했다. 이 메서드는 전달한 배열 자체를 정렬한다.

```java
import java.util.Arrays;

int[] arr = {2, 7, 3, 5, 1, 9};
Arrays.sort(arr);
System.out.println(Arrays.toString(arr)); // [1, 2, 3, 5, 7, 9]
```

### 중복 없는 로또 번호 생성

로또 실습은 난수 생성, 배열 저장, 중복 검사, 정렬을 함께 사용했다. 핵심은 **중복되지 않은 값이 저장될 때만 다음 위치로 이동하는 것**이다.

```java
import java.util.Arrays;

int[] lotto = new int[6];
int index = 0;

while (index < lotto.length) {
    int random = (int) (Math.random() * 45) + 1;
    boolean isDuplicate = false;

    for (int i = 0; i < index; i++) {
        if (lotto[i] == random) {
            isDuplicate = true;
            break;
        }
    }

    if (!isDuplicate) {
        lotto[index] = random;
        index++;
    }
}

Arrays.sort(lotto);
System.out.println(Arrays.toString(lotto));
```

`Math.random()`의 결과에 45를 곱하고 정수로 변환하면 0부터 44까지가 되므로, 1을 더해 1부터 45까지의 난수를 만든다. 난수는 반복문 안에서 매번 새로 생성해야 한다.

`index`는 지금까지 저장한 개수이자 다음 저장 위치다. 따라서 `i < index`로 이미 저장한 값만 검사한다. 중복이면 저장도 `index++`도 실행하지 않고 다시 난수를 만든다. 중복이 아니면 저장한 뒤 다음 위치로 이동한다. 여섯 개를 모두 저장한 후 오름차순으로 정렬하며, 출력값은 실행마다 달라질 수 있다.

### 클래스와 객체와 DTO

회원의 이름과 나이를 개별 변수로 관리하면 회원이 늘어날수록 어떤 값이 누구의 정보인지 함께 관리하기 어려워진다. 클래스는 관련 데이터와 기능을 하나의 자료형으로 정의한다.

| 개념               | 실습에서의 의미                                         |
| ------------------ | ------------------------------------------------------- |
| 클래스             | 회원이 가질 데이터와 기능을 정의한 `Member`             |
| 필드               | 클래스 내부에 선언한 `name`, `age`, `hobby` 등의 데이터 |
| 객체 또는 인스턴스 | `new Member()`로 실제 생성한 회원 객체                  |
| 참조 변수          | 생성한 객체를 가리키는 참조값을 저장한 `member`         |

```java
public class Member {
    String name;
    int age;
    String[] hobby;
}
```

아래는 위 클래스와 같은 패키지의 실행 코드다. 수업 예시에서 필드를 일부만 골랐다.

```java
Member member = new Member();
member.name = "박지성";
member.age = 5;
member.hobby = new String[]{"축구", "풋살", "영화"};
```

`Member member;`는 참조 변수의 선언이고, `new Member()`는 객체 생성이다. 참조값을 저장한 뒤 `.`을 사용해 객체의 필드나 메서드에 접근한다.

#### DTO의 역할

DTO는 **Data Transfer Object**로, 여러 데이터를 하나로 묶어 전달하기 위한 객체다. 수업의 `MemberDTO`는 회원 번호, 이름, 나이, 성별, 키, 활성화 여부를 필드로 가지고 getter와 setter를 제공했다.

```java
MemberDTO member = new MemberDTO();
member.setNumber(1);
member.setName("지성");
member.setAge(40);
member.setActivated(true);

System.out.println(member.getAge());   // 40
System.out.println(member.getName());  // 지성
System.out.println(member.isActivated()); // true
```

이 DTO 예시에서는 데이터를 담고 꺼내는 데 초점을 맞췄다. boolean 필드의 getter는 `isActivated()`라는 이름으로 작성되어 있다.

### 캡슐화와 getter setter

필드에 직접 접근할 수 있으면 외부 코드가 `member.age = -5`처럼 잘못된 값을 넣을 수도 있다. 캡슐화는 내부 상태를 감추고, 객체가 제공하는 메서드를 통해 상태를 읽거나 변경하게 하는 방식이다.

수업에서는 접근제한자로 필드와 메서드의 접근 범위를 조절했다.

| 접근제한자  | 접근 범위                                                                     |
| ----------- | ----------------------------------------------------------------------------- |
| `public`    | 모든 패키지에서 접근 가능                                                     |
| `protected` | 같은 패키지에서 접근 가능하며, 다른 패키지에서는 상속 관계에 따른 접근을 허용 |
| 생략한 경우 | 같은 패키지에서 접근 가능하며, default 접근이라고 부른다.                     |
| `private`   | 해당 클래스 내부에서 접근 가능                                                |

다른 클래스 안에 선언하지 않은 최상위 클래스에는 `public` 또는 접근제한자 생략만 사용할 수 있다.

`Children`은 `age`를 private으로 감추고 setter에서 값을 검사했다. 아래는 나이 관련 코드만 추린 예시다.

```java
public class Children {
    private int age;

    public void setAge(int age) {
        if (age >= 0) {
            this.age = age;
        } else {
            System.out.println("나이는 음수일 수 없습니다.");
            this.age = 0;
        }
    }

    public int getAge() {
        return this.age;
    }
}
```

getter는 필드의 값을 반환하고, setter는 전달받은 값으로 필드를 설정하거나 변경한다. `this`는 현재 객체를 가리킨다. `this.age = age`에서 왼쪽은 객체의 필드이고 오른쪽은 매개변수다.

```java
Children child1 = new Children();
child1.setAge(-10); // 나이는 음수일 수 없습니다.
System.out.println(child1.getAge()); // 0
```

이 예시의 setter는 음수를 받으면 경고를 출력하고 나이를 0으로 설정한다. **필드를 private으로 감추고, 변경 메서드에 규칙을 넣어 잘못된 상태를 막는다.** getter와 setter가 있다는 것만으로 값이 검증되는 것은 아니다. 실제로 수업의 `MemberDTO.setAge()`는 전달된 값을 그대로 저장한다.

### 추상화와 객체의 역할 분담

추상화는 프로그램에 필요한 특징과 기능을 골라 객체로 표현하고, 사용하는 쪽에는 의미 있는 기능을 보여주는 설계 방식이다. 자동차 내부 처리를 모두 알아야 운전할 수 있는 대신, 시동·가속·제동 같은 기능으로 사용할 수 있게 만든다.

자동차 실습에서는 역할을 다음과 같이 나눴다.

| 객체           | 담당하는 역할                                                  |
| -------------- | -------------------------------------------------------------- |
| `Car`          | 시동 상태와 속도를 관리하고, 현재 상태에 따라 동작 여부를 판단 |
| `CarRacer`     | 자신이 가진 자동차에 시동·가속·제동·시동 종료를 요청           |
| `Application1` | 입력받은 메뉴에 따라 운전자 객체의 메서드를 호출               |

```java
public class CarRacer {
    private final Car myCar = new Car();

    public void startUp() {
        myCar.startUp();
    }

    public void stepAccelerator() {
        myCar.go();
    }
}
```

위 코드는 운전자 클래스의 일부다. `CarRacer`가 `Car`를 필드로 가지는 구조는 자동차를 소유하는 **has-a 관계**다. 가속 흐름은 `Application1`에서 `racer.stepAccelerator()`를 호출하고, 운전자 내부에서 `myCar.go()`를 호출하는 순서다.

`Car.go()`는 시동이 켜져 있으면 속도를 10씩 올리고, 꺼져 있으면 먼저 시동을 걸라는 메시지를 출력한다. `stop()`은 시동이 켜진 상태에서 양수인 속도를 0으로 바꾸며, `turnOff()`는 주행 중이면 먼저 멈추라는 메시지를 출력하고 시동을 유지한다.

사용하는 쪽은 속도 필드를 직접 바꾸지 않고 원하는 동작을 요청한다. 자동차 객체가 상태에 맞는 처리를 책임진다. 캡슐화가 내부 상태와 접근을 관리하는 데 초점을 둔다면, 추상화는 필요한 역할과 기능을 어떤 형태로 보여줄지에 초점을 둔다.

### 생성자와 객체 초기화

생성자는 `new`로 객체를 만들 때 호출되어 객체의 초기 상태를 설정한다. 나중에 setter로 값을 넣을 수도 있지만, 매개변수 있는 생성자를 사용하면 생성 시점에 여러 초기값을 함께 전달할 수 있다.

생성자 이름은 **클래스 이름과 같아야 하며, 반환 타입을 쓰지 않는다.** `void`를 붙이면 생성자가 아니라 메서드가 된다.

```java
public class User {
    private String id;
    private String pwd;
    private String name;

    public User() {
        System.out.println("User 클래스의 기본생성자 호출됨.");
    }

    public User(String id, String pwd, String name) {
        this.id = id;
        this.pwd = pwd;
        this.name = name;
    }
}
```

수업의 `User`에서 생성자와 세 필드만 추린 예시다. 매개변수 구성이 다른 생성자를 여러 개 선언하면, 전달한 인자에 맞는 생성자가 호출된다.

| 생성 방식                                | 초기 상태                                                            |
| ---------------------------------------- | -------------------------------------------------------------------- |
| `new User()`                             | 인자 없는 생성자 호출. 수업 코드에서는 필드에 별도 값을 넣지 않는다. |
| `new User("user02", "pass02", "박지성")` | 전달받은 값으로 `id`, `pwd`, `name`을 초기화한다.                    |

필드에 별도 초기값을 지정하지 않으면 참조형은 null, `int`는 0, boolean은 false 등의 기본값을 가진다. 수업의 `User`는 기본 생성자로 만들면 `id`, `pwd`, `name`, `enrollDate`가 모두 null이다. 세 문자열을 받는 생성자를 사용해도 `enrollDate`는 초기화하지 않았으므로 null로 남는다.

컴파일러가 인자 없는 기본 생성자를 자동으로 추가하는 조건도 구분해야 한다.

- 클래스에 **생성자를 하나도 선언하지 않았으면** 기본 생성자가 자동으로 추가된다.
- 생성자를 하나라도 선언했으면 기본 생성자는 자동으로 추가되지 않는다.
- 매개변수 있는 생성자를 선언한 뒤에도 `new User()`를 사용하려면 인자 없는 생성자를 직접 작성해야 한다.

수업의 `User`는 두 생성자를 직접 선언했으므로 두 방식으로 객체를 생성할 수 있다.
