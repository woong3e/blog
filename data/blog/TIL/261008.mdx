## ☘️ 배열 수정과 정렬

향상된 for는 배열에서 값을 하나씩 꺼내 반복 변수에 받는다. int 배열의 값은 복사되므로 반복 변수에 10을 더해도 배열 칸 자체는 바뀌지 않는다. 실제 배열을 수정하려면 인덱스로 해당 칸에 대입한다. 값을 읽는 순회와 저장 위치를 바꾸는 순회를 구분한다.

두 값을 교환할 때는 한 값을 temp에 보관한 뒤 다른 값을 덮어쓰고, 보관한 값을 반대편에 넣는다. 첫 대입에서 원래 값을 잃지 않도록 임시 저장이 필요한 것이다.

선택 정렬은 아직 정렬하지 않은 구간의 최소값 위치를 찾고 그 구간 맨 앞과 바꾼다. 한 회차마다 앞쪽 값 하나가 확정된다. 최소 위치를 찾는 안쪽 반복과 실제 교환을 구분한다. 버블 정렬은 이웃한 두 값을 비교해 큰 값을 오른쪽으로 보낸다. 한 회차마다 뒤쪽 최대값이 확정되어 다음에는 비교 범위를 줄인다. j+1이 배열 끝을 넘지 않는지도 확인한다. Arrays.sort는 int 배열 자체를 오름차순으로 정렬한다.

**중복 없는 로또**

수업은 여섯 칸 배열을 만들고 1~45 난수를 새로 생성해 이미 저장한 구간만 검사했다. 중복이면 저장하지 않고 다시 뽑으며, 중복이 아닐 때만 현재 index에 넣고 index를 증가시킨다. index는 저장 개수이면서 다음 저장 위치다. 빈 칸까지 비교할 필요가 없다. 여섯 개가 모이면 sort로 정렬한다. 난수를 반복 밖에서 한 번만 만들면 같은 숫자가 반복된다는 점도 주석의 이전 시도에서 확인할 수 있다.

## ☘️ 클래스, 객체와 데이터 보호

클래스는 어떤 데이터와 기능을 가질지 정의한다. 필드는 클래스 안에서 관리하는 데이터이고 객체는 new로 그 정의에 맞게 만든 개별 대상이다. 참조 변수는 객체를 가리키는 값을 저장한다. 변수 선언만 하는 것과 실제 객체 생성은 별개다.

Member는 id·비밀번호·이름·나이·성별·취미를 묶었다. 필드를 직접 열어 두면 호출자가 나이를 -5로 바꾸는 것도 가능하다. **캡슐화**는 내부 상태를 감추고 정해진 메서드를 통해 접근하게 해 이런 규칙을 관리하는 방식이다.

Children은 필드를 private으로 감추고 getter로 읽고 setter로 바꾼다. setAge는 음수 입력이면 안내 후 0을 넣어 규칙을 지킨다. `this.age`는 객체의 필드이고 age는 메서드가 전달받은 값이다. getter·setter를 만들었다고 검증이 자동으로 생기는 것은 아니다. MemberDTO의 setter는 전달값을 그대로 저장한다.

접근 제한자는 public이면 모든 곳, 생략하면 같은 패키지, private이면 해당 클래스 내부 접근을 허용한다. protected는 같은 패키지와 다른 패키지의 상속 관계에서 정해진 규칙으로 접근한다. 최상위 클래스에는 public 또는 생략만 사용할 수 있다.

DTO는 여러 데이터를 묶어 전달하는 객체다. 수업의 MemberDTO는 번호·이름·나이·성별·키·활성 여부를 보관하며 boolean getter는 isActivated 형태다. 데이터 전달 역할과 모든 업무 규칙을 처리하는 역할을 같은 것으로 생각하지 않는다.

## ☘️ 추상화와 객체 사이의 역할

추상화는 필요한 특징과 동작을 골라 표현하고, 사용하는 쪽에 복잡한 내부 처리 대신 의미 있는 기능을 제공하는 것이다. 수업은 메뉴를 받는 Application, 운전 행동을 요청하는 CarRacer, 자동차 상태를 관리하는 Car로 나눴다. CarRacer는 자기 자동차를 가지는 has-a 관계다.

Car는 시동 여부와 속도를 private으로 관리한다. 시동이 있어야 가속하고, 가속할 때 속도를 10 늘린다. 브레이크는 주행 중 속도를 0으로 바꾸며 이미 멈췄거나 시동이 없는 경우 안내한다. 달리는 중에는 시동을 끄지 않고 먼저 멈추도록 요구한다. 호출자는 내부 변수를 직접 바꾸는 대신 startUp·go·stop·turnOff를 사용한다.

Application은 메뉴 번호에 따라 CarRacer의 메서드를 호출하고 CarRacer는 Car에 요청을 전달한다. 역할을 나누면 화면 입력 처리와 자동차 상태 규칙을 한 함수에 섞지 않고 읽을 수 있다.

## ☘️ 생성자로 초기 상태 정하기

생성자는 new로 객체를 만들 때 초기 상태를 정하는 부분이다. 이름이 클래스명과 같고 void를 포함한 반환 타입을 쓰지 않는다. 매개변수가 없는 기본 생성자와 필요한 값을 전달받는 생성자를 둘 수 있다.

수업의 User 기본 생성자는 필드에 값을 별도로 넣지 않아 문자열과 날짜 참조가 null이다. id·pwd·name을 받는 생성자는 세 값만 초기화하므로 enrollDate는 여전히 null이다. setter로 나중에 바꾸는 것과 생성 시점에 필요한 값을 넣는 것은 시점이 다르다.

컴파일러가 기본 생성자를 자동으로 추가하는 것은 **생성자를 하나도 선언하지 않았을 때만**이다. 매개변수 생성자를 만들고 new User()도 사용하려면 인자 없는 생성자를 직접 선언해야 한다. 매개변수 구성이 다르면 여러 생성자를 둘 수 있다.
