## ☘️ Chroma에 문서를 저장하고 다시 열기

**메모리 저장소의 한계**

`InMemoryVectorStore` 같은 메모리 기반 저장소는 프로그램이 끝나면 벡터도 함께 사라진다. 다음에 실행할 때 같은 문서를 다시 임베딩해야 하므로, 문서가 많을수록 시간과 임베딩 API 비용이 반복해서 든다.

Chroma는 문서 본문, metadata(출처·주제 같은 부가 정보), 벡터를 디스크 폴더에 저장할 수 있는 벡터 데이터베이스다. `persist_directory`로 저장 폴더를 지정하면 커널이나 프로그램을 종료해도 자료가 남는다. Chroma 안에서 문서 묶음은 컬렉션(collection) 단위로 구분하므로, 같은 자료를 다시 열려면 **같은 저장 경로와 같은 컬렉션 이름**을 사용해야 한다.

**전체 예제**

아래 코드는 `07_vectorstore/01_VectorStore.ipynb`의 셀들을 실행 순서대로 하나의 파일로 모은 것이다. 이 절과 뒤의 두 절은 모두 이 코드를 기준으로 설명한다. 노트북의 준비 셀은 `load_dotenv`를 import만 하고 호출하지는 않는다. `.env` 파일의 `OPENAI_API_KEY`를 읽으려면 아래처럼 `load_dotenv()`를 호출해야 하므로 이 줄을 추가했다.

```python
# 07_vectorstore/vector_store.py (01_VectorStore.ipynb의 셀을 한 파일로 모은 코드)
from pathlib import Path
from dotenv import load_dotenv
from langchain_core.documents import Document
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma

load_dotenv()  # .env의 OPENAI_API_KEY를 환경 변수로 읽는다

LESSON_DIR = Path.cwd()
DATABASE_DIR = LESSON_DIR / ".chroma-lab" / "center-policy-v1"

QUESTION = "강의를 취소하면 결제한 돈을 돌려받을 수 있나요?"
EMBEDDING_MODEL = "text-embedding-3-small"

# 1. 저장할 문서: 고정 ID, 본문, metadata
DOCUMENTS = [
    Document(id="refund", page_content="수업 시작 24시간 전까지 취소하면 전액 환불됩니다.", metadata={"source": "center_policy.txt", "topic": "policy"}),
    Document(id="hours", page_content="토요일 실습실은 오전 10시부터 오후 5시까지 운영합니다.", metadata={"source": "center_policy.txt", "topic": "policy"}),
    Document(id="rag", page_content="RAG는 외부 문서를 검색해 모델 요청에 넣는 방식입니다.", metadata={"source": "course_guide.txt", "topic": "lesson"}),
]

# 2. 디스크의 컬렉션 열기 (없으면 새로 만든다)
embeddings = OpenAIEmbeddings(model=EMBEDDING_MODEL, timeout=20, max_retries=0)
store = Chroma(
    collection_name="center-policy-v1",
    embedding_function=embeddings,
    persist_directory=str(DATABASE_DIR),
)

# 3. 자료 존재 여부를 최대 1건 조회해 최초 저장/재사용 결정
stored = store.get(limit=1)
print(type(stored).__name__, stored["ids"])

if stored["ids"]:
    print("상태: 저장한 문서와 벡터 재사용")
else:
    ids = [str(document.id) for document in DOCUMENTS]
    # 본문을 벡터로 바꾸고 본문·metadata·벡터를 각 ID와 함께 저장
    store.add_documents(DOCUMENTS, ids=ids)
    print("상태: 문서와 벡터를 처음 저장함")

# 4. 실제로 저장한 내용 조회
saved = store.get(include=["documents", "metadatas"])
print("문서 수:", len(saved["ids"]))
for item in zip(saved["ids"], saved["documents"], saved["metadatas"]):
    print(item)

# 5. 전체 문서에서 검색
print("\n[전체 검색]")
all_retriever = store.as_retriever(search_kwargs={"k": 2})
all_result = all_retriever.invoke(QUESTION)
print(type(all_result).__name__, len(all_result))
for document in all_result:
    print(document.id, document.metadata, document.page_content)

# 6. topic이 policy인 문서 안에서만 검색
print("\n[정책 필터 검색]")
policy_retriever = store.as_retriever(search_kwargs={"k": 2, "filter": {"topic": "policy"}})
policy_results = policy_retriever.invoke(QUESTION)
for document in policy_results:
    print(document.id, document.metadata, document.page_content)
```

예제는 Python 3.12, `langchain-core` 1.8.4, `langchain-openai` 1.8.5, `langchain-chroma` 1.2.0, `chromadb` 1.5.9에서 실행했다. `07_vectorstore` 폴더에서 실행해야 `Path.cwd()`가 그 폴더를 가리키고, 저장소가 `07_vectorstore/.chroma-lab/center-policy-v1`에 만들어진다. 같은 폴더나 상위 폴더에 `OPENAI_API_KEY=발급받은 키` 형식의 `.env` 파일이 있어야 한다.

**문서와 고정 ID**

`Document`는 본문 `page_content`, 부가 정보 `metadata`, 식별자 `id`를 담는 LangChain의 문서 객체다. 여기서는 `refund`, `hours`, `rag`처럼 ID를 직접 정했다. 두 문서의 `source`가 모두 `center_policy.txt`여도 ID가 다르므로 저장소 안에서 별개의 항목으로 구분된다. `topic`은 뒤에서 검색 대상을 고르는 필터에 사용한다.

**Chroma 객체 만들기**

`Chroma(...)`에 전달하는 세 값의 역할은 다음과 같다.

- `collection_name`: 저장소 안의 문서 묶음 이름
- `embedding_function`: 문서와 질문을 벡터로 바꿀 임베딩 객체. 저장할 때와 검색할 때 같은 모델을 써야 벡터를 비교할 수 있다.
- `persist_directory`: 자료를 보관할 디스크 폴더

이 시점에는 연결만 만들 뿐 문서를 임베딩하지 않는다. 임베딩 API 호출은 `add_documents()`와 검색 시점에 일어난다.

**최초 저장과 재사용**

`store.get(limit=1)`은 저장된 항목을 최대 1건 가져온다. 반환값은 딕셔너리이고, `ids`는 ID 문자열의 리스트다. 처음 실행하면 컬렉션이 비어 있어 `[]`가 나오고, `else` 분기에서 `add_documents()`가 세 문서를 임베딩해 저장한다. 두 번째 실행부터는 디스크에 남은 `refund`가 조회되므로 임베딩 없이 저장된 자료를 그대로 쓴다.

같은 코드를 두 번 실행한 출력은 다음과 같다. 첫 실행의 앞부분이다.

```text
dict []
상태: 문서와 벡터를 처음 저장함
```

두 번째 실행의 앞부분이다.

```text
dict ['refund']
상태: 저장한 문서와 벡터 재사용
```

이 재사용 조건은 "항목이 하나라도 있는가"만 확인한다. `DOCUMENTS`에 문서를 추가하거나 본문을 고쳐도 기존 항목이 있으면 저장 단계를 건너뛰므로, 바뀐 내용은 저장소에 반영되지 않는다. 문서를 바꿨다면 컬렉션 이름을 `center-policy-v2`처럼 새로 정하거나 저장 폴더를 지우고 다시 저장해야 한다.

고정 ID를 쓰는 이유도 여기에 있다. `langchain-chroma`의 `add_documents()`는 내부에서 Chroma의 upsert를 사용하므로, 같은 ID로 다시 저장하면 기존 항목을 덮어쓴다. ID를 주지 않으면 실행할 때마다 무작위 UUID가 만들어져 같은 문서가 중복 저장된다. 이 예제처럼 `Document`에 `id`가 이미 있으면 `ids=`를 생략해도 문서의 `id`가 사용되지만, `ids=`로 명시하면 어떤 ID로 저장되는지 코드에서 바로 보인다.

## ☘️ 저장 내용 조회와 유사도 검색의 차이

Chroma에서 자료를 꺼내는 방법은 두 가지다. 저장된 항목을 그대로 읽는 `get()`과, 질문과 의미가 가까운 문서를 찾는 검색이다.

**get()으로 저장 내용 조회하기**

`store.get(include=["documents", "metadatas"])`는 저장된 항목을 조회한다. 반환 딕셔너리의 `ids`, `documents`, `metadatas`는 같은 위치끼리 대응하는 리스트이므로, `zip()`으로 같은 위치의 값을 튜플로 묶어 순회한다. 질문을 벡터로 바꿀 필요가 없으므로 임베딩 API를 호출하지 않는다.

```text
문서 수: 3
('refund', '수업 시작 24시간 전까지 취소하면 전액 환불됩니다.', {'source': 'center_policy.txt', 'topic': 'policy'})
('hours', '토요일 실습실은 오전 10시부터 오후 5시까지 운영합니다.', {'source': 'center_policy.txt', 'topic': 'policy'})
('rag', 'RAG는 외부 문서를 검색해 모델 요청에 넣는 방식입니다.', {'source': 'course_guide.txt', 'topic': 'lesson'})
```

metadata 딕셔너리의 키 순서는 실행할 때마다 `{'topic': ..., 'source': ...}`처럼 바뀌어 출력될 수 있다. 딕셔너리의 내용은 같다.

**retriever로 질문과 가까운 문서 검색하기**

Retriever는 질문을 받아 관련 문서를 돌려주는 LangChain의 공통 검색 인터페이스다. `store.as_retriever(search_kwargs={"k": 2})`는 이 저장소에서 최대 2개 문서를 가져오는 retriever를 만든다. `invoke(QUESTION)`을 호출하면 질문을 임베딩한 뒤(API 호출) 저장된 벡터와 비교해 가까운 순서로 문서를 반환한다.

```text
[전체 검색]
list 2
refund {'source': 'center_policy.txt', 'topic': 'policy'} 수업 시작 24시간 전까지 취소하면 전액 환불됩니다.
rag {'topic': 'lesson', 'source': 'course_guide.txt'} RAG는 외부 문서를 검색해 모델 요청에 넣는 방식입니다.
```

질문에는 "환불"이라는 단어가 없지만 "취소", "돌려받다"와 의미가 가까운 `refund`가 첫 번째로 나왔다.

두 방법의 반환 형태는 다르다.

- `get()`: `ids`, `documents`, `metadatas` 리스트를 담은 **딕셔너리**
- `retriever.invoke()`: 유사도 순서로 정렬된 **`list[Document]`**

검색 결과는 저장된 원문과 metadata일 뿐 모델이 생성한 답변이 아니다. 답변을 만들려면 이 문서들을 근거로 묶어 채팅 모델에 따로 요청해야 한다.

## ☘️ metadata 필터로 검색 대상 좁히기

전체 검색의 두 번째 결과 `rag`는 환불 질문과 관계가 없다. `k=2`는 "가장 가까운 문서 2개"를 의미할 뿐, 관련도가 일정 기준 이상인 문서만 가져오라는 조건이 아니기 때문이다. 저장된 문서가 3개뿐이므로 덜 관련된 문서도 2위 자리를 채운다.

metadata 필터를 쓰면 검색 대상 자체를 좁힐 수 있다. `search_kwargs`에 `"filter": {"topic": "policy"}`를 넣으면 `topic`이 `policy`인 문서 안에서만 유사도를 비교한다.

```python
policy_retriever = store.as_retriever(search_kwargs={"k": 2, "filter": {"topic": "policy"}})
```

```text
[정책 필터 검색]
refund {'source': 'center_policy.txt', 'topic': 'policy'} 수업 시작 24시간 전까지 취소하면 전액 환불됩니다.
hours {'source': 'center_policy.txt', 'topic': 'policy'} 토요일 실습실은 오전 10시부터 오후 5시까지 운영합니다.
```

`rag`는 `topic`이 `lesson`이라 검색 대상에서 빠졌다. 하지만 2위 자리는 운영 시간 문서 `hours`가 채웠다. `filter`는 **검색 대상의 조건**이고, `k`는 **그 대상 안에서 반환할 최대 개수**다. 정책 문서가 `refund`, `hours` 두 개이므로 `k=2`이면 둘 다 반환된다.

따라서 "정책 문서에 속한다"는 것과 "이 질문에 답할 근거다"는 것은 다른 이야기다. 필터는 엉뚱한 종류의 문서를 제외하는 데 쓰고, 검색 결과를 답변 근거로 쓰기 전에는 본문이 실제로 질문에 답하는지 확인해야 한다.

## ☘️ CSV 행을 Document로 바꾸기

실제 서비스의 자료는 TXT 문서보다 표 형태로 주어지는 경우가 많다. CSV(Comma-Separated Values)는 첫 줄에 열 이름, 다음 줄부터 데이터 행을 쉼표로 구분해 적은 표 형식의 파일이다. 와인 리뷰 CSV를 Chroma에 넣으려면 각 행을 `Document`로 바꿔야 한다.

`07_vectorstore/data/wine_reviews_sample.csv`는 `title`(와인 이름)과 `description`(영어 리뷰) 두 열, 200개 데이터 행으로 이루어져 있다. 앞의 세 줄은 다음과 같다.

```text
title,description
Nicosia 2013 Vulkà Bianco  (Etna),"Aromas include tropical fruit, broom, brimstone and dried herb. The palate isn't overly expressive, offering unripened apple, citrus and dried sage alongside brisk acidity."
Quinta dos Avidagos 2011 Avidagos Red (Douro),"This is ripe and fruity, a wine that is smooth while still structured. Firm tannins are filled out with juicy red berry fruits and freshened with acidity. It's  already drinkable, although it will certainly be better from 2016."
```

리뷰 본문 안에 쉼표가 있어도 큰따옴표로 감싼 값은 하나의 열로 읽힌다. 이런 규칙 때문에 문자열을 직접 `split(",")`하지 않고 `csv` 모듈로 읽는다.

**전체 예제**

아래 코드는 `07_vectorstore/02_Wine_Review_RAG.ipynb`에서 CSV 한 행을 확인하는 셀, 변환 함수 셀, 결과 확인 셀을 하나의 파일로 모은 것이다. 이 코드는 모델이나 임베딩을 호출하지 않으므로 API 키 없이 실행된다.

```python
# 07_vectorstore/load_reviews.py (02_Wine_Review_RAG.ipynb의 CSV 변환 셀을 한 파일로 모은 코드)
from pathlib import Path
import csv
from itertools import islice
from langchain_core.documents import Document

CSV_PATH = Path.cwd() / "data" / "wine_reviews_sample.csv"

# 1. CSV의 한 행 확인
with CSV_PATH.open(encoding="utf-8-sig", newline="") as file:
    reader = csv.DictReader(file)
    columns = reader.fieldnames
    sample_row = next(reader)
print(columns)
print(type(sample_row), sample_row["title"], sample_row["description"])


# 2. 리뷰를 Document로 바꾸는 함수
def load_reviews(csv_path, limit=200):
    documents = []
    with csv_path.open(encoding="utf-8-sig", newline="") as file:
        for number, row in enumerate(islice(csv.DictReader(file), limit), start=1):
            title, review = row["title"].strip(), row["description"].strip()
            if title and review:
                documents.append(Document(
                    page_content=review,
                    metadata={"title": title, "review_number": number}
                ))
    return documents


# 3. 변환 결과 확인
documents = load_reviews(CSV_PATH)
print(type(documents), len(documents))
print(documents[0].metadata)
print(documents[0].page_content)
```

`07_vectorstore` 폴더에서 실행한 출력이다.

```text
['title', 'description']
<class 'dict'> Nicosia 2013 Vulkà Bianco  (Etna) Aromas include tropical fruit, broom, brimstone and dried herb. The palate isn't overly expressive, offering unripened apple, citrus and dried sage alongside brisk acidity.
<class 'list'> 200
{'title': 'Nicosia 2013 Vulkà Bianco  (Etna)', 'review_number': 1}
Aromas include tropical fruit, broom, brimstone and dried herb. The palate isn't overly expressive, offering unripened apple, citrus and dried sage alongside brisk acidity.
```

**CSV를 여는 방식**

- `encoding="utf-8-sig"`: 이 파일은 맨 앞에 BOM(Byte Order Mark, 파일이 UTF-8임을 알리는 보이지 않는 문자 `﻿`)이 붙어 있다. `utf-8`로 열면 첫 열 이름이 `'﻿title'`로 읽혀 `row["title"]`에서 `KeyError`가 난다. `utf-8-sig`는 BOM을 제거하고 읽는다. 엑셀에서 UTF-8 CSV로 저장한 파일에 BOM이 붙는 경우가 많다.
- `newline=""`: 줄바꿈 처리를 `csv` 모듈에 맡긴다. 큰따옴표 안에 줄바꿈이 들어 있는 값도 올바르게 읽기 위해 `csv` 모듈 문서에서 권장하는 설정이다.
- `csv.DictReader`: 첫 줄의 열 이름을 키로 사용해 각 데이터 행을 딕셔너리로 읽는다. `fieldnames`는 열 이름 리스트이고, `next(reader)`는 열 이름 줄이 아닌 첫 번째 **데이터 행**을 꺼낸다.
- `with` 블록이 끝나면 파일은 닫히지만, 그 전에 읽어 둔 `columns`와 `sample_row`는 변수에 남아 블록 밖에서 출력할 수 있다.

**load_reviews 함수의 동작**

1. `islice(csv.DictReader(file), limit)`: 데이터 행을 앞에서부터 최대 `limit`개까지만 꺼내는 반복자를 만든다. CSV 전체를 리스트로 읽지 않고도 개수를 제한할 수 있다. `limit=5`로 호출하면 `Document` 5개가 반환된다.
2. `enumerate(..., start=1)`: 각 행에 1부터 시작하는 번호를 함께 붙여 `number`, `row`로 받는다.
3. `strip()`으로 앞뒤 공백을 제거하고, 제목과 본문이 모두 있는 행만 `Document`로 만든다. 빈 값이 있는 행은 건너뛴다.
4. 리뷰 본문 `description`은 `page_content`에, 와인 제목과 행 번호는 `metadata`에 넣는다.

본문과 metadata를 나누는 기준은 **무엇을 임베딩해 검색할 것인가**다. 임베딩은 `page_content`로 만들어지므로, 음식과 어울리는 맛 표현을 찾으려면 맛과 향을 묘사한 리뷰 본문이 `page_content`에 있어야 한다. 와인 제목과 행 번호는 검색 결과가 어떤 와인의 몇 번째 리뷰인지 알려 주는 출처 정보로, 답변을 원문과 대조할 때 사용한다.

자료형은 CSV 행 딕셔너리 → `Document` 객체 → `list[Document]` 순서로 바뀐다. 이 목록은 앞 절의 정책 문서처럼 별도의 저장 경로와 컬렉션에 `add_documents()`로 넣어 검색할 수 있다. 서로 다른 자료를 같은 컬렉션에 섞지 않으면 와인 검색 결과에 정책 문서가 섞여 나오지 않는다.
