## ☘️ API 요청과 컴포넌트의 역할

API는 다른 프로그램이 제공하는 기능이나 데이터를 정해진 방식으로 사용하는 통로다. 브라우저가 주소로 요청을 보내면 서버는 응답을 돌려준다. 네트워크 응답은 즉시 준비되지 않으므로 Promise나 async·await로 도착 이후의 처리를 연결한다. await는 해당 비동기 함수 안에서 결과를 기다리게 하며 브라우저 전체를 멈추는 뜻은 아니다.

GitHub 이모지 과제는 서버에서 이모지 이름과 이미지 URL 목록을 받아 검색 결과를 보여 주는 구조다. App은 API 요청과 공유 state, SearchBox는 입력 전달, ImageBox는 결과 표시를 맡도록 나눈다. 여러 자식이 함께 쓰는 상태는 공통 부모가 갖고 값과 함수를 내려주면 흐름을 추적하기 쉽다.

수업은 마운트 Effect 안에서 axios.get으로 이모지 목록을 요청하고 response.data를 state에 넣는다. 응답은 이름을 키로, 이미지 주소를 값으로 가진 객체다. `emojiList?.[keyword]`는 입력 문자열을 동적 키로 사용하고 목록이 null·undefined라면 undefined로 멈춘다.

**원본 구현이 끝난 범위**

이모지 원본은 목록을 받아 저장하고 입력 변화로 keyword를 바꾸는 부분까지 구현되어 있다. 검색 버튼에는 handleClick이 연결되지 않았고, ImageBox는 props를 받지 않은 채 true 조건과 고정 이미지를 표시한다. isLoading도 선언만 하고 요청 전후에 변경하지 않는다. 따라서 이 코드를 검색 버튼·로딩·검색 결과가 모두 동작하는 완성본으로 읽으면 안 된다. 전달한 props를 자식에서 사용하고 버튼 이벤트와 상태 변경을 연결해야 한다.

## ☘️ 목록에서 상세 요청으로 이어가기

포켓몬 목록 API는 이름과 상세 주소를 반환한다. 카드에 필요한 번호와 이미지를 얻으려면 각 상세 주소도 요청해야 한다. 흐름은 **목록 요청 → JSON 읽기 → 상세 주소별 요청 → 모두 모으기 → state 저장 → 카드 표시**다.

fetch의 응답은 먼저 Response 객체다. `response.json()`은 본문을 읽어 자바스크립트 데이터로 바꾸는 비동기 작업이므로 그 결과도 기다린다. HTTP 404·500 같은 응답은 fetch가 자동으로 reject하는 조건이 아니므로 response.ok를 확인해 실패를 직접 throw해야 한다.

원본은 목록 JSON을 읽고 나서 ok를 검사한다. 본문 해석 중 오류가 먼저 발생할 수 있으므로 상태를 확인하는 단계와 본문을 읽는 단계를 구분한다. 상세 응답에는 ok 검사와 json 반환이 들어 있다.

```js
const urlArr = listData.results.map((el) => {
  return fetch(el.url).then((response) => {
    if (!response.ok) {
      throw new Error('')
    }
    return response.json()
  })
})
const temp = await Promise.all(urlArr)
```

위는 실제 수업의 상세 요청 부분이다. map의 결과는 완성된 데이터 배열이 아니라 Promise 배열이다. Promise.all이 모든 성공 결과를 모으면 temp에서 상세 데이터 배열을 받는다. 결과 순서는 완료된 순서가 아니라 입력 배열 순서를 따른다. 하나라도 실패하면 이 묶음도 실패하므로 catch에서 처리한다. then 체인으로 연결할 때도 json과 Promise.all을 return해야 다음 단계가 기다린다.

## ☘️ 로딩·오류·카드 표시

요청 중에는 loading, 실패하면 error, 성공하면 pokemons를 기준으로 화면을 나눈다. try는 요청과 데이터 저장, catch는 오류 상태 저장, finally는 성공·실패 모두에서 로딩 종료를 맡을 수 있다. 데이터가 준비되기 전에 배열이나 중첩 속성이 있다고 가정하지 않도록 화면 분기 순서도 중요하다.

원본은 상세 배열 temp를 콘솔에 출력하지만 setPokemons로 저장하지 않았다. catch도 콘솔 출력만 하고 setError를 호출하지 않으며, setLoading(false)도 없어 계속 로딩 화면에 남는다. 카드 목록 렌더링도 비어 있다. 필요한 단계가 주석의 TODO로 남아 있다는 점을 구분한다.

Card는 pokemon을 props로 받아야 하는데 원본 함수에는 매개변수가 없다. 내부에서 pokemon을 읽으면 선언되지 않은 값 문제가 생긴다. 준비된 목록을 map할 때 각 pokemon을 전달하고 고유한 id를 key로 쓰는 것이 과제 요구다.

이미지 선택은 dream_world 이미지가 있으면 사용하고 없으면 기본 front_default를 고른다. 중간 객체가 없을 수 있는 부분의 `?.`와 값이 없을 때 대체하는 `||`는 서로 역할이 다르다. 이 과제에서 요청을 시작하는 것, 응답을 모으는 것, state에 저장하는 것, 화면에 표시하는 것은 각각 필요한 별도 단계다.
