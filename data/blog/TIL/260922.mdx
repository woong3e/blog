## ☘️ 이모지 검색

![이모지 검색 실습](/static/images/TIL/260922_1.png)

- SearchBox: 입력 state 관리, 검색 시 부모 콜백에 값 전달
- App: 전체 이모지·검색어·요청 상태 관리. 공통 부모가 공유 상태 소유
- ImageBox: 전달받은 로딩·URL에 따라 표시. API 요청은 담당하지 않음

```jsx
// 마운트 Effect 안에서 https://api.github.com/emojis 요청
const response = await axios.get(emojiURL)
setEmojiList(response.data)
// App에서 검색 결과 계산
const imgURL = emojiList?.[keyword]
```

응답은 이모지 이름이 키인 객체다. 동적 키는 대괄호로 읽고, `?.`는 객체가 null·undefined면 오류 대신 undefined를 반환한다. 부모는 데이터·함수를 props로 내려주고 자식은 입력·표시 역할에 집중한다.

원본은 isLoading 상태를 선언했지만 요청 전후 setter를 호출하지 않아 실제 로딩 전환은 구현되지 않았다. 요청과 상태 연결이 필요하다.

## ☘️ 포켓몬 목록과 상세

![포켓몬 API 실습](/static/images/TIL/260922_2.png)

**목록 요청 → 상세 URL → Promise 배열 → Promise.all → 데이터 배열 → state → Card**

```js
const response = await fetch('https://pokeapi.co/api/v2/pokemon')
if (!response.ok) throw new Error('목록 요청 실패')
const listData = await response.json()
const details = await Promise.all(
  listData.results.map(async (pokemon) => {
    const detailResponse = await fetch(pokemon.url)
    if (!detailResponse.ok) throw new Error('상세 요청 실패')
    return detailResponse.json()
  })
)
setPokemons(details)
```

목록에는 이름·상세 URL만 있어 이미지·번호는 상세 API로 가져온다. map에서 fetch를 반환하면 데이터가 아닌 Promise 배열이며, Promise.all로 모아야 실제 결과 배열이 된다. **결과 순서는 입력 순서**, 하나라도 reject면 전체도 reject다. then 체인으로 작성할 때도 json()·Promise.all()을 return해야 이어진다.

## ☘️ 응답과 화면 상태

- fetch는 HTTP 404·500만으로 자동 reject하지 않으므로 목록·상세 모두 response.ok 검사
- `try`: 요청·저장 / `catch`: setError / `finally`: 성공·실패 모두 setLoading(false)
- 화면은 loading → error.message → 목록 순서로 분기
- `pokemons.map(pokemon => <Card key={pokemon.id} pokemon={pokemon} />)`으로 안정적인 key와 데이터 전달
- Card 이미지는 `sprites.other?.dream_world?.front_default || sprites.front_default`로 대체 이미지 선택

원본은 목록 JSON 변환 후 ok를 검사했다. 위 예시는 성공 여부부터 확인하도록 순서를 정리했다.
