여러 컴포넌트가 같은 값을 필요로 할 때 공통 부모의 props 전달이 길어질 수 있다. Zustand는 컴포넌트 밖의 store에 상태와 변경 함수를 두어 필요한 곳에서 읽게 한다. 서버 데이터는 요청·캐시·재조회가 필요하므로 화면의 단순 공유 상태와 관리 기준이 다르다.

## ☘️ store와 선택해서 읽기

create는 상태와 액션을 가진 훅을 만든다. set은 새 상태를 반영하고 get은 현재 store 값을 읽는다. 이전 값에 의존하는 증가는 set의 함수 인수에서 계산한다. 컴포넌트는 selector로 필요한 count나 함수를 읽어 자신이 사용하는 부분을 드러낸다.

배열도 직접 수정하기보다 새 배열로 바꾼다. 장바구니 추가는 기존 목록 뒤에 항목을 붙이고 삭제는 대상 id를 제외한 항목을 남긴다. 삭제할 항목과 같은 id를 남기면 목적이 반대가 되므로 filter 조건의 의미를 확인한다.

역할이 다른 값은 관심사별 store로 나눌 수 있다. count·장바구니·테마·사용자 조회는 서로 다른 갱신 규칙을 가진다. persist는 선택한 상태를 브라우저 저장소에 남겨 새로고침 후 복원한다. 브라우저 저장소에 남는 것과 서버에 영구 저장되는 것은 다르며 민감한 값을 무작정 넣지 않는다.

## ☘️ 비동기 액션의 상태 전환

사용자 조회는 idle에서 loading으로, 성공하면 데이터와 success로, 실패하면 오류와 error로 바꾼다. 화면은 데이터가 비었을 때와 아직 요청 중일 때를 구분한다. 요청 함수는 HTTP 상태를 검사하고 예외를 처리해 완료 후에도 로딩 표시가 남지 않게 한다.

## ☘️ TanStack Query와 서버 상태

서버에 있는 게시글은 다른 요청으로 바뀔 수 있다. TanStack Query는 queryKey로 조회 결과를 구분하고 QueryClient가 캐시를 관리한다. Provider는 이 클라이언트를 컴포넌트에 제공한다. 렌더링마다 새 QueryClient를 만들지 않고 같은 인스턴스를 유지한다.

useQuery는 목록 조회와 로딩·오류를 다루고 useMutation은 등록·수정·삭제를 요청한다. 변경 성공 뒤 invalidateQueries로 관련 목록을 오래된 것으로 표시하면 다시 조회해 서버 결과와 화면을 맞출 수 있다. mutation을 실행했다고 모든 목록이 자동으로 올바르게 바뀌는 것은 아니다.

API 함수는 주소·메서드·본문을 담당하고 컴포넌트는 입력과 화면을 담당한다. 응답이 204면 본문이 없으므로 무조건 json을 호출하지 않는다. 아래 구성은 3000의 화면과 9999의 JSON 서버를 따로 실행하고 db.json에 게시글을 보관한다.

## ☘️ 공유 상태와 서버 데이터의 전체 연결

학습 코드의 Zustand 스토어와 TanStack Query 사용 흐름을 작은 게시글 프로젝트로 정리한 설명용 예제다. 아래 파일을 같은 프로젝트에 저장한다. 프론트엔드와 JSON 서버는 서로 다른 프로세스로 실행한다.

**app/page.js**

```jsx
'use client'
import { useEffect, useState } from 'react'
import { useQuery } from '@tanstack/react-query'
import { useStore, useCartStore, usePersistStore, useUserStore } from './store'
import { postAPI } from './post-api'
async function fetchUsers() {
  const response = await fetch('https://jsonplaceholder.typicode.com/users')
  if (!response.ok) throw new Error('목록 요청 실패')
  return response.json()
}
export default function Home() {
  const count = useStore((state) => state.count),
    increase = useStore((state) => state.increase)
  const { items, addItem, removeItem } = useCartStore(),
    { theme, toggleTheme } = usePersistStore()
  const { user, loading, error, fetchUser } = useUserStore()
  const [mounted, setMounted] = useState(false),
    [posts, setPosts] = useState([]),
    [postError, setPostError] = useState('')
  const query = useQuery({ queryKey: ['users'], queryFn: fetchUsers })
  useEffect(() => {
    setMounted(true)
    fetchUser()
  }, [fetchUser])
  async function reload() {
    try {
      setPosts(await postAPI.getPosts())
      setPostError('')
    } catch (error) {
      setPostError(error.message)
    }
  }
  async function change(action) {
    try {
      await action()
      await reload()
    } catch (error) {
      setPostError(error.message)
    }
  }
  if (!mounted) return <p>저장 상태 준비 중</p>
  return (
    <main style={{ background: theme === 'dark' ? '#ccc' : 'white' }}>
      <button onClick={increase}>count: {count}</button>
      <button onClick={toggleTheme}>테마: {theme}</button>
      <button onClick={() => addItem({ id: Date.now(), name: '새 상품' })}>장바구니 추가</button>
      {items.map((item) => (
        <button key={item.id} onClick={() => removeItem(item.id)}>
          {item.name} 삭제
        </button>
      ))}
      <p>{loading ? '사용자 로딩 중' : error || user?.name}</p>
      <button onClick={() => query.refetch()}>사용자 목록 다시 요청</button>
      <p>
        {query.isLoading
          ? '목록 로딩 중'
          : query.isError
            ? query.error.message
            : `사용자 ${query.data.length}명`}
      </p>
      {query.isFetching && <p>최신 목록 확인 중</p>}
      <button onClick={reload}>게시글 조회</button>
      <button
        onClick={() => change(() => postAPI.createPost({ title: '새 글', author: '예제 사용자' }))}
      >
        게시글 등록
      </button>
      <p>{postError}</p>
      {posts.map((post) => (
        <article key={post.id}>
          {post.title}
          <button onClick={() => change(() => postAPI.updatePost(post.id, '수정된 제목'))}>
            수정
          </button>
          <button onClick={() => change(() => postAPI.deletePost(post.id))}>삭제</button>
        </article>
      ))}
    </main>
  )
}
```

**app/post-api.js**

```jsx
const baseURL = 'http://localhost:9999/posts'
async function request(path = '', options) {
  const response = await fetch(baseURL + path, options)
  if (!response.ok) throw new Error('게시글 요청 실패')
  return options?.method === 'DELETE' ? true : response.json()
}
export const postAPI = {
  getPosts: () => request(),
  createPost: (post) =>
    request('', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(post),
    }),
  updatePost: (id, title) =>
    request('/' + id, {
      method: 'PATCH',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ title }),
    }),
  deletePost: (id) => request('/' + id, { method: 'DELETE' }),
}
```

**app/providers.js**

'use client'
import { useState } from 'react'
import { QueryClient, QueryClientProvider } from '@tanstack/react-query'
export default function Providers({ children }) {
  const [client] = useState(() => new QueryClient())
  return <QueryClientProvider client={client}>{children}</QueryClientProvider>
}

**app/store.js**

```jsx
import { create } from 'zustand'
import { persist } from 'zustand/middleware'
export const useStore = create((set) => ({
  count: 0,
  text: '',
  increase: () => set((state) => ({ count: state.count + 1 })),
  setText: (text) => set({ text }),
}))
export const useCartStore = create((set) => ({
  items: [],
  addItem: (item) => set((state) => ({ items: [...state.items, item] })),
  removeItem: (id) => set((state) => ({ items: state.items.filter((item) => item.id !== id) })),
  clearCart: () => set({ items: [] }),
}))
export const usePersistStore = create(
  persist(
    (set) => ({
      theme: 'light',
      toggleTheme: () => set((state) => ({ theme: state.theme === 'light' ? 'dark' : 'light' })),
    }),
    { name: 'theme-storage' }
  )
)
export const useUserStore = create((set) => ({
  user: null,
  loading: false,
  error: '',
  fetchUser: async () => {
    set({ loading: true, error: '' })
    try {
      const response = await fetch('https://jsonplaceholder.typicode.com/users/1')
      if (!response.ok) throw new Error('사용자 요청 실패')
      set({ user: await response.json() })
    } catch (error) {
      set({ error: error.message })
    } finally {
      set({ loading: false })
    }
  },
}))
```

Zustand의 set은 새 상태를 저장하며 컴포넌트는 selector로 필요한 값만 읽는다. 장바구니 제거는 조건에 맞지 않는 항목을 남겨 새 배열로 교체한다. persist는 브라우저 저장소에 테마를 남기지만 서버의 영구 저장을 대신하지 않는다. 사용자 요청 스토어는 로딩·성공·실패 상태를 관리한다. TanStack Query의 QueryClientProvider가 캐시를 공유하고 useQuery는 조회를, useMutation은 등록·수정·삭제를 다룬다. 변경 성공 뒤 invalidateQueries를 호출하면 해당 게시글 목록을 다시 확인해 화면을 갱신한다. 204 삭제 응답은 본문이 없으므로 JSON으로 읽지 않는다. 이 예제의 JSON 서버 데이터는 db.json에 보관된다.

**실행 방법**

프로젝트 루트에서 `npm install` 후 터미널 하나에서 `npm run server`, 다른 터미널에서 `npm run dev`를 실행한다. 화면은 http://localhost:3000, 게시글 서버는 http://localhost:9999이다. 외부 사용자 조회는 인터넷이 필요하다.
