## ☘️ 공유 상태와 store

Props Drilling은 사용하지 않는 중간 컴포넌트도 props를 계속 전달하는 상황이다. page → Child → GrandChild의 count·setter 전달을 외부 store 구독으로 바꿨다.

```js
export const useStore = create((set) => ({
  count: 0,
  text: '',
  increase: () => set((state) => ({ count: state.count + 1 })),
  decrease: () => set((state) => ({ count: state.count - 1 })),
  setText: (value) => set({ text: value }),
}))
```

- create로 상태·액션을 가진 Hook 생성. 필요한 컴포넌트가 같은 store 사용
- set은 최상위 얕은 병합. text만 바꿔도 count·액션 유지
- 이전 값으로 계산할 때 함수형 set, 새 값 지정은 객체 전달
- 전체 store 대신 `useStore(state => state.count)`처럼 필요한 값만 구독
- Client Component 지시문은 `'use client'`. 원본 `'usec client'`는 오타

## ☘️ 배열과 영속화

사용자(useUserStore)·장바구니(useCartStore)·모달/사이드바(useUIStore)로 관심사를 나눴다.

```js
// store 액션의 핵심
addItem: item => set(state => ({ items: [...state.items, item] })),
removeItem: id => set(state => ({ items: state.items.filter(item => item.id !== id) })),
clearCart: () => set({ items: [] }),
```

원본 filter는 중괄호 안에 return이 없어 전부 삭제됐다. 식을 바로 반환하거나 return을 명시한다.

메모리 store는 새로고침 시 초기화된다. `persist(상태 생성 함수, { name: 'theme-storage' })`로 테마를 기본 localStorage에 저장하고 light·dark를 토글했다.

서버는 localStorage를 알 수 없어 첫 화면이 다를 수 있다. 실습은 isMounted=false로 같은 로딩 화면 → 마운트 Effect에서 true → 테마 표시 순서다. **마운트와 저장 상태 복원 완료는 별개**이며 비동기 저장소는 복원 상태도 확인해야 한다.

## ☘️ 비동기와 서버 데이터

Zustand fetchUser는 loading 켜기 → 요청 → user 저장 → finally에서 loading 끄기다. Effect에서 액션을 호출하고 상태로 화면을 나눴다. 원본은 ok 검사·화면 에러가 빠졌고, 호출부 login/logout은 store에서 주석 처리되어 이름·구현 일치도 확인해야 한다.

TanStack Query는 API 데이터의 요청 상태·캐시를 관리한다. Providers에 QueryClientProvider를 두고 `useState(() => new QueryClient())`로 클라이언트를 유지했다.

```jsx
const { data, isLoading, isFetching, isError, error, refetch } = useQuery({
  queryKey: ['users'],
  queryFn: fetchUsers,
})
```

- queryKey: 캐시 식별 / queryFn: 데이터 반환 또는 오류 throw
- isLoading: 실습의 데이터 없는 최초 로딩 / isFetching: 기존 데이터가 있어도 재요청 중이면 true
- refetch(): 같은 쿼리 재요청. 사용자 목록·상세는 별도 키로 구분

**게시글 CRUD**는 별도의 useState 예제다. json-server의 db.json을 쓰고 postAPI에 통신을 분리했다.

- 목록: `GET /posts` / 등록: `POST /posts`
- 수정: `PATCH /posts/ID` / 삭제: `DELETE /posts/ID`
- 등록·수정 본문: Content-Type application/json + JSON.stringify
- API 함수에서 response.ok 확인·오류 throw, 화면에서 try-catch
- 변경 후 loadPosts()로 재조회. 이 실습은 Query mutation과 연결된 구조가 아님
