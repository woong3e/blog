## ☘️ 목록과 Todo

`map()`으로 데이터를 JSX로 바꾸고 `key={item.id}`로 항목을 식별한다. key는 형제 사이에서 고유하고 같은 항목에 안정적이어야 한다. 고정 목록에서는 index를 쓰기도 했지만, 추가·삭제되는 Todo에는 위치가 바뀌므로 id를 쓴다.

```jsx
// 빈 입력 차단 → 추가 → 다음 id 증가 → 입력 비우기
if (!inputValue.trim()) return
setTodos([...todos, { id: nextId, text: inputValue, isDone: false }])
setNextId(nextId + 1)
setInputValue('')
// 삭제
setTodos(todos.filter((todo) => todo.id !== id))
// 완료 토글
setTodos(todos.map((todo) => (todo.id === id ? { ...todo, isDone: !todo.isDone } : todo)))
```

push·splice로 원본 state를 직접 수정하지 않는다. **새 배열과 변경할 객체의 복사 둘 다** 필요하다. id는 삭제해도 다시 당기지 않고 계속 증가시킨다.

## ☘️ 역할 분리와 완료

TodoList는 입력값·배열·다음 id·변경 로직, TodoItem은 항목 화면과 사용자 동작 전달을 담당한다.

```jsx
function TodoItem({ todo, onRemove, onToggle }) {
  return (
    <li>
      <input type="checkbox" checked={todo.isDone} onChange={() => onToggle(todo.id)} />
      <span className={todo.isDone ? 'completed' : ''}>{todo.text}</span>
      <button onClick={() => onRemove(todo.id)}>삭제</button>
    </li>
  )
}
```

부모가 데이터·콜백을 props로 전달하고, 자식은 id로 동작을 알린다. 체크 상태는 value가 아닌 boolean checked다. 완료 클래스에 취소선을 적용했다.

원본의 “남은 할 일”은 todos.length로 전체를 셌다. 미완료 수는 `todos.filter(todo => !todo.isDone).length`로 계산해야 한다.

## ☘️ Effect와 cleanup

Effect는 DOM 반영 후 외부 작업을 시작한다.

- 의존성 생략: 매 커밋 후 / `[]`: 마운트 / `[count]`: 마운트와 count 변경 시
- otherCount만 바꾸면 `[count]` Effect는 재실행하지 않음
- 사용한 반응형 값을 의존성에 포함. 이전 값과 Object.is로 비교

```jsx
useEffect(() => {
  const id = setInterval(() => console.log('1초 경과'), 1000)
  return () => clearInterval(id)
}, [])
```

Timer를 조건부 표시·숨김하며 정리를 확인했다. cleanup은 **제거 시**, 그리고 **의존성 변경으로 재실행하기 전**에 이전 작업을 정리한다. 개발 Strict Mode는 초기 setup·cleanup을 추가 실행할 수 있어 `[]`를 무조건 한 번이라고 외우지 않는다.
