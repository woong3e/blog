오늘은 배열을 화면에 반복해서 표시하는 방법을 배우고 Todo List에 추가·삭제·완료 체크 기능을 붙였다. 이후 `useEffect`의 실행 시점을 비교하고 컴포넌트가 사라질 때 타이머를 정리하는 실습을 했다.

## 목록 렌더링과 배열 state

`map()`으로 배열의 각 값을 JSX 요소로 바꾸면 목록을 렌더링할 수 있다. 객체 배열에서는 데이터가 가진 `id`를 `key`로 사용했다.

```jsx
const users = [
  { id: 1, name: '박지성' },
  { id: 2, name: '손흥민' },
  { id: 3, name: '차범근' },
]

return (
  <ul>
    {users.map((user) => (
      <li key={user.id}>{user.name}</li>
    ))}
  </ul>
)
```

**key는 목록 항목을 식별하는 값이다**

React는 `key`를 보고 이전 목록의 어느 항목이 추가·삭제·이동되었는지 구분한다. 형제 항목 사이에서 고유하고, 같은 항목에는 계속 같은 값이어야 한다. 과일처럼 고정된 배열 예제에서는 index를 사용했지만, 추가와 삭제가 있는 Todo에서는 위치가 바뀔 수 있으므로 데이터의 `id`를 사용했다.

**추가와 삭제는 새 배열을 만든다**

이름 목록 실습에서는 입력값이 공백뿐이면 추가를 막고, 새 항목을 기존 배열 뒤에 붙였다. 삭제할 때는 `filter()`로 해당 id를 제외한 배열을 만들었다.

```jsx
const handleAdd = () => {
  if (inputValue.trim() === '') return

  const newName = { id: nextId, text: inputValue }
  setNames([...names, newName])
  setNextId(nextId + 1)
  setInputValue('')
}

const handleRemove = (idToRemove) => {
  setNames(names.filter((name) => name.id !== idToRemove))
}
```

state 배열을 직접 `push()`하거나 `splice()`로 수정하기보다, spread나 `filter()`로 새 배열을 만들어 setter에 전달한다. 추가할 때 사용한 id는 항목을 삭제해도 다시 당겨서 계산하지 않고 `nextId`로 계속 증가시켰다.

## Todo List의 역할 분리와 완료 체크

부모 `TodoList`는 입력값, Todo 배열, 다음 id와 변경 로직을 관리했다. 자식 `TodoItem`은 할 일 한 개의 화면을 그리고 사용자 동작을 부모가 전달한 함수에 알렸다.

```jsx
function TodoItem({ todo, onRemove, onToggle }) {
  const { id, text, isDone } = todo

  return (
    <li>
      <input type="checkbox" checked={isDone} onChange={() => onToggle(id)} />
      <span className={isDone ? 'completed' : ''}>{text}</span>
      <button onClick={() => onRemove(id)}>삭제</button>
    </li>
  )
}
```

checkbox의 상태는 문자열 `value`가 아니라 boolean인 `checked`와 연결한다. 완료 여부가 바뀌면 클래스도 함께 바뀌어서 글자에 취소선을 표시했다.

**수정할 항목만 새 객체로 바꾸기**

완료 토글은 `map()`으로 전체 배열을 순회하되 클릭한 id와 일치하는 항목만 복사하고 `isDone`을 뒤집었다.

```jsx
const handleToggle = (id) => {
  const updatedTodos = todos.map((todo) =>
    todo.id === id ? { ...todo, isDone: !todo.isDone } : todo
  )
  setTodos(updatedTodos)
}
```

새 배열을 만드는 것과 배열 안의 객체를 직접 변경하지 않는 것은 별개다. 변경할 항목도 `...todo`로 복사해야 원래 state의 객체를 수정하지 않는다.

부모는 목록을 렌더링하면서 `todo`, `onRemove`, `onToggle`을 props로 전달했다. 자식은 부모의 state를 직접 바꾸는 대신 해당 함수에 id를 전달했다.

**실습 코드에서 다시 확인한 부분**

원본 화면의 문구는 “남은 할 일”인데 계산은 `todos.length`라서 완료한 항목도 포함한다. 전체 개수를 보여주는 코드와 미완료 개수를 보여주는 코드는 구분해야 한다. 미완료 개수가 필요하다면 아래처럼 계산할 수 있다.

```jsx
// 원본의 개수 표시를 개선하는 예시
const remainingCount = todos.filter((todo) => !todo.isDone).length
```

## useEffect의 실행 조건과 cleanup

`useEffect`는 렌더링 결과가 DOM에 반영된 후 외부 작업을 시작하는 데 사용한다. 실습에서는 콘솔 로그와 타이머를 이용해 컴포넌트 함수 실행과 Effect 실행을 비교했다.

| 의존성 배열 | 기본 실행 조건                                              |
| ----------- | ----------------------------------------------------------- |
| 생략        | 컴포넌트의 매 커밋 후 실행                                  |
| `[]`        | 마운트 시 실행, 일반적인 state 업데이트로는 재실행하지 않음 |
| `[count]`   | 마운트 시 실행하고 이후 `count`가 바뀌면 재실행             |

`count`와 `otherCount`를 각각 증가시키는 예제에서 `[count]`를 가진 Effect는 `otherCount`만 바뀔 때 다시 실행되지 않았다. 의존성에는 Effect 안에서 사용하는 반응형 값을 빠짐없이 넣어야 하며, React는 이전 값과 다음 값을 `Object.is`로 비교한다.

**타이머를 만들었다면 정리도 연결한다**

타이머 보이기·숨기기 버튼으로 `Timer` 컴포넌트를 조건부 렌더링했다. Effect에서 만든 interval은 반환하는 cleanup 함수에서 제거했다.

```jsx
function Timer() {
  useEffect(() => {
    const timerId = setInterval(() => {
      console.log('1초 경과')
    }, 1000)

    return () => clearInterval(timerId)
  }, [])

  return <p>타이머가 동작 중입니다.</p>
}
```

cleanup은 컴포넌트가 제거될 때 실행되고, 의존성이 바뀌어서 Effect를 다시 시작할 때도 이전 작업을 먼저 정리한다. 개발 환경에서 Strict Mode를 사용하면 초기 setup·cleanup 과정이 한 번 더 실행될 수 있으므로 `[]`를 “어떤 상황에서도 정확히 한 번 실행”이라고 외우지는 않는다.

- 목록은 `map()`, 삭제는 `filter()`, 특정 항목 수정은 `map()`과 객체 복사를 조합한다.
- 변경 가능한 목록의 `key`에는 안정적인 id를 사용한다.
- 자식은 전달받은 데이터로 화면을 그리고 콜백으로 부모에게 동작을 알린다.
- Effect의 의존성은 실행 조건과 사용한 값을 함께 설명해야 한다.
- 타이머처럼 시작한 외부 작업은 cleanup에서 해제한다.
